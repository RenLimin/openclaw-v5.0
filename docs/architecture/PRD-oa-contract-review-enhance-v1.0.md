## 1. 背景与问题

OA「销售合同审核流程」（workflowid **757**）当前已具备：读单据 / 读审批链 / 22 条受控规则审查 / 分项↔合同正文比对。
2026-11-18 处理在审单据 886377 时发现**两项既有审查未覆盖、但对审批决策关键的核查**：

| # | 缺口 | 实测证据 |
|---|---|---|
| G1 | 不查**客户履约义务状态**：老客户新购时，无法核对同产品上一轮交付/验收进度 | 886377 标注「老客户新购」；**ONES 实时**显示同产品上一轮（`SSXM-2025-1111-3440`）已交付 + 客户确认版验收单 → 续购正常；但关联提前实施项目 `SSXM-2025-1015-3068` 私有化义务仍「实施未开始」（提示） |
| G2 | 不核**概算一致性**：合同金额与已批概算无对照，超概算无提示 | 886377 分项合计 64,000.00；概算 9955「AndroidSDK加固软件V7.0」预签约价 20,000 < 本单 24,000，**超概算 4,000**（口径：**允许超，仅提醒**） |

## 2. 需求清单

### R1 履约义务核查（最终用户/客户维度）

| 项 | 内容 |
|---|---|
| 输入 | 最终用户名称、客户名称、本单产品服务编码列表（均可从 757 单据字段取得） |
| 处理 | ① 用 **ONES GraphQL 实时**按项目（项目编号由 OA 单据 / BDMS 线索定位）查询「项目履约义务」任务及状态；② 标出本单产品编码的命中记录；③ 汇总每条履约义务的**实时状态** |
| 输出 | 履约义务清单表（实时状态）+ 判定（正常 / 提示 / 异常） |
| 判定口径 | 以 ONES 实时状态为准：`交付邮件已归档`/`客户确认版验收单`/`已完成`/`验收文件已归档` → 正常；`实施未开始`/`义务已拆分` 且项目整体未完成 → 提示；`应交未交`/`交付异常`/`应验未验`/`验收异常`/`应结未结` → 异常 |
| 只读 | ✅ 仅读 ONES/BDMS，不写任何系统 |

### R2 概算核对（概算名称 → 明细/单价一致性）

| 项 | 内容 |
|---|---|
| 输入 | 757 单据字段「销售合同概算名称」（浏览框 `field26675`，值 = 概算卡片 billid） |
| 处理 | ① 用 billid 打开概算卡片（新 tab），读「成本概算明细」各产品分项的**预计签约价格**；② 与本单分项按**产品服务编码**逐项匹配；③ 输出差异 |
| 输出 | 逐项比对表（概算价 / 本单价 / 差异）+ 结论（一致 / 超概算 / 缺项） |
| 口径 | **允许销售额超概算，超出仅提醒**（Rex 2026-11-18 拍板）；明细及单价应可对照，不一致时提示 |
| 边界 | 概算卡片可读（实测 9955 ✅）；「概算流程」字段（`requestid=885969`）**当前账号无权限** → 显式 skip 留证，不伪造 |

## 3. 验收标准

> 【已验证 2026-11-18｜OA 单据 886377 + 概算卡片 9955 只读】下列标准均已在本次实测中取得证据。

| # | 标准 | 验证方式 |
|---|---|---|
| A1 | R1 对 886377 跑出：同产品上一轮 `SSXM-2025-1111-3440` 履约义务实时状态（交付邮件已归档 + 客户确认版验收单）→ 结论=续购正常；`SSXM-2025-1015-3068` 私有化义务「实施未开始」→ 提示 | 真实 **ONES 实时**跑通，输出可复现 |
| A2 | R2 对 886377 跑出：AndroidSDK 项 24,000 > 概算 20,000，合计 64,000 > 60,000，结论=超概算**（提醒级，不阻断）** | 真实 OA 卡片只读跑通 |
| A3 | 无匹配记录时输出「无履约义务记录」，不伪造、不静默 | 构造无记录客户验证 |
| A4 | 会话失效 / 无权限时显式 skip 并留证，不中断整单审查 | 复用 OA 会话自愈口径 |
| A5 | 输出为结构化（JSON + Markdown 表），可嵌入现有审查报告 | 与 `contractctl review` 报告格式对齐 |
