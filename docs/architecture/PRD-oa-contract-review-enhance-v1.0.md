## 1. 背景与问题

OA「销售合同审核流程」（workflowid **757**）当前已具备：读单据 / 读审批链 / 22 条受控规则审查 / 分项↔合同正文比对。
2026-11-18 处理在审单据 886377 时发现**两项既有审查未覆盖、但对审批决策关键的核查**：

| # | 缺口 | 实测证据 |
|---|---|---|
| G1 | 不查**客户履约义务状态**：老客户新购时，无法发现「相同产品上一轮仍未验收」就签新单 | 886377 标注「老客户新购」；BDMS 显示同产品（`SP-AAP-7.0-SAPLV-PLUS`/`SP-IAP-4.0-SAPLV`/`SP-SDKP-7.0-SAPLV`）历史履约义务状态 = **5：应验未验**，关联提前实施项目「实施未开始」 |
| G2 | 不核**概算一致性**：合同金额可超出已批概算而无提示 | 886377 分项合计 64,000.00；概算 9955「AndroidSDK加固软件V7.0」预签约价 20,000 < 本单 24,000，**超概算 4,000** |

## 2. 需求清单

### R1 履约义务核查（最终用户/客户维度）

| 项 | 内容 |
|---|---|
| 输入 | 最终用户名称、客户名称、本单产品服务编码列表（均可从 757 单据字段取得） |
| 处理 | ① 按**最终用户名称**（主）+ 客户名称（辅）在 BDMS 交付月报中检索该客户名下全部项目履约义务；② 标出本单产品编码的命中记录；③ 汇总每条履约义务的「履约义务状态」与「履约项统计状态（财报-交付/确收状态）」 |
| 输出 | 履约义务清单表 + 异常判定（是否存在异常 / 同产品是否存在履约义务及其状态） |
| 异常定义 | 命中记录状态 ∈ {2：应交未交, 3：交付异常, 5：应验未验, 6：验收异常, 8：应结未结}，或关联提前实施项目「实施未开始」→ 判异常 |
| 只读 | ✅ 仅读 BDMS 库，不写任何系统 |

### R2 概算核对（概算名称 → 明细/单价一致性）

| 项 | 内容 |
|---|---|
| 输入 | 757 单据字段「销售合同概算名称」（浏览框 `field26675`，值 = 概算卡片 billid） |
| 处理 | ① 用 billid 打开概算卡片（新 tab），读「成本概算明细」各产品分项的**预计签约价格**；② 与本单分项按**产品服务编码**逐项匹配；③ 判定：本单分项金额 ≤ 概算对应分项金额 |
| 输出 | 逐项比对表（概算价 / 本单价 / 差异）+ 结论（一致 / 超概算 / 缺项） |
| 口径 | 「明细及单价应该与本流程一致（或金额低于等于本流程中各明细项）」——即**本单金额不得高于概算**；超出即提示需补概算变更 |
| 边界 | 概算卡片可读（实测 9955 ✅）；「概算流程」字段（`requestid=885969`）**当前账号无权限** → 显式 skip 留证，不伪造 |

> 【已验证 2026-11-18｜OA 单据 886377 + 概算卡片 9955 只读】下列标准均已在本次实测中取得证据。

| # | 标准 | 验证方式 |
|---|---|---|
| A1 | R1 对 886377 跑出：3 个产品编码全部命中历史履约义务，状态均为「5：应验未验」，结论=异常 | 真实 BDMS 只读跑通，输出可复现 |
