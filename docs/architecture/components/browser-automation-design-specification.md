# 浏览器自动化开发设计文档编制规范

## 适用范围

所有涉及浏览器自动化的需求，包括但不限于：
- 企业内部系统数据导出（OA / ONES / 工时门户 等）
- 登录态复用 / SSO 单点登录
- 数据采集 / 爬虫 / 内容提取
- 自动化操作流程

## 文档位置

- 方法论 / 通用模式：`docs/architecture/components/browser-automation-oa-export.md`
- 设计规范 / 编制规则：本文档 `docs/architecture/components/browser-automation-design-specification.md`
- 项目级详细设计：各自项目内 `DESIGN-DETAIL-*.md`

## 一、设计文档必备要素

### 1. 环境信息

| 要素 | 说明 | 示例 |
|---|---|---|
| 目标系统名称 | 要操作的系统 | OA协同办公平台 / ONES管理平台 / 工时门户 |
| 系统入口URL | 登录页或首页地址 | `https://iam.bangcle.com/#/login` |
| 环境类型 | 生产 / 测试 / 预发 | 生产 |
| 浏览器类型及版本 | Chrome / Firefox / Edge | Chrome 最新稳定版 |
| 自动化框架 | Playwright / Selenium / osascript | Playwright + Chrome CDP |
| 操作系统 | macOS / Windows / Linux | macOS 14+ |

### 2. 认证信息

| 要素 | 说明 | 示例 |
|---|---|---|
| 认证方式 | 账号密码 / SSO / Cookie复用 / 扫码登录 | IAM统一身份认证（账号密码） |
| 登录页URL | 登录页面地址 | `https://iam.bangcle.com/#/login` |
| 用户名输入框选择器 | DOM选择器 | `input[type=text]` |
| 密码输入框选择器 | DOM选择器 | `input[type=password]` |
| 登录按钮选择器 | DOM选择器 | `button:has-text("登录")` |
| 登录后跳转验证 | 登录成功后的判断依据 | URL包含 `#/home`，页面标题变为「统一认证 - 首页」 |
| Cookie有效期 | 登录态保持时长 | 12小时 |
| 凭证存储位置 | 凭证存放的安全位置，禁止明文写文档 | 系统密钥链 / 环境变量 / 配置服务 |

**安全红线：** 设计文档中**禁止**出现真实用户名密码，只能说明凭证获取方式，不得泄露。

### 3. 导航路径

| 要素 | 说明 | 示例 |
|---|---|---|
| 应用入口名称 | 在IAM/首页上的显示名称 | OA协同办公平台 |
| 菜单路径（逐级） | 从首页到目标页面的完整菜单点击路径，按顺序 | `门户` → `销售合同管理系统` → `合同基本信息管理` → `合同台账` |
| 是否新开标签页 | 点击后是否打开新标签页 | 是，每次点击子菜单都开新标签页 |
| 目标页面URL特征 | 目标页面URL的关键字段，用于验证是否到达 | `customid=179` |
| 是否存在iframe | 目标内容是否在iframe中 | 是，主内容在 `#mainFrame` iframe 内 |
| iframe选择器 | iframe的DOM定位方式 | `iframe#mainFrame` |
| 页面加载等待时间 | 目标页面完全加载需要的时间 | 60秒 |

### 4. 操作元素定义

| 要素 | 说明 | 示例 |
|---|---|---|
| 操作按钮名称 | 按钮显示文本 | 导 出 |
| 按钮位置 | 按钮在页面上的位置 | 搜索按钮右侧，工具栏第二个按钮 |
| 按钮选择器（主选） | 主要定位方式 | `iframe#mainFrame button:nth-child(2)` |
| 按钮选择器（备选） | 降级匹配方式 | `text=导 出` / `//*[contains(text(), "导出")]` |
| 所在DOM层级 | 在iframe内还是父页面 | iframe内 |
| 点击后行为 | 点击后的预期效果 | 弹出进度模态框 |

### 5. 进度与等待策略

| 要素 | 说明 | 示例 |
|---|---|---|
| 进度弹窗位置 | 弹窗所在DOM层级 | 父页面 |
| 进度弹窗选择器 | 弹窗定位方式 | `.ant-modal / [role=dialog]` |
| 进度文本格式 | 进度显示的文本格式 | `当前进度 ：N/113380%` |
| 进度提取正则 | 从文本中提取数值的正则表达式 | `(\d+)/(\d+)` |
| 总数据量（预估） | 预计总记录数 | ~11.3万条 |
| 轮询间隔 | 检查进度的频率 | 10秒 |
| 最大等待时间 | 超时时间，避免无限等待 | 10分钟 |

### 6. 结果处理

| 要素 | 说明 | 示例 |
|---|---|---|
| 文件下载方式 | 下载链接点击 / 自动下载 / 另存为 | 点击"下载"链接，Chrome自动下载 |
| 下载链接位置 | 下载链接所在DOM层级 | 父页面进度弹窗内 |
| 下载链接选择器 | 下载链接定位方式 | `.ant-modal a:has-text("下载")` |
| 默认下载目录 | Chrome默认下载位置 | `~/Downloads/` |
| 文件格式 | 下载文件类型 | .xlsx（Excel） |
| 文件名格式 | 文件名命名规则 | `梆梆_销售合同信息查询台账-销售查询-[姓名]-[日期].xlsx` |
| 归档目录 | 最终文件存放位置 | `~/.openclaw/data/oa_exports/` |
| 归档命名规则 | 归档后的文件名规则 | `oa_contract_ledger_[YYYYMMDD_HHMMSS].xlsx` |
| 是否保留原始文件 | 下载目录的文件是否保留 | 是，归档使用复制不移动 |

### 7. 异常处理

| 异常场景 | 处理方式 |
|---|---|
| 登录失败 | 重试3次，仍失败则报错退出，输出错误信息 |
| 菜单找不到 | 打印当前所有可见菜单，方便排查 |
| 导出按钮找不到 | 打印所有按钮文本，输出到日志 |
| 导出超时 | 超过最大等待时间后报错退出 |
| 网络中断 | 检查网络，尝试重连 |
| Chrome崩溃 | 重新启动Chrome实例，从头开始 |

## 二、代码实现规范

### 1. 代码结构

```
[项目]/src/[模块]/
├── browser_automation/
│   ├── __init__.py
│   ├── auth.py            # 登录认证
│   ├── navigation.py      # 菜单导航
│   ├── export.py          # 导出操作
│   ├── download.py        # 下载与归档
│   └── config.py          # 配置（选择器、路径、等待时间）
```

### 2. 配置与代码分离

所有选择器、URL、等待时间、路径等**必须**放在配置文件中，不允许硬编码在业务逻辑里。

```python
# config.py 示例
OA_CONFIG = {
    "iam_url": "https://iam.bangcle.com/#/login",
    "app_entry_name": "OA协同办公平台",
    "menu_path": ["门户", "销售合同管理系统", "合同基本信息管理", "合同台账"],
    "iframe_selector": "#mainFrame",
    "export_button_index": 1,
    "export_button_text": "导 出",
    "page_load_wait": 60,
    "max_export_wait": 600,  # seconds
    "poll_interval": 10,
    "download_dir": "~/Downloads/",
    "archive_dir": "~/.openclaw/data/oa_exports/",
}
```

### 3. 日志规范

- 每级操作都要有明确日志输出（开始 / 成功 / 失败）
- 失败时输出详细上下文，便于排查
- 进度轮询定期输出百分比
- 关键节点（登录成功、导航完成、导出开始、导出完成、下载完成）必须有日志

## 三、验收标准

一份合格的浏览器自动化详细设计文档，必须：

1. ✅ 包含以上7个必备要素（环境 / 认证 / 导航 / 操作元素 / 进度等待 / 结果处理 / 异常处理）
2. ✅ 所有选择器都经过实际验证，不是猜测
3. ✅ 等待时间基于实际测量，不是拍脑袋
4. ✅ 凭证信息不泄露，只说明获取方式
5. ✅ 明确iframe层级关系（哪些元素在iframe内，哪些在父页面）
6. ✅ 有降级策略（主选择器 + 备选选择器）
7. ✅ 有异常处理方案
8. ✅ 有结果验证方式（如何确认导出成功）

## 四、开发流程

1. **需求分析**：明确要自动化什么操作，产出什么结果
2. **手动走通**：先手动完整操作一遍，记录每一步的元素、等待时间、异常情况
3. **编写详细设计**：按照本文档规范，填写所有要素
4. **代码实现**：配置与代码分离，按设计文档实现
5. **自测验证**：完整跑通至少3次，验证稳定性
6. **文档更新**：根据实际情况修正设计文档

**禁止：** 跳过设计文档直接写代码。
**禁止：** 只写代码不写文档。
**禁止：** 硬编码选择器和等待时间。
