## 1. 需求复述

把本次"建设银行年度项目服务汇报材料"沉淀的**一整套数据溯源 + 汇报文档生成**做法，固化为可复用技能：面向**指定客户/项目集与统计周期**，从 ONES、合同台账等现有系统取数，产出**数字可逐行点账、结论可溯源、适配受众**的项目汇报材料（Markdown，可再导出 docx/PPT）。

一句话：**输入「客户 + 周期 + 受众」，输出一份不掺水、可审计、逻辑闭环的项目汇报材料。**

## 2. 背景与问题（本次建行实战暴露的真实痛点）

1. **结果集截断漏数**：单次全局 `name_match` 查询触顶（3534 条）被服务端按时间截断尾部，漏掉 10-08~11-05 的任务。
2. **字段找错实体**：合同编号是**项目级**自定义字段（`CAaTom7U`/别名 `7KF6tXvk`），挂在 `Project` 而非 `Task`，在 Task 层找必然失败。
3. **口径混淆**：把"项目履约义务/建档记录"（设备领用、外包外采、客户合同项目信息，共 64 条）误当工作量；把累计 807 口径误当年度成果。
4. **数量不闭合**：分类数量无法从明细逐行反推；写了"目标支撑"却没闭合到"目标实现"。
5. **受众适配缺失**：对外材料出现内部系统名/编号（ONES、SSXM、harbor）与回款条款；合同名用了自行概括而非台账官方名。

## 3. 目标与非目标

### 3.1 目标

- G1 **完整性可举证**：取数先枚举项目、分页取全、校验触顶；报告附数据完整性与快照时间。
- G2 **口径正确**：严格区分"实际工作"与"履约范围/建档记录"；严格限定统计周期（按 createTime）。
- G3 **账账可反推**：所有汇总数量均可由明细行筛选精确反推；明细每个数量逐条罗列。
- G4 **逻辑闭环**：合同 → 交付事项 → 目标支撑 → **目标实现** 全链闭合；在途事项单列方案。
- G5 **零编造**：每个数字/名词/日期机器溯源；价值论述明确标"基于事实的推断"。
- G6 **受众适配**：对外版自动脱敏内部系统名/编号/商务条款，名称一律取官方正式名。

### 3.2 非目标（明确边界，避免重造/越界）

- N1 **不重做数据底座**：复用 `bangcle-project-summary` 的交付台账与 ONES 取数方法；本技能在其上做"汇报化综合"。
- N2 **不做内部改进诊断**：产品差异/lessons learned/责任方建议归 `bangcle-project-retrospective`。
- N3 **不做履约到期跟踪**：授权/维保到期、履约子任务清单归 `bangcle-obligation-summary`。
- N4 **不做客户需求/环境画像**：归 `bangcle-customer-profile`。
- N5 **不直接产 PPT**：版式渲染/VI 合规的 PPT 归 `bangcle-ppt`；本技能可提供结构化内容。
- N6 **不自动对外发送**：邮件/群发等外发副作用必须人工确认（红线）。

## 4. 功能清单（F = Feature）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 范围界定 | 按"签约 + 服务期内 / 到期未验收未结项"规则圈定合同与项目；输出范围清单与排除项理由 |
| F2 | 完整取数 | 逐项目枚举 + 分页取全 + 触顶校验；合并实时 Project 合同字段；产出快照与完整性证据 |
| F3 | 口径分类 | 区分 5 类实际工作（定制/缺陷/工单/产研/专项）与履约范围/建档记录；剔除后者出工作量 |
| F4 | 周期切分 | 时间戳归一（微秒/毫秒/秒），按 createTime 限定统计周期，支持季度等切分 |
| F5 | 多维汇总 | 按工作类别 / 产品方向 / 时间周期三维汇总，且全部可由明细反推 |
| F6 | 逐条明细 | 输出时间排序明细表：日期/合同/产品方向/工作类别/事项/状态；数量逐条罗列 |
| F7 | 在途与方案 | 在途事项按方向归并，写当前进展 + 处理安排，不编造承诺日期 |
| F8 | 目标实现矩阵 | 维保类目标挂服务事项、采购新建类目标挂部署/授权交付记录，逐条给目标实现状态 |
| F9 | 价值论述 | 基于真实交付的价值提炼，明确"基于事实的推断"，措辞可配置（保留/降级） |
| F10 | 溯源审计 | 机器核对全文数字/名词/日期是否命中原始数据，输出无源项清单（fail-closed） |
| F11 | 受众适配 | 内部版/对外版切换；对外脱敏内部系统名编号与商务条款，名称取官方名 |
| F12 | 交付与导出 | 输出 Markdown + 原始 JSON；按需导出 docx；不自动外发 |

## 5. 典型使用场景

- 年度/季度向**甲方**汇报某客户（如建行）整体项目服务情况（对外版）。
- 向**公司管理层/销售负责人**汇报某大客户在手合同的交付进展与目标达成（内部版）。
- 单个重大项目**验收前**，汇总交付记录并闭合到立项目标实现情况。

## 6. 输入 / 输出

### 6.1 输入

| 项 | 必填 | 说明 |
|---|---|---|
| 客户/项目集 | 是 | 客户名或项目集范围 |
| 统计周期 | 是 | 如 2026 年度 / 2026Q3 / 起止日期 |
| 受众 | 是 | 对外（甲方）/ 内部（管理层）；决定脱敏与措辞 |
| 范围口径 | 否 | 是否纳入"到期未验收"等；默认按 F1 规则 |

### 6.2 输出

- 主交付：项目汇报材料 **Markdown**（章节结构见 DESIGN-OUTLINE §4）。
- 随附：原始数据 JSON、数据完整性与溯源审计结果。
- 可选：docx（PPT 走 `bangcle-ppt`）。

## 7. 验收标准（Acceptance Criteria）

> 数字类验收必须用真实数据，不接受"参数被解析"当作"参数生效"。

- AC1（完整性）：取数日志显示逐项目分页取全、无触顶未处理；项目数与范围清单一致。
- AC2（口径）：实际工作与建档记录无混算；周期外成果（如固件往年建成）不记入当期工作量。
- AC3（可反推）：随机抽取任一汇总数，脚本从明细行筛选复算一致；明细条数 = 完成数 + 在途数。
- AC4（闭环）：每个签约方向都有"目标实现状态"且由真实完成数或交付记录支撑；无悬空格。
- AC5（零编造）：溯源审计 exit=0（PASS）；全文数字/名词/日期命中原始数据；价值论述有标注。
- AC6（脱敏）：对外版 `grep` 内部系统名/编号/商务条款 = 0；合同名与台账官方名一致。
- AC7（幂等）：同输入连跑 3 次，汇总数与结论稳定一致。
- AC8（边界）：不产出 retrospective/obligation/profile/PPT 的越界内容；不触发外发。

## 8. 依赖与复用

- 数据获取：复用 `ones-browser-export`、`bangcle-project-summary/references/ones-query.md`。
- 标准产品基线：`product-kb`。
- 应答契约：L2 `answer-spec-base.md`（P1）+ `prompts/project-answer-spec.md`（P2）+ fail-closed 校验器。
- 合同/项目字段：合同编号项目级自定义字段 `CAaTom7U`；合同官方名/服务期取合同台账（BDMS）。

| 风险 | 等级 | 缓解 |
