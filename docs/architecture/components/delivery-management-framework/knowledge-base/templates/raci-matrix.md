# RACI 矩阵模板

## 模板用途
明确项目各角色在各项工作中的职责分工（谁负责、谁批准、咨询谁、通知谁），避免职责不清、推诿扯皮或多头指挥。

## RACI 定义
| 角色 | 全称 | 含义 |
|------|------|------|
| R | Responsible | 执行者，负责完成任务/产出交付物 |
| A | Accountable | 最终负责人，对结果负最终责任，有一票否决权 |
| C | Consulted | 咨询对象，需要在事前/事中提供意见和专业输入 |
| I | Informed | 被告知对象，需要知道进展和结果，但不参与决策 |

## 填写说明
| 字段 | 必填 | 说明 |
|------|------|------|
| 任务/交付物 | ✅ | 列名，通常是 WBS 的二级或三级条目 |
| 角色列 | ✅ | 参与项目的所有关键角色 |
| RACI 标注 | ✅ | 每个交叉点填 R/A/C/I，一个任务只能有一个 A |

## 注意事项
1. **每个任务有且只有一个 A**：最终负责人只能有一个，避免"两个和尚没水喝"
2. **R 可以有多个**：执行可以多人分工，但 A 必须唯一
3. **A 必须有相应权力**：承担最终责任的人必须有相应的决策权和资源调配权
4. **C 和 I 不要太多**：每个任务咨询/通知的人太多会导致效率低下，只列真正需要的
5. **定期回顾更新**：项目进入不同阶段，职责分工可能变化，RACI 也要相应调整
6. **争议时找 A 裁决**：对任务有分歧时，由该任务的 A 来拍板
7. **不要写成 R/A 矩阵**：避免所有格子都填满，空白表示不参与，这很正常
