# 状态报告模板

## 模板用途
周期性地向上级和干系人同步项目进展，确保信息透明、预期对齐，是项目沟通管理的核心交付物。

## 填写说明
| 字段 | 必填 | 说明 |
|------|------|------|
| 报告周期 | ✅ | 本周/本月/本迭代 |
| 项目基本信息 | ✅ | 项目名称、编号、报告人 |
| 整体状态 | ✅ | 🟢 绿 / 🟡 黄 / 🔴 红 |
| 进度状态 | ✅ | 计划 vs 实际，偏差说明 |
| 质量状态 | ✅ | 缺陷情况、测试进展 |
| 风险与问题 | ✅ | 新增风险、未解决问题 |
| 下周计划 | ✅ | 下一个周期的重点工作 |
| 需要的支持 | ⬜ | 需要上级或其他团队协调的事项 |
| 关键指标 | ⬜ | 量化数据，燃尽图、速率等 |

## 注意事项
1. **结论先行**：开头的整体状态和一句话总结最重要，领导可能只看前 3 行
2. **用数据说话**：少用"基本顺利""还可以"这种模糊描述，用百分比和具体数字
3. **红黄绿灯标准要统一**：提前定义什么情况算红、什么算黄，避免每个项目标准不一样
   - 🟢 绿：进度偏差 < 10%，无高风险，质量达标
   - 🟡 黄：进度偏差 10%-20%，或有中高风险但有应对措施
   - 🔴 红：进度偏差 > 20%，或高风险无应对方案，或质量严重不达标
4. **报问题一定要带方案**：不要只说"有问题"，要说"有什么问题、影响多大、建议怎么办"
5. **需要支持的事项要明确**：说清楚需要谁、做什么、什么时候要，别让领导猜
6. **定期按时发**：状态报告的价值在于规律性，哪怕一切顺利也要发，沉默会让人不安
7. **控制篇幅**：周报 1-2 页足够，详细内容可以放附件或链接
