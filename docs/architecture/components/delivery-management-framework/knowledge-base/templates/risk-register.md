# 风险登记册模板

## 模板用途
系统化地识别、评估、跟踪和管理项目风险，确保风险可见、可控、有人负责，避免风险变成问题后才被动应对。

## 填写说明
| 字段 | 必填 | 说明 |
|------|------|------|
| 风险编号 | ✅ | 唯一标识，便于追踪 |
| 风险描述 | ✅ | 清晰描述风险事件，包含"如果…那么…"的因果逻辑 |
| 风险类别 | ✅ | 范围/进度/成本/质量/资源/技术/外部等 |
| 发生概率 | ✅ | 高/中/低，或百分比 |
| 影响程度 | ✅ | 高/中/低，或具体影响描述 |
| 风险等级 | ✅ | 概率 × 影响，高/中/低 |
| 应对策略 | ✅ | 规避/转移/减轻/接受 |
| 应对措施 | ✅ | 具体要做什么来降低概率或影响 |
| 负责人 | ✅ | 谁对风险应对负责 |
| 状态 | ✅ | 已识别/应对中/已关闭/已发生 |
| 识别日期 | ✅ | 什么时候发现的 |
| 预计发生时间 | ⬜ | 如果发生，大概在什么时候 |
| 触发条件 | ⬜ | 出现什么信号说明风险即将发生 |

## 注意事项
1. **风险不是问题**：风险是可能发生的坏事，问题是已经发生的坏事。不要把风险登记册变成问题清单
2. **应对措施要具体可执行**："加强沟通"不是应对措施，"每周与第三方同步进度，超时 2 天升级到总监"才是
3. **每个风险必须有负责人**：没有负责人的风险等于没人管
4. **定期更新**：建议每周回顾一次风险登记册，更新状态、补充新风险、关闭已过期风险
5. **高风险要单独跟踪**：高风险项需要更频繁的跟踪频率（如每日/每两日）
6. **风险发生了就转成问题**：风险一旦发生，就从"风险"变成"问题"，转到问题管理流程
7. **不要只列技术风险**：范围、资源、外部、管理类风险往往影响更大
8. **接受风险要有意识**：选择"接受"策略的风险，要确保相关方知晓并同意承担后果
