# 经验教训模板

## 模板用途
项目收尾或阶段性总结时，系统地复盘项目过程中的成功经验和失败教训，沉淀知识，避免同类问题在未来项目中重复发生。

## 填写说明
| 字段 | 必填 | 说明 |
|------|------|------|
| 项目基本信息 | ✅ | 项目名称、周期、参与人员等 |
| 做得好的方面 | ✅ | 成功经验，值得推广的做法 |
| 做得不好的方面 | ✅ | 问题和教训，需要改进的地方 |
| 改进建议 | ✅ | 具体可落地的改进行动 |
| 责任人和时间 | ⬜ | 谁来推动改进，什么时候完成 |
| 知识沉淀 | ⬜ | 需要归档到知识库的内容 |

## 注意事项
1. **对事不对人**：复盘的目的是改进流程和方法，不是追究个人责任，营造安全的氛围很重要
2. **挖根因不要找借口**：用"5 Why"法往下挖三层，停留在"人员不足""时间不够"这种表面原因没有意义
3. **改进措施要 SMARK**：每个改进项必须有具体的动作、责任人和时间，不然就是空话
4. **既要批评也要表扬**：不能只说问题不说成绩，好的经验同样需要沉淀和推广
5. **及时做**：项目结束后 1 周内完成，时间长了大家都忘了细节
6. **跟踪改进落地**：复盘完不是结束，3 个月后回头看改进项有没有真的落地
7. **分享出去**：经验教训不要只存在这个项目的文件夹里，要分享给其他项目团队
8. **诚实但建设性**：问题要说透，但要用建设性的方式说，避免变成批斗会
