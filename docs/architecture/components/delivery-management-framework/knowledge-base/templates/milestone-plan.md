# 里程碑计划模板

## 模板用途
定义项目的关键里程碑节点和交付物，是项目进度跟踪和决策的核心依据，也是向上汇报和对外承诺的基础。

## 填写说明
| 字段 | 必填 | 说明 |
|------|------|------|
| 里程碑名称 | ✅ | 简洁有力的里程碑名称 |
| 计划日期 | ✅ | 里程碑预计达成日期 |
| 交付物 | ✅ | 该里程碑必须产出的可验证交付物 |
| 验收标准 | ✅ | 怎么就算达成了，必须可验证 |
| 负责人 | ✅ | 对该里程碑负最终责任的人 |
| 前置依赖 | ⬜ | 达成此里程碑依赖的前置条件 |
| 风险提示 | ⬜ | 可能影响里程碑的主要风险 |

## 注意事项
1. 里程碑是"点"不是"段"：里程碑是某个时间点必须达成的状态，不是一段时间的任务
2. 里程碑要有可验证的交付物：不能是"需求分析完成"这种主观判断，必须有产出物和验收标准
3. 里程碑数量控制在 5-10 个：太少不够跟踪，太多失去重点
4. 关键路径必须明确：知道哪些里程碑延期会直接影响整体交付
5. 定期更新状态：建议每周更新一次里程碑状态（绿/黄/红）
6. 里程碑变更要审批：里程碑是进度基线的一部分，变更需要走变更流程
7. 不仅列计划，还要列风险和依赖：提前识别威胁里程碑的因素
