# L4 交付中心运营引擎 — 项目规划

> 创建日期：2026-08-28
> 状态：M0 设计阶段
> 基于：L3 交付管理通用业务层 + Bangcle 专有业务需求

---

## 一、项目定位

**目标**：建设 Bangcle 交付管理系统（BDMS），作为 L4 专有业务层的核心载体。

**核心功能**：
1. 交付月报自动生成（15 Sheet）
2. 确收月报自动生成（10 Sheet）
3. 数据采集（ONES/OA/企业微信/工时门户）
4. 业务逻辑引擎（关联查询/状态判定/考核计算）
5. 审批流程（OA 审批 + 合同解析）
6. 调度监控（cron + WeCom 投递）

## 三、技术架构

### 3.1 分层

```
┌─────────────────────────────────────────┐
│  M5 调度层 (cron + 投递)                  │
├─────────────────────────────────────────┤
│  M4 审批层 (OA 审批 + 合同解析)            │
├─────────────────────────────────────────┤
│  M3 报告层 (Excel 生成器)                  │
├─────────────────────────────────────────┤
│  M2 引擎层 (关联/状态/考核/统计)            │
├─────────────────────────────────────────┤
│  M1 数据层 (采集 + 清洗 + 存储)            │
└─────────────────────────────────────────┘
```

### 3.2 数据流

```
ONES ──┐
OA ────┤──→ 采集器 ──→ 清洗 ──→ SQLite ──→ 引擎 ──→ 报告
微信 ──┤                                              │
工时 ──┘                                              └──→ WeCom 投递
```

### 3.3 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 浏览器自动化 | Playwright | 支持大数据量导出 |
| 数据处理 | pandas | VLOOKUP → merge, Pivot → pivot_table |
| 报告生成 | openpyxl | Excel 原生格式，支持公式 |
| 数据存储 | SQLite | 轻量级，本地持久化 |
| 调度 | OpenClaw cron | 已集成，支持 announce 投递 |

## 四、核心难点

1. **数据量 100000+** → 分批处理 + SQLite 中间存储
2. **月度继承** → 按月份顺序逐月计算
3. **跨系统关联** → 合同编号校准 + 模糊匹配
4. **报告一致性** → 逐列对比验证

---

## 五、核心风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 报告结果偏差 | 业务决策错误 | 逐列对比 + 差异报告 |
| 系统升级导致自动化失效 | 采集中断 | 选择器抽象 + 版本锁定 |
| 项目范围蔓延 | 延期 | 严格按里程碑推进 |
| 沙箱文件系统隔离 | 文件丢失 | 通过 exec+bash-lc 在 host 写入 |
