# 沙箱隔离 (L2 基础设施组件)

> 本文档是 [系统架构](../00-system-architecture.md) 的 L2 组件设计文档。
> 决策记录: [ADR-XXXX] — TBD, 2026-08-24 建设完成

## 1. 定位

**层级**: L2 基础设施层
**类型**: 横切关注点 (Cross-Cutting Concern)
**状态**: ✅ 已上线 (2026-08-24) — Docker + non-main 加固基线，实测验证通过

沙箱隔离是 L2 的安全组件——为非主会话（子任务、cron、子代理）提供隔离执行环境，避免不可信代码影响主系统。

## 2. 问题定义

| 风险 | 不隔离后果 |
|---|---|
| 子任务代码误删主目录文件 | 主工作区损坏，需要恢复备份 |
| 子任务联网拉取恶意代码 | 危及整个系统安全 |
| 子任务消耗过多资源 | 主会话响应变慢 |

核心需求：**默认安全**——非主会话默认隔离，需要时才放开权限。

## 3. 设计原则

| 原则 | 说明 |
|---|---|
| **默认隔离** | 所有非主会话自动进入沙箱，不例外 |
| **最小权限** | 只读访问工作区，无网络，降权运行 |
| **不影响主会话** | 沙箱故障不影响主系统运行 |
| **可配置** | 对可信任务可逐步放开权限（网络/读写） |
| **复用官方** | 基于 OpenClaw 原生沙箱实现，不重新发明轮子 |

## 4. 架构设计

### 4.1 当前基线配置 (OpenClaw 原生)

```yaml
agents.defaults.sandbox:
  mode: non-main
  backend: docker
  image: openclaw-sandbox:bookworm-slim
  workspaceAccess: ro
  network: none
  readOnlyRoot: true
  capDrop: ALL
  scope: agent
```

### 4.2 权限矩阵

| 会话类型 | 沙箱 | 网络 | 工作区 | 根文件系统 |  capabilities |
|---|---|---|---|---|---|
| 主会话 | ❌ 不隔离 | ✅ 允许 | ✅ 读写 | ✅ 可写 | 完整 |
| 子代理/cron 任务 | ✅ 隔离 | ❌ 禁止 | ✅ 只读 | ❌ 只读 | 全部丢弃 |

### 4.3 能力边界

**沙箱内可用工具**：
- gateway 代理工具（automations / sessions / memory 等）—— 由 gateway 执行，不碰沙箱网络/文件系统
- 纯计算任务，不依赖外部网络

**沙箱内不可用**：
- `exec` 执行外部命令（无网络，容器内没有 host CLI）
- 写入工作区文件（只读挂载）
- 网络请求（`network: none`）

## 5. 已知适配问题与解决方案

| 问题 | 解决方案 |
|---|---|
| 需要 host 网络/CLI 的 cron 任务（如 provider 健康探测、记忆检索监控） | 改为 `sessionTarget: current`，运行在主会话，保持工具权限白名单限制，兼顾安全和功能 |
| 沙箱内没有 openclaw CLI | 所有操作通过 gateway 代理工具（automations 等）完成，不依赖本地 CLI |
| 配置变更需要重启沙箱 | OpenClaw 自动处理，每次运行新建容器 |

## 7. 与其他组件的关系

```
沙箱隔离 (本组件)
  ↑ 被依赖
  ├── L1 OpenClaw 原生沙箱能力
  ├── L2 所有非主会话组件 (cron / 子代理)
  └── L3/L4 任务执行

  ↓ 依赖
  ├── L1 运行时抽象契约 (沙箱执行接口)
  └── L2 错误自动处理 (沙箱任务失败自动重跑)
```
