# ADR-033：Web UI 设计开发能力体系建设

> 状态：proposed
> 日期：2026-10-17
> 决策人：Rex

## 背景

近期 BDMS 报表页 UI 调试暴露了系统级问题：

1. **视觉质量不可控**：纯文本模型无法直接感知页面视觉效果，布局/间距/对齐等低级问题需用户反复指出才能修复
2. **web-common 组件文档空心化**：现有 PRD/DESIGN-OUTLINE/DESIGN-DETAIL 均为骨架模板，无实质内容
3. **缺视觉验收环节**：交付 7 步法只覆盖功能和数据准确性，未覆盖视觉布局
4. **缺视觉回归保障**：改一个页面的 CSS 可能影响其他页面，没有自动化检测手段

截至 2026-10-17，系统有 7 个 Web 组件、71 个页面模板，但没有统一的视觉质量保障体系。

## 决策

建设 **Web UI 设计开发能力体系**，落地为 web-common 组件的 v2.0 升级，包含 5 大模块：

### 模块 1：Design Tokens 设计系统
- 从现有 CSS 变量抽象为标准化 Design Tokens 体系
- 覆盖：颜色 / 间距 / 字号 / 圆角 / 阴影 / 断点 六大类
- 单一事实来源，所有组件复用
- 产出：`DESIGN-TOKENS.md` + CSS 变量定义

### 模块 2：视觉回归测试基础设施
- 技术选型：**Playwright Python + 像素级对比**
- 选型理由：Python 技术栈原生支持、已有浏览器自动化基础、零额外依赖、与 E2E 测试体系融合
- 核心能力：黄金基准图管理 / 自动截图对比 / diff 报告 / 动态内容 mask
- 阈值：默认 0.1% 像素差异容忍度

### 模块 3：UI 验收 Checklist + 流程制度化
- 5 大类 25+ 检查项：布局对齐 / 视觉层次 / 组件一致性 / 交互反馈 / 可访问性
- 嵌入交付 7 步法，新增第 8 步「视觉验收」
- 开发完成 → 自动视觉回归通过 → checklist 走查 → 交付

### 模块 4：UI 设计师角色
- 在 role-library 中新增 `ui-designer` 角色
- 职责：UI 走查 / 布局优化 / 组件规范 / 视觉一致性检查
- 让"以 UI 设计师角色 review 这个页面"成为标准工作流

### 模块 5：现有 71 页面 UI 走查
- 7 个 Web 组件 × 页面逐一走查
- 建立基准图库
- 批量修复布局/间距/对齐/一致性问题

## 理由

### 为什么现在做
- BDMS 事件证明：低级视觉问题反复出现，已影响交付质量
- 71 个页面规模已足够大，靠人工记忆不可靠
- L2 web-common 组件已有基础，升级成本低、收益高

### 为什么选 Playwright 而非其他工具
| 工具 | 开源 | Python 支持 | 学习成本 | 适配度 |
|---|---|---|---|---|
| Playwright | ✅ | ✅ 原生 | 低（已有浏览器自动化基础） | ⭐⭐⭐⭐⭐ |
| BackstopJS | ✅ | ❌ JS 栈 | 中 | ⭐⭐⭐ |
| Lost Pixel | ✅ | ❌ JS 栈 | 中（需 Storybook） | ⭐⭐ |
| Argos | ✅核心 | ❌ | 中 | ⭐⭐⭐ |

结论：Playwright Python 是唯一与我们技术栈完全匹配的选项。

### 为什么不引入完整设计系统（如 Carbon/ShadCN）
- 我们是 Jinja2 模板 + 原生 CSS，不是 React/Vue 组件体系
- 引入重型设计系统成本过高，且与现有架构不匹配
- 从轻量 Design Tokens 入手，渐进式升级更合适

## 影响

### 正向
- 从源头消除视觉不一致问题
- 交付质量提升，减少用户反复指出低级问题
- 视觉回归自动化，防止改 A 页面弄坏 B 页面
- 71 个页面统一规范，长期维护成本降低

### 负向
- 需要投入约 15 天工作量（3 个 Phase）
- 全量页面走查期间可能产生较多 CSS 变更
- 视觉基准图建立后，后续改动需同步更新基准图

### 风险
- **视觉审美判断仍依赖人**：自动化只能保证"一致"和"规整"，不能保证"好看"。最终审美决策仍需 Rex 或设计师拍板
- **动态内容干扰**：图表、数据列表等动态内容会导致视觉对比误报，需要 mask 处理
- **浏览器渲染差异**：headless Chrome 和真实浏览器渲染可能有细微差异

## 边界

本 ADR 不包含：
- 完整的 UI/UX 设计能力（AI 模型本身的视觉感知能力局限）
- 交互设计师角色（复杂交互设计仍需专业设计师）
- 设计稿到代码的自动生成
- 移动端适配的全面升级（后续单独规划）
