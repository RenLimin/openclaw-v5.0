# Lane C 调研：不碰客户端，用官方/现成产品拿「微信 / 企业微信群消息」

- 版本：v1.0 ｜ 日期：2026-11-24 ｜ 子代理：官方通道与现成产品(C)
- 目标：在**不做桌面 UI 自动化、不破解客户端**的前提下，枚举一切「官方能力 + 现成产品」路径，判断能否拿到微信群 / 企业微信群消息。
- 对照背景：桌面直连 lane（AX/本地库）已实测——企业微信 AX 可读、微信 macOS 4.1.15 AX 为空壳；本地库解密需关 SIP/重签/root 调试。本报告只覆盖 lane C。
- 口径：✅ 官方文档实证 ｜ ⚠️ 第三方/社区来源（可能过时或有利益立场）｜ ❓ 未核实（缺权威出处，禁止当作结论）。

一句话结论：**微信群**在"不碰客户端"约束下只剩两条真路——iOS 27 通知自动化（当条增量）与第三方工具解析迁移/备份出的本地库（全量但离线）；**企业微信群**的正解是会话内容存档（付费、需授权、不可回溯），智能机器人只能拿 @ 消息。

## 二、逐项评估表（机制 / 前置条件 / 边界 / 成本 / 成熟度）

### C1 微信 iLink / ClawBot 插件（官方）
- 机制：OpenClaw 侧装 `@tencent-weixin/openclaw-weixin`（npm 安装器为 `@tencent-weixin/openclaw-weixin-cli`），iOS 微信「设置-插件-ClawBot」扫码，建立 HTTP JSON 协议通道（长轮询收消息）。仓库：https://github.com/Tencent/openclaw-weixin （实证 200）；npm registry 实证 200。
- 前置：iOS 微信（社区称安卓未开放，❓未核实官方）、Node ≥22.13、OpenClaw ≥2026.5.12（README 环境要求）。
- **群聊边界（关键）**：腾讯官方口径与媒体一致——「微信 ClawBot 是与自己拥有的 OpenClaw 之间的私密消息通道……**目前微信 ClawBot 不能被加入微信群，仅支持个人单点使用**」（Yahoo 财经转述微信官方，⚠️媒体来源）。社区实测（2026-09，cc-connect issue #1841）：新建群/群设置/群成员页/插件页**四处入口都搜不到 bot**，私聊正常、群消息为零。官方仓库 issue #42 仍在请求开放群聊能力 → 未开放。
- 其他限制：iLink 不支持主动推送（需用户先发消息，HTTP API 除外）；一个微信只能绑一个 OpenClaw；腾讯保留随时限速/终止权利（⚠️二手来源）。
- 判定：**对"群消息"= 死路**；对"个人微信当遥控器"成立。

### C2 微信官方消息 API（个人号）
- 微信公众平台/开放平台只提供公众号、开放平台账号、小程序、微信客服等主体能力；**不存在面向个人微信号收发消息/读取聊天记录的开放 API**。任何声称"微信个人号 API"的服务均为非官方逆向，不在本 lane 且合规风险高。
- 判定：**死路**（就官方而言）。

### C3 微信聊天记录迁移 / 备份 + 现成工具
- 官方机制：手机微信「我-设置-通用/聊天-聊天记录迁移与备份-迁移到电脑」，把记录迁到电脑微信本地库；另有「备份与恢复」生成加密备份（官方明示加密、不可直接查看，用于恢复到手机）。2026 年灰测「备份到外部存储设备 + 自动备份（>24h）」，官方强调加密存储、多人不串台（⚠️媒体来源，灰测中）。
- 可程序化程度：迁移到电脑后的本地库 = 标准 SQLite（SQLCipher），第三方工具可解密读取，含群聊。→ 这已属"读客户端数据"，不是纯 lane C，但不需要 UI 自动化，比 lane A 省事。
- 判定：**可用（全量、离线、批处理）**；代价是必须先在手机/电脑微信上做一次官方迁移动作。

### C4 Apple 快捷指令「通知自动化」（iOS 27）★2026 新变化
- 官方机制：Apple 官方新功能页（https://support.apple.com/zh-cn/149045 ，实证 200）在 27 的新自动化中列出「**通知（"当我收到来自'新闻'的通知时"）**」。第三方媒体（少数派 https://sspai.com/post/114536 ，实证 200）实测确认：**任何能发通知的 App 都可作触发器，微信在内**；可读取通知的标题/副标题/正文做筛选；前置条件：该 App 系统通知开启，且在「锁屏」或「通知中心」至少选一种展示位置（**仅横幅不触发**）。
- 拿群消息的能力：通知标题=群名/联系人备注、正文=消息内容（媒体/长文会被截断）；可在快捷指令里用「获取 URL 内容」POST 到 webhook / 邮件 / Telegram Bot，实现转发。
- 硬边界：
  - 只能拿**通知产生的那一条**（增量），历史消息不可回溯；
  - 群消息若被折叠成"X 条新消息"汇总通知，则拿不到逐条正文（❓取决于微信通知样式，未实测）；
  - 依赖 iPhone 在手、通知未被一键清除、自动化未被系统节流；锁屏/隐私策略可能限制后台运行（❓未核实）；
  - macOS Tahoe 也引入了快捷指令自动化，但是否有"第三方 App 通知"触发器未核实（❓）。
- 成本：0（系统内置）。成熟度：2026 年新功能，生态案例已成型。
- 判定：**本 lane 中唯一"零客户端接触、官方、实时"的微信群增量通道**；定位为补充，不是全量采集器。

### C5 iOS 加密备份 + 备份提取产品
- 机制：iTunes/Finder 加密备份包含微信数据（含群聊库）；现成产品如 Reincubate iPhone Backup Extractor 宣称支持 WeChat（⚠️其官网本次连接失败，能力为搜索快照，未完全核实）；同类还有 iBackup Viewer 等。
- 前置：加密备份密码；备份必须在本机/自有设备。
- 判定：可用但小众、付费、非实时；与 C3 同源（读库）。

### C6 企业微信「智能机器人」（回调 / 长连接 / API 模式）
- 官方文档节点（均实证 200）：概述 101039、接收消息 100719、接收事件 101027、被动回复 101031、主动回复 101138、长连接 101463、API 模式机器人使用说明 101468、加解密 101033。
- **核心边界（官方正文摘要，实证）**：可接收的消息是「① 用户群里 @智能机器人 或单聊发的文本；② 群里 @机器人 的图文混排；③ 单聊图片/语音/文件/视频；④ 群里 @机器人 或单聊的引用消息」等。即**群内没有 @ 机器人的消息一律收不到**。
- 前置：企业管理员在后台创建智能机器人、配置回调 URL 或改用 WebSocket 长连接（免公网回调）；机器人需被拉进目标群。
- 成本：接口免费；长连接省去回调服务器。
- 判定：**半死路**——适合"群里提问机器人"场景，不适合"旁听全群"。

### C7 企业微信「会话内容存档」（原生 + 数据与智能专区）★唯一全量官方路径
- 官方节点（实证 200）：概述 91360、使用前帮助 91361、获取会话内容 GetChatData 91774、开发案例 91551、FAQ 91552、开启成员列表 91614、同意情况 91782、内部群信息 92951、产生会话回调事件 95039；数据与智能专区 99941～100142（含获取会话记录 99968、会话搜索 99971/99972、会话导出 99987）；收费方案 100099。
- 机制：企业管理员开通存档 → 员工知情同意（有同意回调事件）→ 企业设公钥 → 通过 SDK 拉取或回调接收明文消息（含内部群、客户群、音视频会议<企业版>）。
- 官方明示边界：**不可回溯**——只存"自授权日起"的会话；存储时长企业可选 90 天/180 天/1 年/2 年，过期不存；试用 30 天；付费到期 30 天未续期则停止存储（以上出自官方收费方案页 100099，实证）。
- 前置：企业管理员权限 + 员工同意 + 企业自行开发（官方只给 API/SDK，SDK 仅 Linux/Windows，见 FAQ 91552）或采购服务商。
- 价格：官方页面未列单价；第三方报价（⚠️未核实、有销售立场）：原生存档服务版约 900 元/人/年、企业版约 1800 元/人/年；数据与智能专区服务版约 300 元/人/年、企业版约 500 元/人/年。**禁止把上述数字当官方定价**。
- 判定：**企业微信群全量消息的唯一合规官方路径**；个人/小团队无管理员权限即不可用。

### C8 企业微信「客户群 API」
- 节点：获取客户群列表 92120、详情 92122、opengid 转换 94822、入群方式 92229、群聊数据统计 92133、消息推送（创建企业群发 92135 / 提醒成员群发 97610）。
- 边界：**只返回群元数据（群名、成员、群主、创建时间、统计）与群发能力，不返回群内聊天内容**。要内容须回到 C7。
- 判定：**死路（消息内容维度）**，但可作 C7 的群清单补充。

### C9 企业微信自建应用「接收消息与事件」
- 节点：概述 90238、消息格式 90239、事件格式 90240、被动回复 90241；另可经「创建群聊会话 90245」建应用群。
- 边界：自建应用能收到的是发给应用的消息及被配置回调的事件；要覆盖既有群，需把应用作为成员拉入群并让其处于可见范围，逐群配置，非开箱全量。
- 判定：**边缘可行**，工程量大，一般不如直接上 C7。

### C10 商业会话存档 / SCRM 服务商
- 事实：市场上存在微盛·企微管家、尘锋、一维助手、艾客 SCRM、探马等基于「数据与智能专区/原生存档」的服务商，提供会话查看、质检、关键词/情绪监控、AI 总结等（⚠️厂商宣传页，能力描述未逐一核实）。
- 价值：免自研（官方 SDK 需企业自己写），开箱即用；代价是数据经服务商、付费、需企业授权。
- 判定：C7 的封装，可用；选型需核验其是否为官方认证服务商与数据存储边界。

### C11 开源导出 / 备份工具（现成产品）
| 工具 | 群聊 | Mac 支持 | 机制 | 状态 |
|---|---|---|---|---|

### C12 换平台承载工作群（事实对比，不建议）
- 飞书（官方文档实证 200，https://open.feishu.cn/document/server-docs/im-v1/message/events/receive ）：事件 `im.message.receive_v1`，权限含「**获取群组中所有消息（敏感权限，仅自建应用）**」「获取群组中用户和机器人消息」「获取群组中用户 @ 机器人消息」→ **机器人可拿群内全部消息**，另有历史版本权限；支持 Webhook 与长连接。
- 钉钉（官方文档实证，机器人概述/事件订阅总览）：机器人类型表中「自定义机器人」支持群聊（外部群&&内部群）**发送**；但事件订阅总览的即时通讯分类只列会话管理事件（群解散/加人/删人/换群主等），**未见"接收群消息内容"事件**；消息接收类仅见「下载机器人接收消息的文件内容」。→ 通用群消息读取能力 ❓未核实是否存在其他入口。
- 结论（仅事实）：**在"群消息可编程读取"上，飞书的开放度明显高于钉钉与微信/企微智能机器人**；但换平台 = 换掉群本身，属重决策。

## 四、2026 年最新变化（相对早期认知）

1. **iOS 27 通知自动化**：第三方 App 通知首次成为快捷指令触发器（Apple 官方功能页实证），微信群消息第一次有了"零接触、实时、官方"的增量通道（局限见 C4）。
2. **企业微信智能机器人长连接 + API 模式**：官方把机器人从"回调"升级到 WebSocket 长连接（101463）与 API 模式（101468），降低部署门槛，但**消息范围仍限 @机器人**，没有放宽。
3. **会话存档价格/产品形态**：2025 年末起原生存档与"数据与智能专区"并行，出现服务商低价封装（⚠️价格均来自第三方，未核实官方）。
4. **微信聊天记录备份**：灰测"备份到外部存储设备 + 自动备份"，仍是加密、面向恢复而非程序读取。
5. **腾讯 QClaw / WorkBuddy**：腾讯系桌面 Agent 与企微打通的新闻存在（⚠️媒体），但不改变消息获取通道本身。
