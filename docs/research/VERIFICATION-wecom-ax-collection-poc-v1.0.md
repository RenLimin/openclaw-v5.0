## 二、详细验证结果

### 1. 会话列表读取 ✅

- **接口**：遍历 AX 树中所有 `AXCell`，过滤 x 在 60-347 范围（左侧窄条）
- **数量**：可见区域 46 个 cell，完整列表约 92 个（含滚动）
- **字段**：
  - 群名/人名 ✅
  - 最后一条消息 ✅（支持长文本截断）
  - 时间戳 ✅（刚刚/X分钟前/昨天/周X/MM-DD）
  - 内外群标签 ✅（外部/部门/全员）
  - 未读数 ✅（1-3 位数字小红点）
- **示例**（已脱敏为合成数据）：
  ```
  1. 示例项目群B  2分钟前
     ↳ @张三 处理进度？另外，本周需反馈客户侧内容…
  4. 示例部门群A [部门]  昨天
     ↳ 李四: [示例附件_20261120.xlsx]
  6. 示例客户专项群C（外） [外部]
     ↳ 王五: 收到 星期四
  ```
- **坐标精度**：每个 cell frame = `(60, y, 287, 64)`，高度 64px，可直接用于点击定位

### 2. 消息正文读取 ✅

- **接口**：过滤 x 在 340-1250 范围的 `AXTextArea` + `AXStaticText`
- **数量**：可见区域约 20-30 条消息（视消息长度）
- **可读到的元素**：
  - 消息正文（多行、含 @提及、含链接）✅
  - 发送者名称 ✅
  - 时间戳（HH:MM / 昨天 HH:MM）✅
  - 系统消息（日期分隔、加入群聊、撤回）✅
  - 群公告/智能总结卡片文本 ✅
- **结构化解析状态**：可用但需优化
  - 发送者识别：启发式（左侧短文本 = 发送者），准确率约 85%
  - 多行合并：按 y 坐标分组，基本正确
  - 右侧群成员面板干扰：已通过 x<1250 过滤排除
- **改进空间**：
  - 需要通过气泡 x 坐标区分「自己发的」vs「对方发的」（x 近左 = 对方，x 近右 = 自己）
  - 图片/文件/表情的文本占位符需要单独处理
  - 长消息的折叠展开需通过 AX 滚动+追加采集

### 3. AX 点击切换会话 ✅

- **方法**：通过 `CGEvent` 发送鼠标左键点击事件到 cell 中心坐标
- **验证**：点击「示例部门群A」后，消息区内容从另一会话切换为目标会话
- **切换延迟**：约 200-500ms（UI 渲染 + AX 树更新）
- **注意**：
  - 点击会抢走鼠标焦点（真实鼠标移动），后台轮询时应避免干扰用户
  - 可以用 `AXUIElementPerformAction` + `kAXPressAction` 替代（本次用 CGEvent 更可靠）
  - 滚动到不可见的会话需要先模拟滚动

### 4. 轮询去重 ✅（可用，未深测）

- **去重指纹方案**：消息 y 坐标 + 内容哈希 + 发送者
- **原理**：同一条消息在未滚动时 y 坐标稳定，滚动后可通过内容+发送者匹配
- **新消息检测**：对比前后两次采集的消息指纹集合，差集 = 新消息
- **待工程化验证**：
  - 滚动时的消息位置漂移处理
  - 编辑/撤回消息的变更检测
  - 图片消息的占位符识别

### 5. 后台/最小化稳定性 ✅

| 状态 | AX 节点数 | 会话 cell | 文本节点 | 消息区采样 |
|---|---|---|---|---|
| 前台激活 | 599 | 78 | 214 | 正常 |
| 最小化 | 599 | 78 | 214 | 正常 |
| 恢复 | 600 | 78 | 214 | 正常 |
| 后台（Finder 前台） | 600 | 78 | 214 | 正常 |
| 恢复激活 | 599 | 78 | 214 | 正常 |

**关键结论**：企微 AX 树在最小化和后台状态下**完全可读、节点数稳定**。不需要保持窗口前台，也不需要屏幕录制权限。

> 注：`AXMinimized` 属性读取为空（可能是企微窗口的子角色/属性命名差异），但不影响采集——frame 和内容都正常。

## 三、能力边界（诚实说清）

| 能力 | 状态 | 说明 |
|---|---|---|
| 读取已加载的会话列表 | ✅ 完整 | 可见区域 ~46 个，完整需滚动 |
| 读取当前打开群的可见消息 | ✅ 完整 | 文字、@、链接、系统消息均可读 |
| 读取历史消息 | ⚠️ 部分 | 需要模拟滚动加载，越滚越慢，不适合全量 |
| 发送消息 | ❌ 未验证 | 理论上可通过 AX 操作输入框，但不在本次 PoC 范围 |
| 图片/文件内容 | ❌ 不可读 | AX 只能读文本节点，图片/文件只能看到文件名或占位符 |
| 语音/视频 | ❌ 不可读 | — |
| 群成员列表 | ✅ 可读 | 右侧面板 x>1300 区域，已验证 29人群成员全部可见 |
| 实时推送 | ❌ 不支持 | AX 是轮询模型，不是事件推送 |
| 多账号/多窗口 | ❓ 未验证 | 理论上每个窗口一棵 AX 树 |

## 五、工程化路线（如果要做成产品）

### Phase 1：最小可用采集器（1-2 天）
- Python 包一层 `swift` 调用（或用 pyobjc 直调 AX API）
- 会话列表轮询 + 新消息检测（指纹去重）
- 输出到 JSONL / MQ / webhook
- 配置文件：监控的群名列表、轮询间隔

### Phase 2：稳定化（3-5 天）
- 自动处理窗口最小化/关闭/重启
- 滚动加载更多历史消息
- 消息解析准确率优化（发送者识别、气泡左右判断、@提及提取）
- 错误恢复（AX 树超时/失效时重建）

### Phase 3：生产级（1-2 周）
- 去重+幂等（消息 UUID 生成策略）
- 存储后端（SQLite / 向量库）
- 监控与告警（采集率、延迟、异常）
- 权限自检与引导

## 六、风险与限制

1. **版本耦合**：企微升级可能改变 AX 树结构，导致解析失效。需要版本适配测试。
2. **只能读 UI 已加载内容**：历史全量采集不现实（需逐条滚动，效率低）。
3. **不支持富媒体**：图片、文件、语音只能看到文件名/占位符，看不到内容。
4. **用户体验影响**：切换会话时鼠标会真实移动（如果用 CGEvent 方案）。可以用 `AXPress` action 或后台窗口操作优化。
5. **合规性**：辅助功能权限 + 读取他人对话 = 敏感操作，需明确用途和留存策略。
6. **封号风险**：低（纯读 UI，不注入不改客户端），但高频自动操作可能触发反作弊，需控制频率。
