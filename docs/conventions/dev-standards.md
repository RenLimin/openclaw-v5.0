# 全局开发设计规范

> 版本：v1.0 · 2026-09-08
> 归属层级：L1 操作规范（约定层）— 与 `multi-session-build.md`、`commit-and-config.md` 同级
> 依据：ADR-012（运行时抽象）· 00-system-architecture.md §1.3（原生优先原则）
> 适用范围：**所有 L2/L3/L4 新功能、新组件、新机制的设计与开发**（不限于会话编排）

## 目的

在开发任何新功能/新组件/新机制前，统一按以下三查 + 六问核查，确保：

1. **符合系统架构** — 分层设计、低耦合、可继承、可移植、可跨 AI Agent
2. **符合 AI Agent 官方文档** — 复用原生能力，避免系统冲突
3. **不重复建设** — 读取现有资产，先复用再新建；已有重复建设则重新规划

## 三查（建设前强制）

| 序号 | 查什么 | 怎么查 | 结论处理 |
|---|---|---|---|
| 1 | **运行时原生能力** | 当前 AI Agent 官方文档（OpenClaw: `docs/` 目录或 docs.openclaw.ai） | 原生已有 → 复用，不自己做 |
| 2 | **现有 L2 资产** | `docs/architecture/01-asset-inventory.md` + `L2-infra/components/` | 已有类似组件 → 复用/扩展，不新建 |
| 3 | **现有 L3/L4 资产** | `docs/architecture/00-system-architecture.md` §3.4/§3.5 + 对应组件目录 | 通用业务层已有 → 继承，不重复实现 |

**查完必须留下记录**：在 DESIGN.md 开头写明「已查原生能力 / 已查资产 / 复用结论」，否则视为未过三查。

## 六问（设计时逐条自答）

新组件/DESIGN 必须能回答以下 6 个问题，答案写入 DESIGN.md：

| # | 问题 | 合格答案 |
|---|---|---|
| 1 | **分层位置** | 放在 L2/L3/L4 哪一层？为什么？（依据职责，不越级） |
| 2 | **职责边界** | 管什么、不管什么？与相邻组件如何分工？（避免重叠） |
| 3 | **原生优先** | 运行时原生是否已有此能力？为什么不复用？（依据官方文档） |
| 4 | **可移植性** | 是否绑定具体 AI Agent？核心逻辑与适配层是否分离？（L2-L4 只依赖 L1 抽象） |
| 5 | **可继承性** | 是否可被上层复用？是否继承了通用层能力？（复用优先） |
| 6 | **冲突规避** | 会不会与运行时原生机制冲突（双层控制/重复限流）？（架构对齐） |

## 原生能力归属速查（持续更新）

> 新功能设计时先查此表；本表随运行时而变，升级/切换 Agent 后需更新。

| 能力 | 归属 | 说明 |
|---|---|---|
| 最大并发数控制 | 运行时原生 | OpenClaw: `agents.defaults.subagents.maxConcurrent`（默认 8） |
| 子代理嵌套深度 | 运行时原生 | OpenClaw: `maxSpawnDepth`（默认 1，范围 1-5） |
| 每会话最大子代数 | 运行时原生 | OpenClaw: `maxChildrenPerAgent`（默认 5） |
| 速率限制(RPM/TPM) | 运行时原生 + provider 侧 | OpenClaw 控制面写入 30/60s；业务级限流走模型调度组件 |
| 会话生命周期管理 | 运行时原生 + L2 辅助 | 原生自动归档为主，L2 会话隔离组件补充策略 |
| 任务依赖/排序 | L2 自建 | 原生不提供业务级编排原语 |
| 错峰启动(间隔控制) | L2 自建 | 避免 burst 限流，原生不提供 |
| 任务状态跟踪/任务卡 | L2 自建 | 业务状态管理，原生只管会话生命周期 |
| 模型路由/健康/用量/预算 | L2 自建(model-scheduling) | 已上线，原生不提供业务级路由策略 |

## 设计文档要求

新组件必须包含 `docs/architecture/components/<name>/DESIGN.md`，且必须包含：

| 章节 | 内容 |
|---|---|
| 目的 | 解决什么问题，不解决什么 |
| 分层定位 | 所属层级 + 依据 |
| 职责边界 | 管什么 / 不管什么 + 相邻组件分工 |
| 三查记录 | 原生能力 / 现有资产 / 复用结论 |
| 六问自答 | 上面 6 个问题的答案 |
| 依赖声明 | dependencies 字段：升级前校验点 / 升级后更新点 |
| 可移植性 | 核心逻辑 vs 适配层如何分离 |
| 测试策略 | 如何验证，测试先行 |
