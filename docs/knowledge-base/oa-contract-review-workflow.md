## 五、处理口径（从实测意见提炼）

1. **金额一致性是硬闸**：合同总金额 = 审核流程金额 = 概算金额 = 分项合计（872777 因 438000 vs 300000 不符被财务要求重走概算 + 重走合同审批）。
2. **分项 = 合同标的**：产品/服务、数量、服务边界、APP 数量（不限量 vs 限量）必须与合同正文一致，作为履约/验收/收入确认依据。
3. **税率与退税**：合同金额较大且以产品为主时，财务建议按产品销售适用 13% + 产品软著名（如「移动应用安全监测软件V5.0」），避免退税损失；服务类用 6%。
4. **验收方式必须明确**：优先双方签字盖章；若邮件验收，须在合同明确甲方官方邮箱等身份信息（保障外部验收效力）。
5. **回款条件审查**：付款节点、开票条件、账期、尾款、逾期责任、必要时的暂停服务权（872777 判定【可接受】）。
6. **源代码 / 定制**：是否交付客户化源代码需显式确认（872777 确认交付，客户仅做验收使用）。
7. **违约条款**：财务/法务提示实施侧注意合同内多项违约条款，避免违约（如合同金额 20% 违约金条款）。
8. **资质证明**：需协助客户提供《技术合同认定登记证明》（技术合同登记备案表/登记证书）时，在流程中确认可提供商侧配合。
9. **AI 小助手意见**：OA 内置 AI 审核产出「重点复核 / 可接受」分级 + 风险点 + 标准依据 + 合同原文片段 + 处理建议，可直接作为合同审查的输入，但**不替代人工评审结论**。
