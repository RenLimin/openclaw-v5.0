# 角色定义规范

> L3 业务角色的标准化定义流程和质量标准。

## 1. 角色定义标准流程

每个业务角色由 **4 个文件** 定义：

```
<dimension>/<role>/
├── SOUL.md       # 身份人设
├── AGENTS.md     # 业务能力
├── IDENTITY.md   # 简介
└── references/   # 参考知识索引（可选）
```

## 2. 文件规范

### 2.1 SOUL.md（身份人设）

**必填字段**：

| 字段 | 说明 | 字数要求 |
|------|------|----------|
| 角色定位 | 一句话定义"我是谁" | ≤ 50 字 |
| 核心能力 | 3-5 项关键能力 | 每项 ≤ 30 字 |
| 行为边界 | **"不做"清单**（防止角色越界） | ≥ 3 条 |
| 方法论 | 遵循的知识体系/标准 | 标注版本 |
| 沟通风格 | 该角色的表达偏好 | ≤ 100 字 |

**写作要求**：
- 角色定位要精准，不用"全能型"描述
- 行为边界必须包含"不做"清单，这是防止角色越界的关键
- 方法论必须标注版本（如"PMBOK 第 7 版"），便于后续更新

### 2.2 AGENTS.md（业务能力）

**必填字段**：

| 字段 | 说明 | 要求 |
|------|------|------|
| 工作流程 | 标准工作步骤 | ≥ 3 个步骤，含输入/输出 |
| 交付物清单 | 每次交互的产出物 | ≥ 3 个，含质量标准 |
| 决策树 | 常见场景的处理逻辑 | ≥ 5 个分支 |
| 工具使用 | 需要哪些 L2 能力 | 列出工具名 + 用途 |
| 质量标准 | 交付物应满足的标准 | 可量化 |

**写作要求**：
- 工作流程用编号步骤，每步有明确的输入和输出
- 交付物必须有模板或质量标准
- 决策树用 if-then 格式，覆盖常见场景

### 2.3 IDENTITY.md（简介）

**必填字段**：

| 字段 | 说明 | 字数要求 |
|------|------|----------|
| 一句话定位 | 20 字以内的角色描述 | ≤ 20 字 |
| 适用场景 | 3-5 个典型使用场景 | 每项 ≤ 30 字 |
| 能力边界 | 能做什么、不能做什么 | ≤ 100 字 |
| 前置条件 | 激活该角色需要什么上下文 | ≤ 50 字 |

### 2.4 references/（参考知识索引）

可选目录，存放该角色依赖的业务知识索引。

格式：`references/README.md`，列出知识文档路径 + 一句话摘要。

## 3. 质量标准

### 3.1 完整性检查

- [ ] IDENTITY.md ≤ 100 字，包含 4 个必填字段
- [ ] SOUL.md 包含"不做"清单（≥ 3 条）
- [ ] AGENTS.md 包含 ≥ 3 个交付物 + ≥ 5 个决策分支
- [ ] 角色不与其他同维度角色职责重叠

### 3.2 一致性检查

- [ ] 术语使用一致（同一概念不用不同名称）
- [ ] 格式遵循模板（标题层级、列表样式）
- [ ] 来源标注清晰（每篇知识文档标注权威来源）

### 3.3 可用性检查

- [ ] 角色能通过端到端测试（给定输入 → 正确输出）
- [ ] 知识检索能召回角色需要的业务知识
- [ ] 交付物符合模板标准

## 4. 端到端测试模板

```
测试角色：<角色名>
测试场景：<场景描述>
输入：<用户自然语言输入>
预期输出：<期望的交付物>
实际输出：<实际结果>
通过/失败：<结果>
备注：<问题描述或改进建议>
```
