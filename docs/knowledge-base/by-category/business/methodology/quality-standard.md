# 质量标准与验证

> L3 业务知识库建设的质量门槛 —— 用可量化标准代替主观评价。

## 1. 六维质量模型

| 检查项 | 标准 | 验证方式 |
|--------|------|----------|
| 知识库完整性 | 每个维度 ≥ 10 篇知识文档 | `kb_index.py --stats` |
| 角色覆盖率 | ≥ 3 个角色，覆盖核心场景 | 角色清单审查 |
| 知识检索准确率 | 业务问题召回相关知识 ≥ 80% | `memory_search` 实测 |
| 角色可用性 | 角色加载后能正确执行任务 | 端到端测试 |
| 交付物质量 | 交付物符合模板标准 | 模板对照检查 |
| 维度独立性 | 新增维度不影响已有维度 | 回归测试 |

## 2. 自动校验（kb_index.py）

### 2.1 硬性阻断（必须为零）

| 错误类型 | 含义 |
|----------|------|
| 缺少 frontmatter | 文档无 YAML 元数据 |
| frontmatter 解析失败 | YAML 语法错误 |
| 缺 title | 无法索引与展示 |
| 非法 dimension | 不在 `VALID_DIMENSIONS` 白名单 |
| ID 重复 | 同一 id 出现 ≥ 2 次，破坏引用完整性 |

### 2.2 业务知识库软性警告（应消除）

| 警告 | 处理 |
|------|------|
| 缺 id | 补齐唯一 id（如 `METHODOLOGY-xxx`） |
| 缺 source | 业务知识必须标注权威来源 |
| tags < 3 | 至少 3 个标签，支持检索 |
| 缺 last_reviewed | 标注最后审查日期 |
| 相对链接失效 | 修复文档间交叉引用 |
| xref 指向不存在文件 | 校验 xref path 存在性 |

> 运营约定：**新增维度知识必须通过 `kb_index.py --validate` 无硬性错误**；软性警告目标清零。

## 3. 端到端验证流程

```
给定业务问题（自然语言）
  ↓
角色激活（SOUL/AGENTS/IDENTITY 加载）
  ↓
知识检索（memory_search / kb_index --query）
  ↓
角色执行任务
  ↓
交付物产出
  ↓
对照质量标准评审
```

### 3.1 角色端到端测试模板

```
测试角色：<角色名>
测试场景：<场景描述>
输入：<用户自然语言输入>
预期输出：<期望的交付物>
实际输出：<实际结果>
通过/失败：<结果>
备注：<问题描述或改进建议>
```

### 3.2 知识召回测试

- 从每个维度抽取 5 个代表性业务问题
- 用 `memory_search` 检索，检查能否召回正确知识文档
- 召回率 = 成功召回数 / 测试问题数，目标 ≥ 80%

## 4. 文档级质量标准

| 维度 | 检查项 | 标准 |
|------|--------|------|
| 完整性 | IDENTITY 4 必填字段 | ≤ 100 字 |
| 完整性 | SOUL "不做"清单 | ≥ 3 条 |
| 完整性 | AGENTS 交付物 + 决策分支 | ≥ 3 交付物 + ≥ 5 决策分支 |
| 一致性 | 术语统一 | 同一概念同一名称 |
| 一致性 | 格式统一 | 遵循模板 |
| 可用性 | 知识可检索 | 关键术语进 tags |
| 时效性 | last_reviewed 新近 | 季度审查机制 |

## 5. 评审流程

| 阶段 | 动作 | 责任人 |
|------|------|--------|
| 建设时 | 作者自检（对照本文件检查表） | 建设者 |
| 交付前 | `kb_index.py --validate` 全量跑 | 建设者 |
| 维度完成 | 端到端测试 + 召回率测试 | 建设者 + 主 agent |
| 季度审查 | last_reviewed 更新 + 知识时效核对 | 主 agent |

## 6. 常见失败模式与处置

| 失败模式 | 表现 | 处置 |
|----------|------|------|
| 质量自评虚高 | 自检勾全选但测试不过 | 以实测为准，不以自检为准 |
| 文档漂移 | 结构与模板不一致 | 对照模板逐项修复 |
| 断链蔓延 | 交叉引用失效 | 批量跑 `kb_index.py --validate` 定位 |
| 角色重叠 | 同维度角色职责不清 | 回到 [role-definition.md](./role-definition.md) 职责边界审查 |
