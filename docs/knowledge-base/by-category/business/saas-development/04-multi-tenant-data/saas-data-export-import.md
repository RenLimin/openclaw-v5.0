# 租户数据导入导出 SOP

## 适用场景

- SaaS 产品中的数据导入导出功能设计
- 客户数据迁移（迁入 / 迁出）
- 批量数据操作（批量新增、批量更新）
- 数据备份的自助恢复

---

## 核心原则

1. **数据主权** — 客户的数据是客户的，他们有权导走，不能绑架
2. **安全第一** — 导出功能是高风险操作，必须有权限控制和审计
3. **异步处理** — 大数据量导入导出必须异步，不能阻塞请求
4. **幂等设计** — 重复导入不会产生重复数据
5. **用户体验** — 导入要友好，错了要告诉用户哪里错了，不是只说"导入失败"

---

## 数据导出

### 导出功能矩阵

| 数据类型 | 导出格式 | 典型大小 | 权限要求 |
|---|---|---|---|
| 业务数据（如客户/订单） | Excel / CSV | 几 KB ~ 几十 MB | 管理员 |
| 报表数据 | Excel / PDF / CSV | 几 KB ~ 几 MB | 普通用户（自有数据） |
| 文件附件 | ZIP 压缩包 | 几十 MB ~ 几 GB | 管理员 |
| 全部数据备份 | JSON / SQL / ZIP | 几百 MB ~ 几十 GB | 超级管理员 |
| 审计日志 | CSV | 几 MB ~ 几百 MB | 管理员 + 审批 |

### 导出权限控制

**权限层级：**

| 角色 | 可导出范围 |
|---|---|
| 普通用户 | 自己创建的数据、自己有权限查看的数据 |
| 管理员 | 本租户所有业务数据 |
| 超级管理员 | 全部数据（含配置、日志等） |
| 运营（平台侧） | 不可导出租户数据（除非审批） |

**二次验证：**
- 导出全部数据 → 需要手机验证码 / 二次密码
- 导出包含敏感字段（如手机号、邮箱） → 需要管理员确认
- 大批量导出（> 10 万行） → 审批流程

### 导出流程

```
用户发起导出请求
    ↓
权限校验
    ↓
创建导出任务（异步）
    ↓
后台任务生成文件
    ↓
生成下载链接（有时效）
    ↓
通知用户（站内信 / 邮件）
    ↓
用户下载（有效期内）
    ↓
链接过期 / 文件清理
```

### 导出安全措施

1. **下载链接有效期** — 默认 24 小时，过期自动失效
2. **下载链接签名** — URL 带签名，防篡改和伪造
3. **文件加密存储** — 导出的文件存储时加密（敏感数据）
4. **审计日志** — 谁、什么时候、导出了什么数据、多少条
5. **频率限制** — 同一租户每天导出次数限制（防数据爬取）
6. **水印** — PDF 导出加水印（泄露了能追溯）
7. **敏感字段脱敏** — 非管理员导出时，敏感字段（手机号、身份证）打码

### 大数据量导出优化

- 分批查询，流式写入，不一次性加载到内存
- 导出大文件使用对象存储（S3 / OSS），不经过应用服务器
- 超大文件分片下载
- 预估导出时间，给用户进度条

## 数据导入

### 导入支持的格式

| 格式 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|
| **Excel (.xlsx)** | 友好，客户常用 | 解析复杂，大文件慢 | 业务数据导入 |
| **CSV** | 简单，性能好 | 编码问题、格式不统一 | 大数据量导入 |
| **JSON** | 结构化好，适合复杂数据 | 不友好，普通客户不会 | API 导入、系统间迁移 |
| **ZIP（多文件）** | 适合包含附件的导入 | 复杂 | 全量数据迁移 |

### 导入流程（五步走）

```
1. 上传文件 → 2. 字段映射 → 3. 预览校验 → 4. 确认导入 → 5. 查看结果
```

#### 第一步：上传文件

**校验项：**
- 文件格式是否支持
- 文件大小是否超限（如最大 50MB）
- 文件是否损坏 / 能否正常解析
- 病毒扫描（上传文件必须扫毒）

#### 第二步：字段映射

**自动匹配：**
- 根据列名自动匹配系统字段（中英文同义词匹配）
- 匹配率 > 80% 的字段自动选中
- 不确定的标黄，让用户手动确认

**手动映射：**
- 拖拽式映射，用户可以调整
- 必填字段必须映射，否则不能下一步
- 支持保存映射模板，下次直接用

#### 第三步：预览与校验

**必须做的检查：**
- 预览前 10 行数据，让用户确认
- 全量校验所有行的格式
- 列出所有错误：行号 + 错误原因
- 错误超过一定比例（如 20%），建议用户修正后重新上传

**校验内容：**
- 必填字段是否为空
- 字段格式是否正确（手机号、邮箱、日期、数字）
- 数据长度是否超限
- 枚举值是否合法
- 唯一性校验（会不会重复）
- 关联数据是否存在（如外键）

#### 第四步：确认导入

**导入方式：**
- 全部导入（有错误的跳过）
- 全部导入（有错误就整体回滚）
- 只导入正确的，错误的导出报告让用户改

**推荐：** 有错误的跳过 + 错误明细报告，用户体验最好

#### 第五步：导入结果

**结果页面展示：**
- 成功多少条
- 失败多少条
- 失败原因统计
- 下载错误明细（Excel，标注每行错误原因）

### 导入性能

| 数据量 | 目标时间 | 实现方式 |
|---|---|---|
| < 1000 行 | < 5 秒 | 同步处理 |
| 1000 ~ 10000 行 | < 1 分钟 | 异步任务 |
| 1 ~ 10 万行 | < 10 分钟 | 异步任务 + 分批 + 批量插入 |
| > 10 万行 | < 1 小时 | 专用导入工具（数据库原生导入） |

**优化手段：**
- 批量插入（batch insert）
- 事务控制（不要一条一个事务）
- 索引先禁用，导入完再重建（大数据量时）
- 使用数据库原生工具（如 COPY 命令，性能比 insert 高 10 倍以上）

## 模板管理

### 导入模板

**提供标准模板下载：**
- 标准字段（必填 + 选填）
- 示例数据
- 字段说明（注释 / 第二行说明）
- 数据格式要求

**模板生成：**
- 系统自动生成最新模板（字段变更时自动更新）
- 不要用静态 Excel 文件，容易过时

### 导出模板

- 导出格式和导入模板对齐（导出的文件可以直接再导入）
- 方便客户在导出的文件上修改后再导回来

## 安全与审计

### 导入安全

1. **文件病毒扫描** — 所有上传文件必须经过病毒扫描
2. **文件类型校验** — 不能只看扩展名，要检查文件头
3. **大小限制** — 防止超大文件 DDoS
4. **SQL 注入防护** — 导入数据严格参数化，不能拼接 SQL
5. **XSS 防护** — 导入的文本内容做过滤（富文本场景）

### 审计日志

**导出日志记录：**
- 操作人
- 时间
- 导出类型
- 数据范围 / 条件
- 导出数量
- 文件大小
- IP 地址

**导入日志记录：**
- 操作人
- 时间
- 文件名
- 文件大小
- 成功数量
- 失败数量
- 导入耗时
- IP 地址

**日志保留：** 至少 1 年

## 常见问题处理

### Q1：Excel 日期格式乱怎么办？

**A：**
- 统一导入模板的日期格式（如 yyyy-mm-dd）
- 解析时尝试多种常见格式
- 解析失败的明确提示格式要求

### Q2：大文件导入 OOM？

**A：**
- 用流式解析（如 EasyExcel / Excel Streaming Reader）
- 分批处理，一批 1000 条
- 异步任务处理，不占 Web 请求线程

### Q3：导入重复数据怎么办？

**A：**
- 定义唯一键（如编号、手机号）
- 支持"更新或插入"模式（UPSERT）
- 导入前检测重复，让用户选择跳过还是覆盖

### Q4：导出太慢用户等不及？

**A：**
- 异步导出，做好了通知用户
- 进度实时展示
- 小数据量同步导出（< 1000 行），大数据量异步

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 导入无校验就存库 | 脏数据进库，后面清理麻烦 | 导入前完整校验，错误的不让进 |
| 错误信息不友好 | "导入失败"三个字，用户不知道哪错了 | 逐行标注错误原因，下载错误明细 |
| 导出无审计 | 谁导了数据没人知道，泄露了追不到 | 所有导出操作详细审计日志 |
| 大文件同步处理 | 用户点了导出浏览器转半天，最后超时 | 异步任务 + 通知 + 进度 |
| 模板和实际不一致 | 模板是旧的，按模板填了导不进去 | 模板从系统动态生成，字段同步更新 |
| Excel 解析 OOM | 10MB 的 Excel 解析占 1GB 内存 | 用流式解析，不要一次性全读进内存 |
| 导出就是全库 dump | 导出功能变成了数据泄露通道 | 严格权限控制 + 二次验证 + 频率限制 |
