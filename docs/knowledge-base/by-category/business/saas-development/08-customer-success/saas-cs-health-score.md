# 客户健康分体系 SOP

## 适用场景

- SaaS 客户健康度的量化评估体系
- 客户成功团队的客户分层管理
- 流失风险的早期识别与干预
- 续约 / 增购机会的提前发现

---

## 核心原则

1. **数据驱动，不靠感觉** — 健康度是算出来的，不是 CSM 拍脑袋
2. **多维度综合评估** — 不只看使用量，要看产品、服务、关系多个维度
3. **动态实时** — 健康分随数据变化实时更新，不是季度评一次
4. **行动导向** — 每个健康等级对应明确的行动方案，不是为了打分而打分
5. **预测未来** — 健康分的意义是提前发现问题，不是事后诸葛亮

---

## 什么是客户健康分

客户健康分（Health Score）是用多个维度的数据综合计算的一个分数，用来衡量：
- 客户用得好不好
- 客户满不满意
- 客户会不会续约
- 客户会不会增购

**为什么需要健康分？**
- CSM 手里几十上百个客户，怎么知道该关注谁
- 提前发现流失风险，主动干预
- 发现增购机会，主动推进
- 统一标准，避免"我觉得这个客户挺健康"的主观判断

## 健康分维度设计

### 五维度模型

| 维度 | 权重 | 说明 |
|---|---|---|
| **产品使用** | 35% | 用了多少、用得多深 |
| **产品深度** | 25% | 用了多少功能、是不是核心功能 |
| **服务支持** | 15% | 工单响应、问题解决满意度 |
| **客户关系** | 15% | 互动频率、高层关系 |
| **商业健康** | 10% | 付费历史、合同状况 |

### 各维度详细指标

#### 1. 产品使用（35%）

| 指标 | 计算方式 | 满分 |
|---|---|---|
| 登录频率 | 过去 30 天活跃天数 / 30 | 10 分 |
| 使用深度 | 核心功能使用次数 / 基准值 | 10 分 |
| 活跃度趋势 | 本月使用量 / 上月使用量 | 10 分 |
| 用户覆盖 | 活跃用户数 / 总席位数 | 5 分 |

#### 2. 产品深度（25%）

| 指标 | 计算方式 | 满分 |
|---|---|---|
| 功能渗透率 | 已使用功能数 / 总可用功能数 | 8 分 |
| 核心功能使用 | 是否使用了 3 个以上核心功能 | 7 分 |
| 高级功能使用 | 是否使用了高级功能（如 API、集成） | 5 分 |
| 集成数量 | 接入的第三方集成数 | 5 分 |

#### 3. 服务支持（15%）

| 指标 | 计算方式 | 满分 |
|---|---|---|
| 工单量 | 过去 90 天工单数量（太多反而扣分） | 5 分 |
| 工单解决率 | 已解决工单 / 总工单 | 4 分 |
| 平均解决时间 | 越短越好 | 3 分 |
| 客户满意度 | 工单 CSAT 评分 | 3 分 |

#### 4. 客户关系（15%）

| 指标 | 计算方式 | 满分 |
|---|---|---|
| 互动频率 | 过去 90 天 CSM 互动次数 | 5 分 |
| 高层对接 | 是否有高层间的交流 | 4 分 |
| 培训参与 | 是否参加过培训 /  webinar | 3 分 |
| 社区活跃度 | 社区 / 用户群参与度 | 3 分 |

#### 5. 商业健康（10%）

| 指标 | 计算方式 | 满分 |
|---|---|---|
| 付费及时性 | 是否按时付款 / 有无逾期 | 4 分 |
| 合同状态 | 是否在合同期内 / 距离到期时间 | 3 分 |
| 增长趋势 | 席位是否在增加 | 3 分 |

### 总分计算

```
总分 = Σ（各维度得分 × 维度权重）
满分：100 分
```

**健康等级：**

| 分数 | 等级 | 颜色 | 说明 |
|---|---|---|---|
| 80-100 | 健康（Green） | 🟢 | 状态良好，续约概率高 |
| 60-79 | 一般（Yellow） | 🟡 | 需要关注，有流失风险 |
| 40-59 | 风险（Orange） | 🟠 | 高流失风险，需主动干预 |
| 0-39 | 危险（Red） | 🔴 | 极高流失风险，紧急处理 |

## 健康分应用场景

### 1. 客户分层管理

**CSM 客户分配策略：**
- 🟢 健康客户：每季度 touch 一次，重点是增购
- 🟡 一般客户：每月 check-in，防止下滑
- 🟠 风险客户：每两周跟进，制定挽救计划
- 🔴 危险客户：每周跟进，高层介入

**CSM 负载参考：**
- 健康客户：1 个 CSM 管 50-80 家
- 一般客户：1 个 CSM 管 30-50 家
- 风险客户：1 个 CSM 管 10-20 家

### 2. 流失风险预警

**自动触发预警的情况：**
- 健康分连续 2 周下降
- 从 🟢 掉到 🟡
- 从 🟡 掉到 🟠
- 某个关键指标骤降（如使用量下降 50%）

**预警后的动作：**
1. 自动给 CSM 发提醒
2. 生成客户风险报告
3. 推荐干预措施
4. 设定挽救目标和时间线

### 3. 增购机会识别

**增购信号：**
- 健康分持续上升（>85 分）
- 席位使用率 > 90%
- 高级功能使用率高
- 客户主动询问高级功能
- 团队规模在扩大

**识别后的动作：**
1. CSM 主动联系，了解需求
2. 介绍相关的高级功能 / 更高套餐
3. 安排产品演示
4. 推动增购转化

### 4. 续约管理

**续约风险评估：**
- 健康分 ≥ 80：低风险，正常续约流程
- 健康分 60-79：中风险，提前 90 天介入
- 健康分 < 60：高风险，提前 120 天启动挽救

**续约时间线：**
```
T-120 天：高风险客户启动挽救计划
T-90 天：中风险客户评估 + 行动计划
T-60 天：所有客户启动续约沟通
T-30 天：续约谈判
T-0：合同续签
```

## 健康分运营机制

### 数据更新频率

| 维度 | 更新频率 |
|---|---|
| 产品使用数据 | 每日更新 |
| 服务支持数据 | 实时 / 每日 |
| 客户关系数据 | 每次互动后更新 |
| 商业数据 | 每日更新 |
| 健康分总分 | 每日重新计算 |

### 定期 Review

**每周：** CSM 看自己客户的健康分变化，制定本周重点

**每月：**
- 客户成功团队健康分总览
- 各等级客户分布
- 健康分变化趋势
- 风险客户名单和跟进情况

**每季度：**
- 健康分模型校准
- 指标权重调整
- 回顾预测准确率（健康分低的是不是真的流失了）
- 模型迭代优化

---

## 模型校准与优化

### 准确率验证

**健康分准不准？看实际数据：**

- **预测准确率：** 健康分低的客户是不是真的流失率高
- **混淆矩阵：** 预测流失的有多少真的流失了，预测留存的有多少真的留了

**常见偏差和修正：**
- 高估了使用量的重要性 → 降低使用量权重，增加满意度权重
- 忽略了行业差异 → 分行业建立不同的基准值
- 新客户和老客户标准一样 → 按客户生命周期分阶段计算

### 持续迭代

健康分模型不是一成不变的：
- 每季度 review 一次
- 新功能上线后可能需要调整功能渗透率的计算
- 业务变化了指标也要跟着变
- 目标是"预测准"，不是"算得对"

---

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 唯使用量论 | 用得多就是健康，用得少就是不健康 | 多维度综合评估，使用量只是其中之一 |
| 静态评分 | 一季度评一次，中间不更新 | 实时数据驱动，每日重新计算 |
| 打分完了就完了 | 有健康分，但没人用它来指导行动 | 每个等级对应明确的 action plan |
| 模型太复杂 | 100 个指标，CSM 都不知道分数怎么来的 | 维度不超过 5 个，指标解释清楚 |
| 一套标准打天下 | 初创公司和大企业用同一套标准 | 分行业、分规模、分阶段调整基准 |
| CSM 人为干预 | CSM 觉得客户健康就手动改分 | 健康分自动计算，CSM 可以加备注但不能改分 |
| 不验证准确率 | 用了两年不知道准不准 | 定期验证预测准确率，迭代模型 |
