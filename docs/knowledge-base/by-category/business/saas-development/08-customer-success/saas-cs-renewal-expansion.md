# 续约管理与增购扩展 SOP

## 适用场景

- SaaS 客户的订阅续约管理
- 增购（Upsell）、交叉销售（Cross-sell）流程
- NRR（净收入留存率）提升策略
- 客户成功团队的收入指标管理

---

## 核心原则

1. **续约是从签约第一天开始的** — 不是快到期了才想起来续约，平时做好了续约是自然结果
2. **价值是前提** — 客户感受到价值，续约才顺理成章
3. **增购不是推销** — 是帮客户解决更多问题，创造更多价值
4. **提前布局** — 续约提前 90 天启动，增购机会提前识别
5. **NRR > 新签** — 存量客户的收入增长比新客户更重要、更便宜

---

## 续约管理

### 为什么续约这么重要

**SaaS 的本质是 recurring revenue（经常性收入）。**
- 新客获取成本（CAC）越来越高
- 存量客户的收入成本几乎为零
- 10% 的流失率意味着每年要找 10% 的新客户才持平
- NRR > 100% 的话，即使不新签也在增长

### 续约时间线（T = 到期日）

```
T-120 天：健康度评估，识别高风险客户
T-90 天：启动续约流程，所有客户续约检查
T-60 天：续约沟通，确认意向和需求
T-30 天：合同谈判，价格 / 条款
T-15 天：合同签署，付款
T-0：续约完成，进入新周期
```

### 续约前的准备

**客户分层策略：**

| 客户层级 | 启动时间 | 负责方 | 续约方式 |
|---|---|---|---|
| 战略客户 | T-120 天 | CSM 负责人 + 销售 VP | 定制化方案，高层对接 |
| 大客户 | T-90 天 | 资深 CSM | 定制方案 + 商务谈判 |
| 中客户 | T-60 天 | CSM | 标准续约流程 |
| 小客户 | T-30 天 | 系统自动 | 自动续费 + 邮件提醒 |
| 自助客户 | T-7 天 | 系统自动 | 自动续费 |

### 续约健康度评估

**续约前评估清单：**

| 维度 | 绿灯（好） | 黄灯（关注） | 红灯（危险） |
|---|---|---|---|
| 产品使用 | 健康分 > 80 | 健康分 60-80 | 健康分 < 60 |
| 业务价值 | 客户有明确的 ROI 数据 | 有价值但没量化 | 说不清有什么价值 |
| 客户关系 | 定期互动，关系好 | 一般互动 | 联系不上 |
| 服务支持 | 问题都解决了，满意 | 有一些小问题 | 有未解决的大问题 |
| 竞品动态 | 没提过竞品 | 问过竞品对比 | 在试用竞品 |
| 客户状况 | 公司在增长 | 稳定 | 在裁员 / 收缩 |

**结果分级：**
- 🟢 低风险：正常续约流程即可
- 🟡 中风险：提前介入，针对性解决问题
- 🔴 高风险：启动挽留流程（见流失预警 SOP）

### 续约沟通

**沟通话术原则：**
- 不说"要不要续约"，说"回顾一下过去这段时间的成果，聊聊接下来怎么更好地合作"
- 用数据说话 — 展示客户用产品获得了什么价值
- 谈未来 — 下一期的规划和目标，不只是续个费

**QBR（季度业务回顾）是最好的续约铺垫：**
- 每季度做一次业务回顾
- 展示成果和价值
- 讨论问题和改进
- 规划下阶段目标
- 续约自然水到渠成

### 续约谈判

**常见异议处理：**

| 异议 | 回应策略 |
|---|---|
| "太贵了" | 先谈价值，再谈价格。展示 ROI，用数据证明值这个价 |
| "用得不多" | 承认问题，提出改进方案。重新 onboarding + 培训 |
| "功能不够" | 了解具体缺什么。能做的给 roadmap，不能做的找替代 |
| "想试试竞品" | 不贬低竞品，强调我们的差异化和客户已经投入的成本 |
| "预算砍了" | 讨论降级方案，而不是直接流失。先留住，以后再升级 |

## 增购扩展（Expansion）

### 什么是 Expansion

**存量客户的收入增长，包括：**
- **Upsell（增购）** — 买更多席位 / 升级到更高套餐
- **Cross-sell（交叉销售）** — 买其他产品 / 模块
- **Add-on（附加功能）** — 购买额外的功能或服务

### 为什么 Expansion 重要

- NRR（净收入留存率）= 100% + Expansion 率 - Churn 率
- NRR > 100% 是优秀 SaaS 的标志
- 存量客户的销售成本远低于新客户
- 投资人非常看重 NRR 这个指标

### 增购机会识别

**信号：**

| 信号 | 对应的增购方向 |
|---|---|
| 席位使用率 > 90% | 增加席位 |
| 功能使用率高，达到套餐上限 | 升级套餐 |
| 频繁询问高级功能 | 升级到高级版 |
| API / 集成用得多 | 高级版 / 企业版 |
| 团队在扩大，新人不断加入 | 增加席位 + 企业版功能 |
| 主动问其他模块 | Cross-sell 其他产品 |
| 项目成功了，其他部门也想用 | 扩大到全公司 |
| 健康分持续 > 90 | 什么都有可能！ |

### 增购时机

**最佳时机：**
- QBR 时（回顾成果，自然提到下一步）
- 客户主动说遇到新问题时
- 客户团队扩大时
- 产品发布新功能时
- 续约谈判时（续约 + 增购一起谈）

**糟糕时机：**
- 客户刚遇到一个大问题时
- 客户在抱怨服务不好时
- 刚出了故障时
- 客户公司正在裁员时

### 增购流程

**CSM 主导的增购：**

```
1. 识别机会（数据信号 + 客户反馈）
   ↓
2. 确认需求（深入了解客户的问题和目标）
   ↓
3. 方案推荐（推荐合适的升级 / 增购方案）
   ↓
4. 价值展示（ROI 计算、案例分享）
   ↓
5. 试用 / POC（如果需要）
   ↓
6. 商务谈判
   ↓
7. 成交 + Onboarding 新功能
   ↓
8. 持续跟进新功能的使用
```

### 增购话术原则

- **从问题出发，不是从产品出发** — "你们在 XX 方面的痛点..." 不是 "我们有个新功能..."
- **讲 ROI，不讲功能列表** — "用了之后可以节省 XX 小时" 不是 "有 A/B/C 三个功能"
- **让客户自己说服自己** — 多问问题，让客户自己说出需求
- **不是推销，是帮忙** — 真心觉得这个对客户有帮助才推荐，为了完成指标硬推会伤关系

## NRR 提升策略

### NRR 计算

```
NRR = (期初 MRR + 增购 MRR - 流失 MRR - 降级 MRR) / 期初 MRR × 100%
```

**NRR 基准：**
- < 80%：危险，存量在萎缩
- 80-90%：一般，及格线
- 90-100%：不错，健康
- 100-110%：优秀，负流失
- > 120%：顶级 SaaS，超级扩张

### 提升 NRR 的三个杠杆

| 杠杆 | 方向 | 影响 |
|---|---|---|
| **降低流失** | 减少 Churn | 减少分母流失 |
| **提升增购** | 增加 Expansion | 增加分子增购 |
| **减少降级** | 减少 Downgrade | 减少分子扣减 |

**优先级：** 先降流失，再做增购，最后控降级。

## 指标与考核

### 客户成功团队的收入指标

| 指标 | 说明 | 目标参考 |
|---|---|---|
| **续约率（Logo Retention）** | 续约客户数 / 到期客户数 | > 90% |
| **金额续约率（Dollar Retention）** | 续约金额 / 到期金额 | > 95% |
| **NRR** | 净收入留存率 | > 100% |
| **增购率** | 增购收入 / 期初 MRR | 10-30% |
| **客户平均收入（ARPU）** | 平均每个客户的收入 | 持续提升 |
| **挽留成功率** | 成功挽留的高风险客户比例 | > 30% |

### CSM 的角色定位

**CSM 应不应该背销售指标？**

两种模式：

| 模式 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| **纯服务型 CSM** | CSM 只管客户成功，不管销售。增购转交给销售 | CSM 和客户关系纯粹 | 机会识别和转化衔接不好 |
| **CSM 带收入指标** | CSM 自己负责续约和增购 | 动力强，衔接顺 | 可能为了卖而伤害客户关系 |

**推荐：** CSM 带续约率 + NRR 指标，但增购以"客户成功"为前提，不是硬推销。

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 临时抱佛脚 | 快到期了才想起来续约，平时不管 | 续约从签约第一天开始，日常做好价值交付 |
| 把续约当销售 | CSM 像销售一样硬推，客户反感 | 价值导向，客户感受到了自然会续 |
| 增购太激进 | 客户刚进来就卖这卖那，吓跑了 | 先让客户用出价值，再谈更多 |
| 只看数量不看质量 | 续约率很高但都是打折续的 | 看金额续约率，不只看 logo 数 |
| 小客户不管 | 小客户自动续费，从来不联系 | 自动化运营也要做，小客户也能变大 |
| 续约就是降价 | 一说要走就降价，没有底线 | 先解决问题，价格是最后手段 |
| QBR 走过场 | 季度回顾变成走流程汇报，没实质内容 | QBR 要有价值，客户觉得有用才愿意开 |
