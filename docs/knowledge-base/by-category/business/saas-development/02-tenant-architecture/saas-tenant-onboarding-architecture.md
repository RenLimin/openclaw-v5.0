# 租户自动化开通与初始化架构 SOP

## 适用场景

- SaaS 产品新租户的自动化开通流程设计
- 租户初始化数据配置与资源分配
- PLG 模式下的自助注册与即时可用
- 企业版客户的定制化开通流程

---

## 核心原则

1. **Self-service first** — 能让用户自己搞定的，就不要人工介入
2. **Time-to-value 最小化** — 从注册到感受到价值的时间越短越好
3. **幂等设计** — 开通流程可以重复执行，不会产生脏数据
4. **可观测可回滚** — 每一步都有日志，失败了能自动回滚
5. **异步化** — 耗时长的初始化步骤异步执行，不让用户等

---

## 开通流程分层设计

### 即时层（< 1 秒，用户等待）

用户注册后立刻能看到的，必须同步完成：

| 步骤 | 说明 | 耗时目标 |
|---|---|---|
| 创建租户账号 | 数据库写入租户记录 | < 50ms |
| 创建管理员用户 | 创建第一个用户账号 | < 50ms |
| 分配默认配置 | 套餐、功能开关、默认设置 | < 50ms |
| 生成登录 Token | 用户直接登录 | < 20ms |
| 跳转到引导页 | 用户开始使用 | — |

**原则：** 同步流程只做最少的事，其他都异步。

### 近即时层（< 30 秒，后台处理）

用户开始使用前需要就绪，但可以晚几秒：

| 步骤 | 说明 | 耗时目标 |
|---|---|---|
| 初始化默认数据 | 示例项目、模板、默认角色 | < 5s |
| 创建系统资源 | 文件存储目录、缓存命名空间 | < 3s |
| 配置监控告警 | 注册租户指标、告警规则 | < 2s |
| 发送欢迎邮件 | 包含登录信息、使用指引 | < 5s |
| 创建 CRM 记录 | 同步到销售/客户成功系统 | < 3s |

### 后台层（< 5 分钟，不阻塞使用）

可以在用户使用过程中逐步就绪：

| 步骤 | 说明 | 耗时目标 |
|---|---|---|
| 预生成报表数据 | 空报表模板初始化 | < 1min |
| 配置备份策略 | 加入备份计划 | < 1min |
| 安全审计配置 | 日志收集、异常检测 | < 2min |
| 示例数据生成 | 帮助用户快速上手的演示数据 | < 3min |

### 企业版定制层（人工介入）

企业版客户可能需要的定制步骤：

| 步骤 | 说明 | 负责方 |
|---|---|---|
| 专属实例部署 | Silo 模式下创建独立环境 | 运维自动化 |
| 域名配置 | 自定义域名 + SSL 证书 | 自动化 + DNS 配置 |
| SSO 配置 | SAML / OIDC 企业身份对接 | 客户成功 + 客户 IT |
| 数据迁移 | 从旧系统导入历史数据 | 实施团队 |
| 定制开发部署 | 专属功能部署 | 研发团队 |
| 专属客户成功 | CSM 对接、培训 | 客户成功 |

## 技术架构

### 开通流程状态机

```
CREATED → CONFIGURING → PROVISIONING → INITIALIZING → READY
   ↓          ↓             ↓              ↓
 FAILED     FAILED        FAILED         FAILED
   ↓          ↓             ↓              ↓
 ROLLBACK → ROLLED_BACK → RETRY / CANCEL
```

**每个状态的含义：**

| 状态 | 说明 | 可操作 |
|---|---|---|
| CREATED | 租户记录已创建，尚未开始配置 | 开始配置 / 取消 |
| CONFIGURING | 正在应用配置（套餐、功能开关等） | 等待 / 取消 |
| PROVISIONING | 正在分配资源（数据库、缓存、存储等） | 等待 |
| INITIALIZING | 正在初始化数据（默认配置、示例数据） | 等待 |
| READY | 开通完成，可以正常使用 | 正常使用 |
| FAILED | 某一步失败 | 重试 / 回滚 / 人工介入 |
| ROLLED_BACK | 已回滚，资源已清理 | 重新开通 |

### 核心组件

```
                    ┌──────────────────────┐
                    │   Tenant Provision   │
                    │      Service         │
                    └──────────┬───────────┘
                               │
          ┌────────────────────┼────────────────────┐
          ▼                    ▼                    ▼
   ┌─────────────┐      ┌─────────────┐      ┌─────────────┐
   │  Resource   │      │    Data     │      │  External   │
   │  Manager    │      │ Initializer │      │  Integrator │
   └──────┬──────┘      └──────┬──────┘      └──────┬──────┘
          │                    │                    │
    ┌─────┴─────┐         ┌────┴────┐         ┌────┴────┐
    │  DB /     │         │ 默认配置  │         │ CRM /   │
    │  Cache /  │         │ 示例数据  │         │ 邮件 /  │
    │  Storage  │         │  种子数据 │         │  监控   │
    └───────────┘         └──────────┘         └──────────┘
```

**组件职责：**

| 组件 | 职责 |
|---|---|
| **Tenant Provision Service** | 编排整个开通流程，状态机管理，失败重试 |
| **Resource Manager** | 基础设施资源分配（数据库 schema、缓存命名空间、存储桶） |
| **Data Initializer** | 业务数据初始化（默认配置、角色、模板、示例） |
| **External Integrator** | 外部系统集成（CRM、邮件、监控、计费） |

## 数据初始化策略

### 初始化数据分类

| 分类 | 说明 | 示例 | 来源 |
|---|---|---|---|
| **系统必需** | 没有就跑不起来的数据 | 管理员角色、默认设置项 | 代码中写死 / 迁移脚本 |
| **业务模板** | 提高效率的预置数据 | 项目模板、报表模板、工作流 | 模板库 / 配置文件 |
| **示例数据** | 帮助用户上手的演示数据 | 示例项目、示例客户、示例报表 | 数据生成脚本 |
| **定制数据** | 企业客户的特定数据 | 客户 Logo、组织架构、历史数据 | 实施团队 / 导入工具 |

### 初始化执行顺序

```
1. 系统配置 → 2. 权限体系 → 3. 业务模板 → 4. 示例数据 → 5. 定制数据
```

每一步都是幂等的 — 重复执行不会重复创建。

### 数据版本管理

- 初始化脚本有版本号，随代码版本迭代
- 新租户永远用最新版本的初始化数据
- 老租户通过数据迁移脚本逐步升级
- 版本不兼容时，提供迁移向导

## 失败处理与回滚

### 失败分级

| 失败级别 | 场景 | 处理策略 |
|---|---|---|
| **轻微失败** | 非关键步骤失败（如欢迎邮件发送失败） | 记录日志，继续流程，后台异步重试 |
| **重要失败** | 关键但可补的步骤失败（如 CRM 同步失败） | 标记为部分就绪，主流程可用，后台重试 + 告警 |
| **严重失败** | 核心步骤失败（如数据库创建失败） | 立即停止，启动回滚，通知运维 |

### 回滚策略

**每一步都要有对应的 undo 操作：**

| 步骤 | 正向操作 | 回滚操作 |
|---|---|---|
| 创建租户记录 | INSERT tenant | DELETE tenant（软删除） |
| 创建数据库 schema | CREATE SCHEMA | DROP SCHEMA |
| 初始化数据 | INSERT 数据 | DELETE 租户相关数据 |
| 创建存储桶 | Create bucket | Delete bucket |
| 发送欢迎邮件 | Send email | 无法撤回，记录日志 |
| CRM 同步 | Create account | Delete / deactivate |

**回滚保证：**
- 回滚本身也可能失败，所以要有重试机制
- 回滚失败生成人工工单，运维介入
- 所有回滚操作有详细日志

## 开通时间目标

### PLG 自助开通

| 指标 | 目标值 | 衡量方式 |
|---|---|---|
| **注册到可用** | < 3 秒 | 从提交注册到进入产品首页 |
| **核心功能就绪** | < 30 秒 | 所有主要功能可以正常使用 |
| **完整就绪** | < 5 分钟 | 所有后台初始化完成 |
| **开通成功率** | > 99.9% | 成功开通 / 总注册数 |
| **首次 Aha Moment** | < 5 分钟 | 从注册到完成第一个有价值的操作 |

### 企业版开通

| 套餐 | 目标开通时间 | 人工介入 |
|---|---|---|
| 自助企业版 | < 1 小时 | 无（全自动化） |
| 标准版企业 | 1-3 个工作日 | 客户成功对接 + SSO 配置 |
| 定制版企业 | 1-4 周 | 数据迁移 + 定制开发 + 培训 |

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 同步做太多事 | 注册要等 10 秒，用户都走了 | 异步化，只做最少的同步步骤 |
| 没有幂等 | 重试一下数据就重复了 | 所有操作幂等设计，用唯一键防重 |
| 失败了没人知道 | 开通失败的租户静静地躺在那里 | 失败告警 + 失败率监控 |
| 回滚不干净 | 回滚后残留资源，慢慢积累成垃圾 | 回滚检查清单 + 定期巡检孤儿资源 |
| 初始化数据过时 | 新用户看到的示例数据是两年前的 | 初始化数据纳入版本管理，定期更新 |
| 企业版开通靠手工 | 每次开通企业客户都要运维手动操作 | 优先做自动化，实在不行也要有脚本 |
