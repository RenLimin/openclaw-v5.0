# 定价与套餐设计 SOP

## 适用场景

- SaaS 产品的定价模型选择与套餐设计
- 新功能定价与现有套餐调整
- 定价的测试、验证与迭代
- 免费版 / 试用版策略设计

---

## 核心原则

1. **定价是产品问题，不是财务问题** — 好的定价本身就是增长引擎
2. **价值定价，不是成本定价** — 价格基于客户获得的价值，不是你的开发成本
3. **简单易懂** — 客户 30 秒内能看懂怎么收费，不要复杂的计算器
4. **可升级可降级** — 客户能顺滑地升上去，也能降下来（不至于流失）
5. **持续迭代** — 定价不是一锤子买卖，要不断测试和优化

---

## 定价模型选择

### 常见定价模型

| 模型 | 说明 | 优点 | 缺点 | 适合产品 |
|---|---|---|---|---|
| **Flat Rate（固定费率）** | 固定价格，不限量 | 简单易懂 | 大客户觉得亏，小客户觉得贵 | 简单工具型产品 |
| **Per Seat（按席位）** | 每个用户多少钱 | 简单，收入随客户规模增长 | 用户数和价值不一定成正比 | CRM、协作工具 |
| **Usage-based（按用量）** | 用多少付多少 | 公平，从小客户到大客户都合适 | 收入不可预测，客户怕超支 | API服务、云服务 |
| **Tiered（阶梯）** | 用量越多单价越低 | 鼓励多用 | 计算复杂 | 短信、邮件、存储 |
| **Freemium（免费增值）** | 免费版 + 付费版 | 获客成本低，病毒传播 | 转化率低，免费用户成本 | PLG 产品 |
| **Feature-based（按功能）** | 不同套餐功能不同 | 客户按需选择 | 功能划分难，客户选错 | 大多数 SaaS |
| **Per Active User** | 按活跃用户收费 | 公平，不用不花钱 | 收入波动大 | 低频使用产品 |
| **Hybrid（混合）** | 基础费 + 用量 + 席位 | 收入稳定又能扩展 | 复杂 | 中大型 SaaS |

### 怎么选

**三个问题帮你选：**

1. **你的价值单位是什么？**
   - 每个人都要用 → 按席位
   - 调用越多越值 → 按用量
   - 功能越多越值 → 按功能套餐

2. **你的客户能接受什么样的计费方式？**
   - 企业客户喜欢固定预算 → Flat Rate / 席位
   - 开发者喜欢按用量 → Usage-based

3. **你的成本结构是什么？**
   - 边际成本高（如存储、计算）→ 按用量
   - 边际成本低 → 按席位 / 套餐

**大多数 B2B SaaS 的选择：**
> Feature-based Tiered Pricing + Per Seat
> （三档套餐：基础 / 专业 / 企业，每档按席位计费）

## 套餐设计

### 经典三档套餐

| 套餐 | 定位 | 目标客户 |
|---|---|---|
| **基础版（Starter / Basic）** | 入门级，满足基本需求 | 个人 / 小团队 / 尝鲜 |
| **专业版（Pro / Professional）** | 主力档，性价比最高 | 成长型团队 / 中小企业 |
| **企业版（Enterprise）** | 高级功能 + 服务 | 大型企业 / 大客户 |

**为什么是三档？**
- 太多了客户选择困难
- 太少了没得选
- 三档是黄金比例，有锚定效应

### 功能打包原则

**Good-Better-Best 策略：**

| 档位 | 功能策略 |
|---|---|
| **基础版（Good）** | 核心功能，够用但有限制，让用户感受到价值但不够 |
| **专业版（Better）** | 大部分功能，性价比最高，主推的一档 |
| **企业版（Best）** | 全部功能 + 高级服务 + 定制化 |

**功能划分维度：**

| 维度 | 基础版 | 专业版 | 企业版 |
|---|---|---|---|
| 核心功能 | ✅ 基础功能 | ✅ 全部功能 | ✅ 全部功能 |
| 高级功能 | ❌ | ✅ 大部分 | ✅ 全部 |
| 使用量限制 | 有上限 | 较高上限 | 无上限 / 定制 |
| 团队规模 | 最多 5 人 | 最多 100 人 | 不限 |
| 支持 | 社区 / 邮件 | 优先邮件 + 在线聊天 | 专属 CSM + 电话 |
| SLA | 无 | 99.9% | 99.99% + 定制 |
| 安全合规 | 基础 | 标准 | SOC 2 / SSO / SCIM |
| 集成 | 基础集成 | 全部集成 | 定制集成 |

### 锚定效应

**怎么让客户选你想让他选的档（专业版）：**

1. **价格锚定** — 企业版很贵，显得专业版很划算
2. **功能对比表** — 清清楚楚展示每档有什么
3. **标记推荐** — "最受欢迎" / "性价比最高" 标签
4. **默认选中** — 价格页默认选中专业版

### 功能划分的常见错误

❌ **功能拆得太细** — 客户不知道选哪个，每个都差点意思
✅ **每档有明确的升级理由** — 升到下一档有明确的价值增量

❌ **免费版功能太少** — 免费版啥都干不了，用户体验不到价值
✅ **免费版能独立创造价值** — 即使不付费也能用得起来

❌ **企业版只是"更多席位"** — 大客户为什么要付更多钱？
✅ **企业版有不可替代的价值** — SSO、SCIM、专属支持、SLA、合规

## 免费版与试用

### Freemium vs Free Trial

| 模式 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| **免费增值（Freemium）** | 永久免费版，功能/用量有限 | 获客成本低，病毒式增长 | 转化率低（2-5%），免费用户有成本 |
| **免费试用（Free Trial）** | 限时全功能试用，到期付费 | 转化率高（10-25%） | 获客成本高，过期流失 |
| **混用** | 免费版 + 付费版试用 | 兼顾获客和转化 | 设计复杂 |

**选择建议：**
- PLG 产品、工具型 → Freemium
- 高客单价、企业级 → Free Trial（14-30 天）
- 有条件都做 → 免费版 + 付费功能试用

### Freemium 设计要点

**免费版的目的：** 获客 + 让用户体验到价值 + 创造升级动力

**免费与付费的分界线（Paywall）怎么画？**

| 策略 | 说明 | 适用 |
|---|---|---|
| **用量限制** | 免费版有上限，超过要付费 | 用量型产品（存储、API调用） |
| **功能限制** | 高级功能付费 | 功能型产品 |
| **用户数限制** | 免费版最多 N 人 | 协作型产品 |
| **支持限制** | 付费才有更好的支持 | 企业服务 |
| **品牌限制** | 免费版有水印 / 品牌标识 | 内容生成型 |

**最佳实践：**
- 免费版能独立创造价值（不是 demo）
- 升级的"痛点"要明确（不要不痛不痒）
- 免费到付费的转化路径要顺滑

### Free Trial 设计要点

**试用期长度：**
- 简单产品：7-14 天
- 复杂产品：14-30 天
- 企业级：30 天 + POC

**试用期优化：**
- 试用期内重点推 Onboarding，让用户尽快感受到价值
- 试用期结束前提醒（提前 7 天、3 天、1 天）
- 试用期结束后数据保留一段时间（给个缓冲）

## 价格设定

### 价值定价法

**不是成本 + 利润 = 价格**
**而是客户获得的价值 × 合理比例 = 价格**

**怎么找价值锚点：**
1. 客户用了你的产品，能省多少钱 / 赚多少钱 / 省多少时间
2. 把时间和效率换算成钱
3. 定价是价值的 10-30%（客户拿大头，你拿小头）

**举例：**
- 你的产品帮客户每人每天省 1 小时
- 客户时薪 ¥100
- 每月省 22 小时 × ¥100 = ¥2200 / 人 / 月
- 定价 ¥299 / 人 / 月（价值的约 13%）
- 客户觉得值，你也有得赚

### 竞品定价参考

- 主要竞品的价格是多少
- 你的功能比竞品多还是少
- 你的品牌比竞品强还是弱
- 定价在竞品的什么位置（高 / 平 / 低）

**注意：** 不要陷入比谁更便宜的竞赛。差异化价值才是关键。

### 价格测试

**A/B 测试：**
- 不同用户看到不同的价格
- 看哪个价格的转化率 × ARPU 最高

**要测试的：**
- 价格高低
- 套餐划分
- 月付 vs 年付折扣
- 展示方式（年付显示月均价 vs 月付价格）

**注意：**
- 定价测试要小心，别让客户发现价格不一样
- B2B 产品定价测试要谨慎，容易引起不满
- 小范围测试，收集数据后再决定

## 定价迭代

### 什么时候该调整定价

**信号：**
- 转化率太低，很多人看了价格就走
- 很多客户说贵
- NRR 低，客户总是降级
- 大客户老是要求定制报价
- 功能加了很多，但价格没涨
- 竞争对手调整了定价

### 涨价策略

**直接涨价的难题：** 老客户会不满，甚至流失

**更好的方式：**
1. **新功能打包升档** — 加新功能，推出更高价位的套餐
2. **版本升级涨价** — 新版本新价格，老版本保持原价但逐步淘汰
3. **用量涨价** — 基础价不变，超用量部分涨价
4. **新客户新价格，老客户原价保护** —  grandfathering（祖父条款）

**涨价沟通：**
- 提前通知（至少 30 天）
- 说明原因（更多功能、更好服务）
- 给老客户优惠（如锁定原价一年）
- 提供降级选项

## 定价页设计

### 定价页要素

- [ ] 三档套餐清晰对比
- [ ] 每档价格 + 计费周期（月/年）
- [ ] 功能对比表
- [ ] "最受欢迎" 标记
- [ ] 月付 / 年付切换（年付显示折扣）
- [ ] 免费试用 / 免费版入口
- [ ] FAQ（常见问题）
- [ ] "联系我们"（企业版）

### 功能对比表

- 按类别组织功能（不是一长串）
- ✅ / ❌ / 数字限制 清晰标识
- 悬停提示（功能名旁边有 i 图标，解释是什么）
- 鼠标悬停高亮对应列

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 成本定价 | 算一下成本加个百分比就是价格 | 价值定价，看客户愿意为价值付多少 |
| 太便宜 | 为了抢市场定低价，结果收入撑不起团队 | 不要怕涨价，先验证价值再定价 |
| 太复杂 | 10 个维度计费，客户要拿计算器算 | 简单！客户 30 秒看不懂就走了 |
| 免费版啥都干不了 | 免费版限制太死，体验不到价值 | 免费版要能独立使用，创造升级动力 |
| 功能划分混乱 | 这个功能在基础版，那个差不多的在专业版 | 每档有明确的定位和升级理由 |
| 一定终身 | 定了价就不敢改 | 定价要持续迭代，定期 review |
| 只看转化率 | 降价了转化率上去了，总收入反而降了 | 看转化率 × ARPU，看总收入 |
| 企业版不"企业" | 企业版就是席位多点，没别的 | 企业版要有不可替代的价值（SSO/安全/服务/SLA） |
