# 发票管理与税务计算 SOP

## 适用场景

- SaaS 产品的发票开具、管理、寄送
- 多地区 / 多币种 / 多税率的税务计算
- 增值税（VAT / GST）、销售税处理
- 税务合规与审计

---

## 核心原则

1. **合规第一** — 税务不能出错，错了就是罚
2. **自动化优先** — 发票和税务是规则驱动的，能自动就不要人工
3. **可追溯可审计** — 每一张发票、每一笔税金都能追溯
4. **地区差异隔离** — 不同国家/地区的税务规则独立维护
5. **提前规划** — 进入新市场前先搞清楚税务要求，不要后补

---

## 发票管理

### 发票类型

| 类型 | 说明 | 适用场景 |
|---|---|---|
| **增值税普通发票** | 不能抵扣进项税 | 个人客户、小规模纳税人 |
| **增值税专用发票** | 可以抵扣进项税 | 一般纳税人企业客户 |
| **形式发票（Proforma）** | 非正式发票，用于付款前确认 | 国际客户、预付款 |
| **红字发票** | 负数发票，用于冲销 | 退款、发票作废 |
| **Credit Note** | 贷记通知单 | 部分退款、折扣调整 |

### 发票内容要求（中国增值税）

**必填项：**
- 发票抬头（购买方名称）
- 纳税人识别号（企业必填）
- 地址、电话（专票必填）
- 开户行及账号（专票必填）
- 商品或服务名称（按税务编码）
- 规格型号、单位、数量、单价
- 金额（不含税）、税率、税额
- 价税合计
- 销售方信息
- 发票号码、代码
- 开票日期

### 发票生命周期

```
待开票 → 开票中 → 已开票 → 已发送 → 已入账
              ↓
            开票失败 → 重试 / 人工处理

已开票 → 申请作废 → 作废中 → 已作废
        （当月可作废，跨月需红冲）
```

### 自动开票规则

**触发开票的时机：**
- 支付成功后自动开票（推荐）
- 订阅续费成功后自动开票
- 客户主动申请开票

**开票方式：**
- 电子发票（推荐，成本低、速度快）
- 纸质发票（客户要求时开具，需邮寄）

**电子发票交付：**
- 发送到客户邮箱（PDF 附件）
- 产品内可下载
- 支持微信 / 支付宝发票夹推送（国内）

## 税务计算

### 中国增值税

| 纳税人类型 | 税率 | 说明 |
|---|---|---|
| **一般纳税人** | 6%（软件服务） | 可抵扣进项税 |
| **小规模纳税人** | 3%（征收率） | 不可抵扣，有减免政策 |

**SaaS 属于"信息技术服务"，一般纳税人税率 6%。**

**不含税金额计算公式：**
```
不含税金额 = 含税金额 / (1 + 税率)
税额 = 不含税金额 × 税率
```

**示例：** 客户支付 ¥299（含税），税率 6%
```
不含税金额 = 299 / 1.06 = ¥282.08
税额 = 282.08 × 6% = ¥16.92
价税合计 = ¥299.00
```

### 国际税务

#### 欧盟 VAT

- 欧盟内销售数字服务，需在客户所在国缴纳 VAT
- 反向征收机制（Reverse Charge）：B2B 销售由客户自行申报
- B2C：按客户所在国税率
- MOSS（Mini One Stop Shop）：一站式申报机制
- 税率范围：17%（卢森堡）~ 27%（匈牙利）

#### 美国销售税（Sales Tax）

- 各州税率不同，部分州无销售税
- SaaS 是否征税各州规定不一
- 经济联结（Economic Nexus）：达到一定销售额/交易数需征税
- 常见税率：5% ~ 10%

#### 其他主要地区

| 地区 | 税种 | 典型税率 |
|---|---|---|
| 英国 | VAT | 20% |
| 澳大利亚 | GST | 10% |
| 新加坡 | GST | 9% |
| 日本 | 消费税 | 10% |
| 韩国 | VAT | 10% |

### 税务计算流程

```
确定客户所在地 → 确定客户类型（B2B/B2C）→ 确定适用税种和税率
        ↓
  校验税号（VAT/GST 号）→ 计算税金 → 生成税务明细
```

**关键步骤：**

**1. 确定税务管辖地**
- B2C：客户所在地（根据 IP、账单地址、支付信息判断）
- B2B：客户注册地（根据税号归属地）

**2. 税号校验**
- 欧盟 VAT 号：通过 VIES 系统校验
- 中国纳税人识别号：格式校验 + 税局系统查询
- 其他地区：格式校验 + 第三方服务

**3. 税金计算**
- 含税价倒推税额（定价是含税的情况）
- 不含税价正向计算税额（定价是不含税的情况）
- 多税率商品：分行计算

## 税务合规要点

### 登记义务

| 触发条件 | 需要做什么 |
|---|---|
| 在某国销售额超过阈值 | 注册当地税号，定期申报 |
| 有实体办公室 / 员工 | 注册税号 + 合规申报 |
| 当地法律要求 | 按当地法规执行 |

**常见阈值：**
- 欧盟：€10,000/年（跨欧盟总销售额）
- 英国：£85,000/年
- 美国各州：$100,000/年 或 200 笔交易

### 申报与缴纳

| 地区 | 申报频率 | 截止日期 |
|---|---|---|
| 中国（一般纳税人） | 月度 | 次月 15 日 |
| 中国（小规模） | 季度 | 次季度 15 日 |
| 欧盟 MOSS | 季度 | 季度结束后 20 天 |
| 英国 | 季度 | 季度结束后 1 个月零 7 天 |
| 美国各州 | 月度/季度/年度 | 各州不同 |

### 记录保存

- 发票记录：至少 10 年
- 税务申报记录：至少 10 年
- 客户税号验证记录：至少 5 年
- 销售记录（按地区）：至少 10 年

## 多币种与汇率

### 定价币种 vs 开票币种

- 定价币种：产品展示的价格币种
- 开票币种：发票上的币种（需与支付币种一致）
- 记账币种：公司财务记账的币种（如人民币）

### 汇率处理

**外币交易折算：**
- 按交易发生日的汇率折算
- 或按当月 1 号汇率（需保持一致）
- 汇率来源：中国人民银行 / 国家外管局 / ECB

**汇兑损益：**
- 支付时汇率与开票时汇率的差异
- 计入财务费用 — 汇兑损益

## 技术实现建议

### 第三方税务服务

| 服务 | 覆盖地区 | 特点 |
|---|---|---|
| **Stripe Tax** | 全球 | 集成简单，自动计算 |
| **Avalara** | 全球 | 功能强大，企业级 |
| **TaxJar** | 美国为主 | 美国销售税专业 |
| **Vertex** | 全球 | 大型企业方案 |

**建议：**
- 国际业务 → 用 Avalara 或 Stripe Tax
- 纯国内 → 用国内开票系统（金税盘、税务 UKey）+ 税务规则自研
- 混合 → 国内 + 国际两套方案

### 国内电子发票对接

**对接方式：**
- 直接对接税局系统（百望 / 航信 / 税务 UK）
- 通过第三方开票平台（如票易通、每刻）

**选型考虑：**
- 开票量大小
- 是否需要专票（专票更复杂）
- 是否需要红冲、作废
- 接口稳定性
- 成本

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 税率搞混 | 含税价和不含税价搞反，账差很多 | 明确定价是含税还是不含税，系统里统一口径 |
| 漏税 | 没在有义务的国家注册和申报 | 定期评估全球销售情况，提前注册 |
| 发票抬头错 | 客户开错抬头，重开很麻烦 | 开票前让客户确认，提供自助修改入口 |
| 专票信息不完整 | 开专票缺了银行账号等信息，票无效 | 专票必填项完整校验，缺一个都不能开 |
| 税务规则变更 | 税率变了系统没更新，算错税 | 订阅税务变更通知，定期更新规则 |
| 红冲流程乱 | 退款了发票没红冲，账对不上 | 退款必须关联发票，自动触发红冲流程 |
| 跨境税务不了解 | 以为只在本国交税就够了 | 进新市场前做税务调研，必要时找税务顾问 |
