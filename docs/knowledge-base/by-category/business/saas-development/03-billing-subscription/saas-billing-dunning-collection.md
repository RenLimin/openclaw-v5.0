# 催收与逾期账款管理 SOP

## 适用场景

- SaaS 订阅扣款失败后的自动催收流程
- 逾期账款的分级处理与人工介入
- 支付方式更新的引导与挽留
- 坏账的认定与处理

---

## 核心原则

1. **自动化为主，人工为辅** — 80% 的逾期通过自动流程解决
2. **多渠道提醒** — 邮件 + 站内信 + 短信 + 产品内提示，不要只发邮件
3. **越早越好** — 扣款失败后第一时间提醒，逾期越久回收率越低
4. **体验友好** — 催收不是讨债，语气要专业友好，帮助客户解决问题
5. **数据驱动** — 持续优化催收策略，提高回款率

---

## 催收（Dunning）流程

### 什么是 Dunning

Dunning 是指在客户付款失败后，通过自动重试和提醒，促使客户更新支付方式并完成付款的过程。

### 自动催收流程图

```
首次扣款失败
    ↓
第 0 天：发送失败通知 + 更新支付方式链接
    ↓
第 3 天：自动重试扣款
    ├── 成功 → 发送成功通知 → 结束
    └── 失败 → 第 2 封提醒邮件
                ↓
第 7 天：自动重试扣款
    ├── 成功 → 结束
    └── 失败 → 第 3 封提醒（警告将暂停）
                ↓
第 14 天：自动重试扣款 + 最终提醒
    ├── 成功 → 结束
    └── 失败 → 服务暂停（Suspended）
                ↓
            第 30 天：仍未付款 → 账号注销
```

### 催收节奏与策略

| 阶段 | 时间点 | 动作 | 渠道 | 语气 |
|---|---|---|---|---|
| **首次失败** | Day 0（当天） | 通知扣款失败，引导更新支付方式 | 邮件 + 站内信 | 友好、提醒 |
| **第二次提醒** | Day 3 | 再次提醒，说明影响 | 邮件 | 友好、关注 |
| **第三次提醒** | Day 7 | 警告即将暂停服务 | 邮件 + 短信 | 正式、紧迫 |
| **最终提醒** | Day 12 | 最后提醒，明确暂停时间 | 邮件 + 短信 + 产品内 | 严肃、最终 |
| **服务暂停** | Day 14 | 服务暂停通知 | 邮件 + 短信 | 正式、告知 |
| **终止通知** | Day 25 | 即将终止账号 | 邮件 | 正式、挽留 |

### 自动重试策略

**重试次数：** 3-4 次

**重试间隔：**
- 第 1 次：失败后第 3 天
- 第 2 次：失败后第 7 天
- 第 3 次：失败后第 14 天

**智能重试（进阶）：**
- 失败原因分析：
  - 余额不足 → 几天后重试（可能发工资了）
  - 卡过期 → 不重试，直接让客户换卡
  - 银行拒绝 → 不重试，让客户联系银行
  - 网络超时 → 立即重试一次

---

## 支付失败原因分类与应对

| 失败原因 | 占比 | 自动重试 | 建议对策 |
|---|---|---|---|
| **余额不足** | ~30% | 是，3-5 天后 | 重试 + 提醒充值 |
| **卡片过期** | ~20% | 否 | 提醒更新卡片信息 |
| **银行拒绝（不明原因）** | ~15% | 否 | 让客户联系银行或换卡 |
| **超过限额** | ~10% | 是，次日 | 提醒客户提高限额 |
| **欺诈检测** | ~10% | 否 | 验证客户身份 |
| **网络/系统错误** | ~5% | 是，立即重试 | 自动重试即可 |
| **其他** | ~10% | — | 人工介入排查 |

## 分级催收策略

### 按客户价值分级

| 客户层级 | ARR 范围 | 催收方式 | 负责人 |
|---|---|---|---|
| **大客户** | > ¥100,000/年 | 客户经理一对一沟通 | CSM / 销售 |
| **中客户** | ¥10,000-100,000/年 | 自动催收 + 客服跟进 | 客户成功 |
| **小客户** | < ¥10,000/年 | 全自动催收 | 自动化流程 |
| **免费用户** | 0 | 不催收，直接降级 | 自动化 |

### 大客户催收流程

对于 ARR Top 20 的客户，扣款失败后：
1. 自动发送通知（同时）
2. 客户成功经理 24 小时内联系客户
3. 了解原因，协助解决
4. 必要时提供特殊安排（如延长宽限期）
5. 记录原因，复盘

**为什么大客户要特殊处理？**
- 大客户收入占比高，流失影响大
- 扣款失败可能是内部流程问题（如审批），不是不想付
- 人工沟通可以加强客户关系，了解真实情况

## 服务暂停与恢复

### 暂停操作

**暂停条件：** 逾期 14 天（可配置），且多次催收无效

**暂停影响：**
- 登录后显示暂停页面，无法正常使用
- API 返回 402 Payment Required
- 后台任务暂停执行
- 数据保留 30 天

**暂停通知：**
- 暂停前 3 天发送最终提醒
- 暂停当天发送暂停通知
- 清晰说明：为什么暂停、怎么恢复、数据保留多久

### 恢复流程

**客户在暂停后付款：**
1. 支付成功 → 自动恢复服务
2. 发送恢复确认通知
3. 客户成功跟进（大客户）
4. 记录恢复原因

**恢复时效：** 支付成功后 15 分钟内恢复服务

## 坏账处理

### 坏账认定

**认定条件：**
- 逾期超过 90 天
- 多次催收无效
- 联系不上客户
- 客户明确表示不付款

**认定流程：**
1. 财务部门审核
2. 管理层审批
3. 做坏账处理
4. 账号数据按规则处理

### 坏账处理方式

| 方式 | 说明 | 适用场景 |
|---|---|---|
| **继续催收** | 外包给第三方催收公司 | 金额较大，有回收可能 |
| **坏账核销** | 计入坏账损失，税务上抵扣 | 确认无法收回 |
| **法律途径** | 发律师函、起诉 | 金额大、有合同依据 |

**SaaS 行业坏账率参考：** 1-3%（健康水平）

## 支付更新引导优化

### 更新支付方式的入口

| 位置 | 说明 | 重要性 |
|---|---|---|
| **扣款失败邮件** | 直接的更新按钮 | 最高 |
| **登录后提示** | 登录即看到大红条 | 高 |
| **账单页面** | 账单详情里的更新入口 | 中 |
| **设置 - 支付方式** | 客户主动找过去 | 低 |

### 优化要点

1. **一键直达** — 邮件里的按钮直接跳到更新支付方式页面，不要让客户找
2. **简洁流程** — 更新卡片只需要卡号、有效期、CVV，不要额外信息
3. **多种支付方式** — 支持微信、支付宝、银行卡、对公转账等
4. **清楚说明** — 告诉客户为什么要更新、不更新会怎样
5. **保存偏好** — 更新后默认设为默认支付方式

## 催收效果衡量

### 核心指标

| 指标 | 定义 | 健康值 |
|---|---|---|
| **首次扣款成功率** | 首次扣款成功的比例 | > 90% |
| **最终回款率** | 经过催收后最终成功回款的比例 | > 85% |
| **平均回款天数** | 从扣款失败到成功回款的平均天数 | < 7 天 |
| **坏账率** | 最终成为坏账的比例 | < 3% |
| **流失率（因支付失败）** | 因支付失败最终流失的客户比例 | < 5% |

### 持续优化

- A/B 测试不同的催收邮件文案
- 测试不同的提醒频率和时间
- 分析流失客户的原因，针对性优化
- 每月 review 催收数据，调整策略

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 催收邮件进垃圾箱 | 发了一堆邮件客户没看到 | 做好邮件送达率优化，多渠道触达 |
| 语气太强硬 | 催款信像讨债，客户反感 | 专业友好，帮助客户解决问题 |
| 只有邮件提醒 | 客户不看邮件，错过了 | 站内信 + 短信 + 产品内提示，多渠道 |
| 没有重试策略 | 失败了就不管了，等客户自己发现 | 自动重试 + 分级提醒 |
| 大客户流失 | 大客户扣款失败没人管，最后走了 | 大客户专人跟进，24 小时内联系 |
| 暂停太快 | 晚了一天就停了，客户体验差 | 设置合理的宽限期，至少 7-14 天 |
| 支付更新流程复杂 | 客户想更新卡片，步骤太多找不到 | 优化流程，一键直达，越少步骤越好 |
