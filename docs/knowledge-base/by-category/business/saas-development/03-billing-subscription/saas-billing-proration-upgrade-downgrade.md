# 按比例计费与升降级 SOP

## 适用场景

- SaaS 订阅套餐的升级 / 降级 / 变更
- 席位数量增减的按比例计费
- 计费周期变更（月付转年付等）
- 客户对账单有疑问时的解释与处理

---

## 核心原则

1. **透明化** — 客户能清楚看到每一笔费用怎么来的，为什么是这么多
2. **即时生效升级，延迟生效降级** — 加钱马上用，减钱等下期
3. **可预览** — 变更前让客户看到变更后的费用和时间
4. **向下取整保护客户** — 四舍五入时如不确定，取对客户有利的方向
5. **账单可追溯** — 每一笔按比例计算都能回溯到源数据和公式

---

## 基本概念

### 关键术语

| 术语 | 定义 |
|---|---|
| **Proration** | 按比例计费，根据实际使用时间计算费用 |
| **计费周期** | 账单周期，如每月 15 号到下月 14 号 |
| **周期日** | 每个周期的起始日（如注册日是 15 号，则每月 15 号为账单日） |
| **剩余天数** | 当前周期内距离下次账单日的天数 |
| **已用天数** | 当前周期内已经过去的天数 |
| **差价** | 新价格 - 旧价格（正 = 补差价，负 = 退差价） |

### 计费时间单位

**推荐精度：天**

- 不建议按小时或分钟（太复杂，客户也难理解）
- 按天计算，简单透明
- 不满 1 天的变更按 1 天算（对客户有利）

**每月天数计算：**
- 推荐用实际天数（365 / 366）
- 不建议用 30 天固定值（2 月会有问题）
- 公式：日单价 = 周期价格 / 周期天数

---

## 升级（Upgrade）— 立即生效

### 场景：基础版 → 专业版

**参数示例：**
- 旧套餐：基础版 ¥99/月
- 新套餐：专业版 ¥299/月
- 计费周期：每月 15 号
- 升级日期：当月 20 号（已用 5 天，剩余 25 天）
- 周期总天数：31 天（假设当月 31 天）

### 计算过程

```
旧价格剩余价值 = ¥99 × 25 / 31 = ¥79.84
新价格剩余价值 = ¥299 × 25 / 31 = ¥241.13

应补差价 = 新价格剩余价值 - 旧价格剩余价值
        = ¥241.13 - ¥79.84
        = ¥161.29
```

**客户立即支付 ¥161.29，享受专业版到本月 14 号。**

**下个账单日（15 号）：** 正常收取专业版月费 ¥299。

### 账单明细示例

```
套餐升级：基础版 → 专业版
生效时间：2026-09-20 14:30
本期剩余：25 天

专业版（剩余 25 天）         ¥241.13
基础版未使用部分抵扣          -¥79.84
─────────────────────────────
本次升级应付                 ¥161.29
```

## 降级（Downgrade）— 下个周期生效

### 为什么降级不立即生效？

1. **避免退款复杂性** — 退款需要走支付渠道退款流程，有手续费、有失败可能
2. **客户体验** — 降级了还扣钱，客户感受不好
3. **简单透明** — 降级 = 下次续费按新价格，好理解
4. **商业考量** — 给客户一个反悔期，说不定又升回来了

### 场景：专业版 → 基础版

**参数示例：**
- 旧套餐：专业版 ¥299/月
- 新套餐：基础版 ¥99/月
- 降级日期：当月 20 号
- 下次账单日：下月 15 号

**处理方式：**
1. 当月继续享受专业版（已付费）
2. 系统记录降级请求
3. 下次账单日（下月 15 号）自动按基础版 ¥99 计费
4. 降级前 3 天发送提醒邮件

**特殊情况 — 客户坚持立即降级并退款：**
- 可以走人工退款流程
- 退款金额 = 原价格 × 剩余天数 / 总天数
- 退款方式：原路退回
- 到账时间：3-15 个工作日（取决于支付渠道）
- 操作权限：需客服主管审批

## 席位增减

### 加席位（Add Seats）

**规则：** 立即生效，按剩余天数比例收费

**计算示例：**
- 当前席位数：10
- 新增席位数：5
- 单价：¥99/席位/月
- 剩余天数：20 天
- 周期总天数：30 天

```
新增费用 = 5 × ¥99 × 20 / 30 = ¥330
```

**立即收取 ¥330，席位立即生效。**

### 减席位（Remove Seats）

**规则：** 下个周期生效，不退款

**原因：** 同降级 — 避免退款复杂性，简单透明

**处理方式：**
1. 客户设置新的席位数（减少）
2. 系统记录，下个周期生效
3. 当期不调整，席位还是原来的数量可用
4. 下次续费按新数量计费

## 计费周期变更

### 月付 → 年付（升级周期）

**规则：** 立即生效，已用月份按月付价格扣除，剩余按年付价格计算

**计算示例：**
- 月付价格：¥99/月
- 年付价格：¥999/年（约 8.4 折）
- 当前月付已用：3 个月
- 变更时间：第 4 个月的第 10 天

```
已用费用 = 3 × ¥99 + ¥99 × 10 / 30 = ¥297 + ¥33 = ¥330
年付价格 = ¥999
应补金额 = ¥999 - ¥330 = ¥669
```

**支付 ¥669 后，年付生效，到期日为 12 个月后的今天。**

### 年付 → 月付（降级周期）

**规则：** 年付到期后自动转为月付，不退款

**例外：** 客户强烈要求退款的，按年付价格折算已用月份，剩余退款
- 已用月份按月付原价计算（因为年付优惠是有条件的）
- 例：年付 ¥999，用了 5 个月退款 = ¥999 - 5 × ¥99 = ¥504

## 变更预览与确认

### 变更前必须展示的信息

在客户点击"确认变更"之前，必须清楚展示：

| 信息项 | 说明 |
|---|---|
| **变更内容** | 从什么套餐 / 什么配置 变到什么 |
| **生效时间** | 立即生效 / 下个周期生效 |
| **本次费用** | 这次要付多少钱（升级场景） |
| **下期费用** | 下个账单日会收多少钱 |
| **账单日变化** | 账单日是否改变（一般不变） |
| **退款说明** | 降级场景说明不退款的规则 |

### 确认机制

- 升级：明确展示费用，点击确认后立即扣费
- 降级：二次确认，明确告知"将在下个周期生效，本期仍为原套餐"
- 重要变更（如年付 → 月付）：邮件确认 + 站内信确认

## 发票处理

### 升级发票
- 单独开一张升级差价的发票
- 发票内容：套餐升级差价
- 金额：实际收取的差价金额

### 降级发票
- 当期发票不变（因为已经付过了）
- 下期发票按新套餐开具

### 退款发票
- 如果发生退款，开红字发票（负数发票）
- 与原发票对应

## 常见问题处理

### Q1：客户升级了又降级，怎么算？

**A：**
1. 升级时收了差价
2. 降级按降级规则（下个周期生效，不退款）
3. 所以客户相当于在剩余周期内享受了高级版，付了差价，合理

**如果客户坚持要退：**
- 人工计算，按天算实际使用费用，多退少补
- 需主管审批

### Q2：月底 31 号升级，只有 1 天，钱太少怎么办？

**A：** 设置最小变更费用（如 ¥1 或 ¥0.01），或者不足 1 天按 1 天算。但要写在服务条款里。

### Q3：免费试用期间升级到付费版？

**A：**
- 立即开始计费，免费试用结束
- 或 免费试用结束后再开始计费（更友好，推荐）
- 推荐做法：试用期升级付费 = 试用继续，试用结束后开始付费

### Q4：升级遇到折扣 / 优惠券怎么办？

**A：**
- 已使用的折扣按比例计算
- 规则要明确，避免复杂的嵌套计算
- 建议：折扣只影响基础价格，proration 按折后价计算

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 计算公式不透明 | 客户看到一个数字不知道怎么来的 | 账单明细展示计算公式，让客户能自己算 |
| 时区问题 | 跨时区客户的"天"怎么算不清楚 | 统一用 UTC 或明确客户所在时区 |
| 闰年 / 大小月 | 2 月 28 天，升级时天数算错 | 用实际天数，不能假设每月 30 天 |
| 小数精度 | 每次除不尽四舍五入，累计误差 | 统一保留两位小数，尾差用调整项找平 |
| 多次变更 | 一个周期内升级降级好几次，算乱了 | 每次变更都生成独立的 proration 记录，不叠加计算 |
| 退款手续费 | 退款了支付渠道手续费谁承担 | 服务条款明确，一般客户原因退款扣手续费 |
