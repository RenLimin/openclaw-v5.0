# 安全合规框架总览（SOC 2 / GDPR / 等保）

## 适用场景

- SaaS 产品安全合规体系建设的总体规划
- SOC 2、GDPR、等保 2.0 等合规框架的对比与落地
- 合规认证的准备与推进
- 合规与业务发展的平衡

---

## 核心原则

1. **合规是基本盘，不是加分项** — 做 To B SaaS，合规是入场券
2. **Security by Design** — 安全和合规要从架构阶段嵌入，不是事后打补丁
3. **框架对齐，一次建设多处受用** — 很多控制项是共通的，建好一套可以满足多个合规要求
4. **持续合规，不是一锤子买卖** — 认证只是开始，持续保持才是难点
5. **合规不拖业务后腿** — 在合规前提下尽量减少对业务的摩擦

---

## 主流合规框架对比

### 概览

| 框架 | 发源地 | 适用行业 | 强制程度 | 核心内容 | 认证周期 |
|---|---|---|---|---|---|
| **SOC 2** | 美国（AICPA） | 科技 / SaaS / 云服务 | 非强制，客户要求 | 信任服务原则（安全、可用、保密、处理完整性、隐私） | 6-12 个月 |
| **ISO 27001** | 国际（ISO） | 全行业 | 非强制，通用 | 信息安全管理体系（ISMS） | 6-12 个月 |
| **等保 2.0** | 中国 | 关键信息基础设施 / 重要系统 | 强制（定级以上） | 技术 + 管理双维度，五级 | 3-6 个月 |
| **GDPR** | 欧盟 | 处理欧盟用户数据的所有公司 | 强制，最高罚 4% 全球营收 | 数据保护和隐私 | 持续 |
| **HIPAA** | 美国 | 医疗健康 | 强制 | 医疗数据隐私与安全 | 3-6 个月 |
| **PCI DSS** | 国际 | 处理支付卡的公司 | 强制 | 支付卡数据安全 | 3-6 个月 |

### SaaS 企业一般需要哪些

| 客户类型 | 需要的合规 | 优先级 |
|---|---|---|
| **国内中小企业** | 等保二级 | ⭐⭐⭐ |
| **国内中大型企业 / 国企 / 政府** | 等保三级 + 密评 | ⭐⭐⭐⭐⭐ |
| **北美中小企业** | SOC 2 Type II | ⭐⭐⭐⭐ |
| **北美中大型企业** | SOC 2 + ISO 27001 | ⭐⭐⭐⭐⭐ |
| **欧洲客户** | GDPR + SOC 2 | ⭐⭐⭐⭐ |
| **医疗行业** | HIPAA + SOC 2 | ⭐⭐⭐⭐⭐ |
| **金融行业** | PCI DSS + 行业特定合规 | ⭐⭐⭐⭐⭐ |

## SOC 2 详解

### 什么是 SOC 2

SOC 2（System and Organization Controls 2）是美国注册会计师协会（AICPA）制定的审计标准，针对服务组织的内部控制。

**Type I vs Type II：**
- **Type I** — 某个时间点的控制设计是否合理（静态快照）
- **Type II** — 一段时间内（通常 6-12 个月）控制是否有效运行（动态验证）

> 客户一般认的是 SOC 2 Type II。Type I 只是第一阶段。

### 五大信任原则

| 原则 | 说明 | 必填？ |
|---|---|---|
| **安全（Security）** | 系统和数据的安全保护 | ✅ 必填 |
| **可用性（Availability）** | 系统的可访问性和可用性 | 可选 |
| **处理完整性（Processing Integrity）** | 数据处理的完整、准确、及时 | 可选 |
| **保密性（Confidentiality）** | 保密信息的保护 | 可选 |
| **隐私（Privacy）** | 个人信息的收集、使用、保留、披露 | 可选 |

> 大多数 SaaS 做的是 **安全 + 可用性 + 保密性**。

### 常见控制域

安全原则下的常见控制类别：
- 组织控制（角色职责、政策）
- 风险评估
- 访问控制
- 变更管理
- 逻辑与物理安全
- 系统运营
- 数据管理
- 第三方管理

## 等保 2.0 详解

### 什么是等保 2.0

网络安全等级保护制度 2.0，是中国的网络安全基本制度。

**五个安全等级：**

| 等级 | 定义 | 适用场景 |
|---|---|---|
| 第一级 | 受到破坏后对公民、法人有损害 | 一般信息系统 |
| 第二级 | 受到破坏后对公民、法人有严重损害，对社会有损害 | 中小企业 SaaS |
| 第三级 | 受到破坏后对社会有严重损害，对国家安全有损害 | 中大型企业 / 政务云 |
| 第四级 | 受到破坏后对国家安全有严重损害 | 关键信息基础设施 |
| 第五级 | 受到破坏后对国家安全有特别严重损害 | 国家级特殊系统 |

**SaaS 一般做二级或三级。**

### 技术 + 管理双维度

**技术要求（5 类）：**
1. 安全物理环境
2. 安全通信网络
3. 安全区域边界
4. 安全计算环境
5. 安全管理中心

**管理要求（5 类）：**
1. 安全管理制度
2. 安全管理机构
3. 安全管理人员
4. 安全建设管理
5. 安全运维管理

### 等保建设流程

```
1. 定级 → 2. 备案 → 3. 建设整改 → 4. 等级测评 → 5. 监督检查
```

- **测评周期：** 三级每年一次，二级每两年一次
- **测评机构：** 必须是有资质的等级测评机构

## GDPR 详解

### 什么是 GDPR

欧盟《通用数据保护条例》（General Data Protection Regulation），2018 年生效。

**适用范围：** 只要处理欧盟用户的个人数据，不管公司在哪，都适用。

**最高罚款：** 2000 万欧元或全球年营业额的 4%，取高者。

### 核心原则

| 原则 | 说明 |
|---|---|
| **合法、公正、透明** | 数据处理要有合法依据，要透明 |
| **目的限制** | 收集数据时的目的，不能超范围使用 |
| **数据最小化** | 只收集必要的，不要什么都要 |
| **准确性** | 数据要准确，及时更新 |
| **存储限制** | 不要存太久，够用就删 |
| **完整性与保密性** | 数据安全保护 |
| **问责制** | 数据控制者要对合规负责 |

### 数据主体权利

GDPR 赋予个人很多权利，SaaS 产品要支持：

| 权利 | 说明 | 响应时间 |
|---|---|---|
| **知情权** | 告诉你收集了什么数据、用来干嘛 | - |
| **访问权** | 个人可以要求看自己的数据 | 1 个月 |
| **更正权** | 个人可以要求更正不准确的数据 | 1 个月 |
| **被遗忘权** | 个人可以要求删除自己的数据 | 1 个月 |
| **限制处理权** | 可以要求限制处理 | 1 个月 |
| **数据可携权** | 可以导出自己的数据，通用格式 | 1 个月 |
| **反对权** | 可以反对基于合法利益的处理 | - |
| **自动化决策反对权** | 反对纯自动化决策 | - |

## 合规框架对齐

### 各框架的共性

很多安全控制是各个框架都要求的，可以一次建设多处受用：

| 控制域 | SOC 2 | ISO 27001 | 等保 2.0 | GDPR |
|---|---|---|---|---|
| 访问控制 | ✅ | ✅ | ✅ | ✅ |
| 变更管理 | ✅ | ✅ | ✅ | - |
| 数据加密 | ✅ | ✅ | ✅ | ✅ |
| 备份与恢复 | ✅ | ✅ | ✅ | - |
| 漏洞管理 | ✅ | ✅ | ✅ | - |
| 安全培训 | ✅ | ✅ | ✅ | - |
| 日志审计 | ✅ | ✅ | ✅ | ✅ |
| 第三方管理 | ✅ | ✅ | ✅ | ✅ |
| 数据主体权利 | - | - | - | ✅ |
| 物理安全 | ✅ | ✅ | ✅ | - |

**建议：** 以一个框架为核心（如 SOC 2 或等保）建设，其他框架做 gap analysis 补齐。

## 合规建设路线图

### 阶段一：基础建设（0-3 个月）

- 制定信息安全政策
- 建立访问控制体系（最小权限、定期审计）
- 数据分类分级
- 部署安全工具（防火墙、WAF、EDR 等）
- 基础日志和监控
- 全员安全意识培训

### 阶段二：体系完善（3-6 个月）

- 建立安全团队 / 安全负责人
- 完善安全管理制度
- 漏洞管理流程
-  incident response 流程
- 供应商安全管理
- 业务连续性计划
- 等保测评准备 / SOC 2 审计准备

### 阶段三：认证推进（6-12 个月）

- 选定认证机构 / 审计师
- 差距分析（gap analysis）
- 整改补齐
- 预评估
- 正式审计
- 取得认证

### 阶段四：持续运营（持续）

- 定期内部审计
- 持续改进
- 年度审计 / 复评
- 安全运营中心（SOC）
- 渗透测试（定期）

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 为合规而合规 | 搞了一堆制度和流程，只是为了拿证，实际没用 | 合规和安全结合，安全提升了自然就合规了 |
| 一次性思维 | 拿了证就不管了，第二年审计前临时抱佛脚 | 合规是持续的，融入日常流程 |
| 过度合规 | 小公司就搞三级等保 + SOC 2 + ISO 27001，成本不堪重负 | 按客户需求逐步做，先做最需要的 |
| 技术和管理两张皮 | 技术搞技术的，制度写制度的，对不上 | 技术和管理同步建设，制度要能落地 |
| 忽略员工 | 只搞技术不培训人，最后钓鱼邮件一钓一个准 | 人是最大的安全漏洞，定期培训 + 钓鱼演练 |
| 合规拖慢业务 | 安全审核流程太长，业务等不及 | 安全左移，自动化安全检查，减少人工卡点 |
