# SaaS 产品路线图制定框架

## 适用场景

- SaaS 产品季度/年度路线规划
- 产品优先级决策与资源分配
- 跨团队（产研/销售/客户成功）对齐产品方向

---

## 核心原则

1. **Outcome over output** — 路线图标的是要达成的业务结果，不是功能列表
2. **Now / Next / Later 三栏制** — 拒绝虚假的精确日期，越远越模糊
3. **客户声音 + 数据驱动** — 直觉和定性反馈要被定量数据校准
4. **双轨制** — 70% 承诺工作 + 30% 探索/技术债，留足弹性

---

## 操作步骤

### 1. 输入收集（季度开始前 2 周）

**数据输入：**
- NPS / CSAT 趋势与关键 detractor 反馈
- 功能使用数据 — 哪些功能 DAU 高/低、哪些几乎没人用
- 流失原因分析（最近季度 churn 的 top 3 原因）
- 支持工单分类统计（哪些问题消耗最多人天）
- 竞品动态（功能对比、定价变化、融资新闻）

**利益相关方输入：**
- 销售：最常卡单的功能 / 竞品对比劣势
- 客户成功：top 20 客户的需求清单
- 工程：技术债清单 + 架构演进需求
- 市场：GTM 需要的差异化能力

### 2. 优先级排序（RICE + Kano 双框架）

**RICE 模型量化评分：**

| 因素 | 定义 | 评分标准 |
|---|---|---|
| Reach | 影响多少用户/收入 | 月活用户数或 ARR 占比 |
| Impact | 对核心指标的影响程度 | 0.25 / 0.5 / 1 / 2 / 3 |
| Confidence | 信心程度 | 低 50% / 中 80% / 高 100% |
| Effort | 投入人月 | 工程预估人月 |

**Kano 模型分类：**
- **基本型需求** — 不做就流失（如 SSO、权限）
- **期望型需求** — 做得越好满意度越高（如性能、报表）
- **兴奋型需求** — 不做不扣分，做了超预期（差异化功能）
- **无差异型** — 做不做都没感觉（果断砍掉）
- **反向型** — 做了反而减分（过度复杂的配置）

### 3. 路线图输出（Now / Next / Later）

| 时间窗 | 粒度 | 确定度 | 示例 |
|---|---|---|---|
| **Now** (当前季度) | 具体功能 / 里程碑 | 90%+ | "Q3 上线企业版 SSO + SCIM" |
| **Next** (下季度) | 问题 / 主题 | 60-80% | "Q4 解决数据导出与报表能力" |
| **Later** (半年以上) | 方向 / 探索 | <50% | "明年探索 AI 助手方向" |

**输出格式：**
1. 一页纸路线图（Now/Next/Later 三栏 + 核心主题）
2. 季度 OKR（3-5 个目标，每个 2-3 个 KR）
3. 详细排期表（仅 Now 部分，含 sprint 拆解）

### 4. 沟通与对齐

- **产品全员会** — 每季度第一天，讲清楚路线图和 why
- **销售对齐会** — 重点讲对赢单有帮助的功能，以及怎么说
- **客户成功沟通** — 哪些能跟客户说，哪些不能承诺日期
- **外部沟通** — 公开发布的路线图（如 public roadmap）只放 Now 部分

### 5. 复盘与迭代（每月 Review）

- **月度路线图检查** — 进度如何？偏差原因？是否需要调整
- **季度复盘** — 承诺的 deliverable 完成了多少？业务指标达成了吗
- **路线图债务** — 连续推迟 2 次以上的项目，重新评估要不要做

## 关键模板

**季度路线图一页纸：**

```
Q3 2026 产品路线图

🎯 季度主题：企业化升级

Now (Q3)                     Next (Q4)               Later (2027)
────────────────────────     ──────────────          ──────────────
• SAML SSO + SCIM          • 自定义报表引擎        • AI 助手
• RBAC 精细化权限           • 开放 API v2           • 移动端 app
• 审计日志                  • 数据导入工具          • 多语言
• 性能优化 (P95 < 500ms)    • 工作流引擎            • 私有化部署
```

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 功能堆砌 | 路线图是一长串功能列表 | 按主题/问题组织，不是按功能 |
| 日期幻觉 | 12 个月后的功能还标了精确日期 | Now/Next/Later 三档，不写死日期 |
| 销售驱动 | 路线图全是销售承诺的功能 | 销售需求占比不超过 40%，留足战略空间 |
| 全部 P0 | 什么都重要 = 什么都不重要 | 强制排序，每季度最多 3 个核心主题 |
| 只看客户 | 路线图全是现有客户需求，忽视 ICP 拓展 | 至少 20% 投入服务新客户/新市场的功能 |
| 无视技术债 | 路线图只有新功能，工程团队暗中抵触 | 每个季度至少 20% 投入技术债/基础设施 |
