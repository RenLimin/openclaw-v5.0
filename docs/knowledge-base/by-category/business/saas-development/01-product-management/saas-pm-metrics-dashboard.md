# SaaS 产品指标体系与数据看板 SOP

## 适用场景

- SaaS 产品核心指标的定义、采集、看板搭建
- 产品团队日常数据监控与决策
- 北极星指标与分层指标体系建设

---

## 核心原则

1. **指标 ≠ 数据** — 指标是有业务含义的数据，能指导行动
2. **少而精** — 每个层级不超过 5 个核心指标，多了等于没有
3. **可行动** — 每个指标都要有对应的 owner 和 action plan
4. **统一口径** — 全公司对同一个指标的定义必须一致
5. **关注趋势，不纠结单点** — 看方向和变化，不被单日波动干扰

---

## SaaS 五层指标体系

### 第一层：北极星指标（North Star Metric）

**定义：** 一个最核心的指标，代表产品为用户创造的核心价值

**选择标准：**
- 能反映客户从产品中获得的价值
- 与收入正相关
- 可测量、可归因
- 团队能直接影响

**常见北极星指标：**

| 产品类型 | 北极星指标示例 |
|---|---|
| 协作工具 | 周活跃团队数 |
| CRM | 月活跃销售代表数 × 人均创建商机数 |
| 数据分析 | 周查询量 |
| 设计工具 | 月创建设计文件数 |
| 客服系统 | 日均处理工单量 |

### 第二层：AARRR 海盗模型

| 阶段 | 指标 | 计算公式 | 说明 |
|---|---|---|---|
| **Acquisition 获取** | 新增注册数 / CAC | 新增用户数 / 获客成本 | 关注获客质量，不仅是数量 |
| **Activation 激活** | 激活率 | 完成关键动作的新用户 / 新增用户 | 定义 "Aha Moment" |
| **Retention 留存** | 次日 / 7 日 / 30 日留存 | 第 N 天还活跃的用户 / 新增用户 | 留存是 SaaS 的生命线 |
| **Revenue 收入** | MRR / LTV / LTV:CAC | 月经常性收入 / 客户终身价值 | 收入质量和增长健康度 |
| **Referral 推荐** | NPS / 病毒系数 | 净推荐值 / 每个用户带来的新用户 | 口碑增长效率 |

### 第三层：业务线指标

**产品使用：**
- DAU / WAU / MAU（日 / 周 / 月活跃用户）
- 日均使用时长
- 功能渗透率（使用某功能的用户占比）
- 核心功能使用频次

**客户层面：**
- 活跃租户数
- 租户健康分（综合指标）
- NRR（净收入留存率）
- GRR（毛收入留存率）

### 第四层：功能级指标

每个功能都要有自己的指标：
- 触达率（看到功能入口的用户比例）
- 点击率
- 首次使用率
- 重复使用率（次日 / 周留存）
- 功能完成率（核心动作完成比例）
- 满意度（功能内 thumbs up/down 或问卷）

### 第五层：体验与性能指标

- 页面加载时间（P50 / P95 / P99）
- 错误率
- 核心操作成功率
- 用户满意度（CSAT）
- 客户支持首次响应时间

## 数据看板搭建

### 核心看板清单

| 看板名称 | 受众 | 更新频率 | 核心内容 |
|---|---|---|---|
| **北极星看板** | 全公司 | 每日 | 北极星指标 + 趋势 + 关键驱动因素 |
| **产品健康看板** | 产品团队 | 每日 | AARRR 指标 + 留存曲线 + 功能使用 |
| **客户健康看板** | 客户成功 | 每日 | 活跃租户 + 健康分 + 流失预警 |
| **增长实验看板** | 增长团队 | 实时 | 实验列表 + 状态 + 结果 |
| **性能监控看板** | 工程团队 | 实时 | 延迟 + 错误率 + 资源使用 |
| **收入看板** | 管理层 | 每周 | MRR / ARR / NRR / 转化率 |

### 看板设计规范

**每个指标卡片包含：**
- 指标名称和定义
- 当前值
- 环比变化（日环比 / 周环比 / 月环比）
- 目标值（如果有）
- 趋势图（最近 30 天）

**颜色规范：**
- 🟢 绿色：达标或超预期（增长类 > 目标，下降类 < 阈值）
- 🟡 黄色：需要关注（偏离目标 10-20%）
- 🔴 红色：报警（偏离目标 >20% 或触发阈值）

## 指标定义规范

**统一口径要求：**
- 每个指标必须有明确的计算公式和数据来源
- 指标定义文档化，全公司共享
- 数据口径变更必须通知所有使用方，并记录变更历史

**定义模板：**

```
指标名称：月活跃用户（MAU）
定义：自然月内至少登录 1 次的去重用户数
计算公式：COUNT(DISTINCT user_id) WHERE login_time BETWEEN ...
数据来源：用户行为日志表 user_events
统计频率：每日更新（T+1）
Owner：数据团队 - 张三
最后更新：2026-06-01
历史变更：
  - 2026-06-01：将 "登录" 定义从 "打开页面" 改为 "完成登录"
```

## 指标运营机制

### 每周数据 Review

**参会人：** 产品负责人 + 数据分析师 + 各模块 PM

**议程（30 分钟）：**
1. 北极星指标回顾（5 分钟）
2. 核心指标异动解读（10 分钟）
3. 各模块指标进展（10 分钟）
4. Action item 确认（5 分钟）

### 每月业务复盘

**输出：** 月度业务简报（1 页）
- 核心指标一览表
- 本月关键变化和原因
- 下月重点关注事项

## 常见陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 虚荣指标 | 只看注册数，不看不活跃用户 | 关注留存和收入等真实价值指标 |
| 指标太多 | 看板上 50 个指标，没人看 | 每层不超过 5 个核心指标 |
| 口径不一致 | 产品说 MAU 1 万，运营说 8 千 | 统一数据仓库，指标定义文档化 |
| 只看数量不看质量 | DAU 涨了就开心，不管是不是僵尸用户 | 关注深度使用指标，如 D7/D30 留存 |
| 数据驱动变数据教条 | 为了数字好看做伤害用户的事 | 定期回顾指标是否还代表真实价值 |
| 没有目标 | 只有数字，不知道是好是坏 | 每个核心指标都设目标值和预警线 |
