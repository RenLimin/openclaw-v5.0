# 软件开发（SaaS 全生命周期）

> L3 通用业务层 — 完整的 SaaS 软件开发业务操作系统
> 覆盖从需求到运维的端到端全生命周期。

## 核心理念

不是 8 个独立维度的简单罗列，而是一个**端到端的业务操作系统**。
每个阶段有明确的角色、交付物、质量标准，阶段间有清晰的输入/输出契约。

## 全生命周期流程

```
产品设计 → 系统架构 → 前端开发 + 后端开发 → 测试工程 → DevOps/SRE → 数据/安全
   ↑                                                                    │
   └──────────── 反馈迭代 ──────────────────────────────────────────────┘
```

## 阶段总览

| 阶段 | 角色 | 核心知识体系 | 交付物 | 优先级 |
|------|------|-------------|--------|--------|
| **1. 产品设计** | 产品经理 | 精益产品 / JTBD / 设计思维 / 用户研究 | PRD / 用户故事 / 原型 / 路线图 | **P0** |
| **2. 系统架构** | 系统架构师 | DDD / 微服务 / 事件驱动 / SOLID / 多租户 | 架构文档 / API 契约 / 技术选型报告 | **P0** |
| **3. 前端开发** | 前端工程师 | React / Vue / SPA / 性能优化 / 可访问性 | UI 组件 / 页面 / 交互实现 | **P0** |
| **4. 后端开发** | 后端工程师 | RESTful / GraphQL / 数据库设计 / 缓存 / 消息队列 | API / 业务逻辑 / 数据模型 | **P0** |
| **5. 测试工程** | QA 工程师 | TDD / 测试金字塔 / 自动化测试 / 性能测试 | 测试用例 / 自动化脚本 / 测试报告 | **P1** |
| **6. DevOps/SRE** | DevOps 工程师 | SRE / GitOps / CI/CD / 混沌工程 / 多租户部署 | 流水线 / 基础设施 / 监控告警 | **P1** |
| **7. 数据工程** | 数据工程师 | ETL / 数据建模 / BI / 实时分析 | 数据管线 / 报表 / 数据仓库 | **P2** |
| **8. 安全工程** | 安全工程师 | OWASP / 等保 2.0 / GDPR / 零信任 | 安全方案 / 审计报告 / 应急预案 | **P2** |

## 阶段间契约

| 输入阶段 | 输出阶段 | 契约内容 |
|----------|----------|----------|
| 产品设计 → | 系统架构 | PRD + 用户故事 + 非功能需求 |
| 系统架构 → | 前端开发 | API 契约 + 组件规范 + 设计令牌 |
| 系统架构 → | 后端开发 | API 契约 + 数据模型 + 技术栈 |
| 前端开发 + 后端开发 → | 测试工程 | 可测试版本 + API 文档 + 测试环境 |
| 测试工程 → | DevOps/SRE | 发布候选 + 测试报告 + 部署清单 |
| DevOps/SRE → | 数据工程/安全工程 | 运行时数据 + 安全事件 + 性能基线 |
| 数据工程/安全工程 → | 产品设计 | 用户行为数据 + 安全反馈 → 迭代输入 |

## 与其他业务领域的协作

| 业务领域 | 协作维度 | 协作方式 |
|----------|----------|----------|
| 交付管理 | 项目管理 | 项目驱动开发流程，里程碑对齐 |
| 交付管理 | 合同管理 | 合同中的功能需求驱动产品规划 |
| 交付管理 | 售后管理 | 售后反馈驱动产品迭代 |
| 交付管理 | 实施管理 | 实施约束影响架构设计 |
