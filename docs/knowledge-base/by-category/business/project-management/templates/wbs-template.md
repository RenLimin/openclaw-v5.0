# WBS 模板（工作分解结构）

> WBS 是将项目范围分解为可管理工作包的分层结构。

## 使用说明

1. 第 1 层：项目名称
2. 第 2 层：主要交付物/阶段
3. 第 3 层：子交付物/工作包
4. 工作包应满足 8/80 规则（8-80 小时可完成）

## 模板

```markdown
# WBS：[项目名称]

## 1. [项目名称]
### 1.1 [主要交付物/阶段 1]
#### 1.1.1 [工作包 1.1.1]
- 描述：
- 验收标准：
- 估算工时：
- 负责人：
- 依赖：

#### 1.1.2 [工作包 1.1.2]
- 描述：
- 验收标准：
- 估算工时：
- 负责人：
- 依赖：

### 1.2 [主要交付物/阶段 2]
#### 1.2.1 [工作包 1.2.1]
...

## 2. 项目管理
### 2.1 项目启动
### 2.2 项目规划
### 2.3 项目监控
### 2.4 项目收尾
```

## 分解原则

| 原则 | 说明 |
|------|------|
| **100% 规则** | WBS 包含全部项目范围，不多不少 |
| **互斥** | 工作包之间不重叠 |
| **MECE** | 相互独立，完全穷尽 |
| **可估算** | 工作包可估算工时和成本 |
| **可分配** | 工作包可分配给具体负责人 |

## 注意事项

- WBS 不是进度计划——它不包含时间顺序
- 分解粒度：太小（管理成本高），太大（控制力不足）
- 团队参与：WBS 应由团队共同创建，而非 PM 独自完成
- 渐进明细：远期工作可粗分解，近期工作需详细分解
