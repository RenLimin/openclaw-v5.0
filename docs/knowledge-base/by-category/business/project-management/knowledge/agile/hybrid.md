# 混合项目管理方法

> 混合方法结合预测型（瀑布）和敏捷的优势，根据项目特征选择最佳组合。

## 混合策略

### 1. 按阶段混合
```
预测型（需求分析/架构设计）→ 敏捷（开发/迭代）→ 预测型（部署/验收）
```
- 适用：需求相对明确但开发需要灵活性的项目

### 2. 按组件混合
```
核心模块（预测型） + 用户界面（敏捷） + 实验功能（精益）
```
- 适用：不同组件有不同确定性程度的项目

### 3. 按团队混合
```
平台团队（Scrum） + 运维团队（Kanban） + 探索团队（Lean Startup）
```
- 适用：多团队并行，工作性质不同的组织

### 4. 渐进式混合
```
预测型（初期） → 混合（中期） → 敏捷（后期）
```
- 适用：项目初期不确定性高，后期逐步明确

## 选择框架

### 情境评估

| 评估维度 | 偏预测型 | 偏敏捷 |
|----------|----------|--------|
| 需求确定性 | 高 | 低 |
| 技术风险 | 低 | 高 |
| 干系人参与 | 阶段性 | 持续 |
| 交付频率 | 单次 | 频繁 |
| 变更容忍度 | 低 | 高 |
| 团队分布 | 集中 | 分布均可 |

### 决策树

```
需求是否明确？
├── 是 → 技术是否成熟？
│       ├── 是 → 预测型（瀑布）
│       └── 否 → 混合（预测架构 + 敏捷开发）
└── 否 → 是否需要频繁交付？
        ├── 是 → 敏捷（Scrum/Kanban）
        └── 否 → 混合（敏捷探索 + 预测交付）
```

## 混合方法实践

### Sprint 内的预测型元素
- Sprint 目标固定（Scrum）
- Sprint Backlog 不变更（Scrum）
- 但 Sprint 计划包含详细的任务分解（预测型元素）

### 敏捷中的预测型里程碑
- 每个 Sprint 交付可工作增量（敏捷）
- 关键里程碑有明确的范围和验收标准（预测型）
- 里程碑之间用 Sprint 填充

## 常见混合模式

| 模式 | 描述 | 适用 |
|------|------|------|
| **Water-Scrum-Fall** | 瀑布需求+设计 → Scrum 开发 → 瀑布部署 | 企业 IT 项目 |
| **Agile-Fall** | 敏捷开发 → 瀑布验收/合规 | 合规要求高的行业 |
| **SAFe** | 规模化敏捷框架 | 大型企业多团队 |
| **Scrumban** | Scrum 结构 + 看板流动 | 运维+开发混合 |

## 注意事项

- 混合不是"两全其美"，需要明确每种方法何时生效
- 团队需要理解两种方法的思维差异
- 避免"假敏捷"（形式上是 Scrum，实质上是小瀑布）
- 定期评估混合策略的有效性
