# 风险管理：风险登记册

> 风险管理是识别、分析和应对项目风险的系统化过程。

## 风险管理流程

```
识别 → 定性分析 → 定量分析 → 应对规划 → 监控
  ↑                                      │
  └──────────────────────────────────────┘
```

## 风险识别

### 识别方法
- **头脑风暴**：团队集体讨论
- **检查清单**：基于历史项目的风险清单
- **SWOT 分析**：优势/劣势/机会/威胁
- **假设分析**：检验项目假设的稳定性
- **专家访谈**：咨询领域专家

### 常见风险类别

| 类别 | 示例 |
|------|------|
| **技术风险** | 技术方案不可行、集成失败、性能不达标 |
| **管理风险** | 进度延误、成本超支、资源不足 |
| **外部风险** | 法规变化、市场变化、供应商问题 |
| **组织风险** | 干系人抵制、优先级冲突、人员流失 |

## 风险评估

### 概率-影响矩阵

| 概率＼影响 | 极低(1) | 低(2) | 中(3) | 高(4) | 极高(5) |
|-----------|---------|-------|-------|-------|---------|
| **极高(5)** | 中 | 高 | 高 | 极高 | 极高 |
| **高(4)** | 中 | 中 | 高 | 高 | 极高 |
| **中(3)** | 低 | 中 | 中 | 高 | 高 |
| **低(2)** | 低 | 低 | 中 | 中 | 高 |
| **极低(1)** | 极低 | 低 | 低 | 中 | 中 |

### 风险评分
- 风险值 = 概率 × 影响
- ≥ 20：极高风险，立即应对
- 10-19：高风险，优先应对
- 5-9：中风险，监控
- < 5：低风险，接受

## 风险应对策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **规避（Avoid）** | 消除风险源 | 高风险且可避免 |
| **转移（Transfer）** | 将影响转移给第三方 | 财务风险（保险/外包） |
| **缓解（Mitigate）** | 降低概率或影响 | 最常见策略 |
| **接受（Accept）** | 承认风险但不主动应对 | 低风险或应对成本过高 |
| **升级（Escalate）** | 上报给更高层级 | 超出项目经理权限 |

## 风险登记册模板

| 字段 | 说明 |
|------|------|
| 风险 ID | R-001 |
| 风险描述 | 如果...则... |
| 类别 | 技术/管理/外部/组织 |
| 概率 | 1-5 |
| 影响 | 1-5 |
| 风险值 | 概率 × 影响 |
| 应对策略 | 规避/转移/缓解/接受 |
| 应对措施 | 具体行动 |
| 责任人 | 负责监控和应对的人 |
| 状态 | 开放/已关闭/已发生 |

## 注意事项

- 风险登记册是活文档，需要持续更新
- 已发生的风险转为问题（Issue），进入问题日志
- 定期（至少每 Sprint/每月）审查风险登记册
- 不要试图管理所有风险，聚焦高优先级
