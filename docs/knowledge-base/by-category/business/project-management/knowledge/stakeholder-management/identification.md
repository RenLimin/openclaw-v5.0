# 干系人识别与参与

> 干系人是影响项目或被项目影响的个人、群体或组织。
> 有效的干系人管理是项目成功的关键因素。

## 干系人识别

### 识别方法
- **头脑风暴**：团队集体列出所有可能的干系人
- **文档分析**：项目章程、合同、组织架构图
- **访谈**：与已知干系人讨论他们知道的其他干系人
- **干系人映射**：从项目中心向外扩展

### 常见干系人

| 类别 | 示例 |
|------|------|
| **内部-管理层** | 项目发起人、高管、职能经理 |
| **内部-团队** | 开发团队、测试团队、运维团队 |
| **内部-其他** | 财务、法务、采购、HR |
| **外部-客户** | 最终用户、产品买家 |
| **外部-供应商** | 外包商、技术供应商 |
| **外部-监管** | 政府机构、行业协会 |

## 干系人分析

### 权力-利益矩阵

| 权力＼利益 | 低利益 | 高利益 |
|-----------|--------|--------|
| **高权力** | 保持满意（Keep Satisfied） | 重点管理（Manage Closely） |
| **低权力** | 最小关注（Monitor） | 保持沟通（Keep Informed） |

### 影响力-态度矩阵

| 影响力＼态度 | 反对 | 中立 | 支持 |
|-------------|------|------|------|
| **高影响力** | 重点转化 | 争取支持 | 持续维护 |
| **低影响力** | 监控 | 沟通 | 维持 |

### 干系人登记册

| 字段 | 说明 |
|------|------|
| 名称/角色 | 干系人及其职位 |
| 分类 | 内部/外部 |
| 权力 | 高/中/低 |
| 利益 | 高/中/低 |
| 态度 | 支持/中立/反对 |
| 期望 | 对项目的期望和关注点 |
| 影响 | 对项目的潜在影响 |
| 沟通需求 | 频率/方式/内容 |

## 干系人参与策略

### 参与层次

| 层次 | 说明 | 目标干系人 |
|------|------|-----------|
| **不知（Unaware）** | 不知道项目 | 需要通知 |
| **抵制（Resistant）** | 反对项目 | 需要转化 |
| **中立（Neutral）** | 不置可否 | 需要争取 |
| **支持（Supportive）** | 支持项目 | 需要维护 |
| **领导（Leading）** | 积极推动 | 需要授权 |

### 参与策略

| 当前层次 → 目标层次 | 策略 |
|---------------------|------|
| 不知 → 支持 | 通知 + 教育 + 邀请参与 |
| 抵制 → 中立 | 倾听顾虑 + 解决合理关切 |
| 中立 → 支持 | 展示价值 + 邀请参与决策 |
| 支持 → 领导 | 授权 + 赋予责任 + 认可贡献 |

## 沟通管理

### 沟通计划

| 干系人 | 内容 | 频率 | 方式 | 责任人 |
|--------|------|------|------|--------|
| 发起人 | 项目状态/风险/决策点 | 每周 | 邮件+会议 | PM |
| 团队 | 任务/进度/阻塞 | 每日 | 站会 | SM |
| 客户 | 交付/反馈/变更 | 每 Sprint | 评审会 | PM |

### 沟通原则
- **及时**：坏消息要快，好消息要稳
- **透明**：主动暴露问题，不掩盖
- **适配**：根据干系人调整沟通方式和深度
- **双向**：不只是传达，还要倾听反馈

## 注意事项

- 干系人分析不是一次性活动，需要持续更新
- 关键干系人的态度可能随时间变化
- 不要忽视"沉默的干系人"——他们可能在关键时刻反对
- 干系人管理与沟通管理紧密关联但不同
