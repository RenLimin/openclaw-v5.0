# 干系人参与计划

> 干系人参与计划描述如何让干系人有效参与项目决策和执行，是干系人管理从"识别"走向"行动"的关键环节。

## 概述

识别干系人（[identification.md](./identification.md)）回答"谁是干系人"，参与计划回答"如何让干系人有效参与"。参与不是"通知"，而是**双向互动**——让干系人影响项目，也让项目理解干系人。

## 参与层级评估

### 当前参与 vs 期望参与

| 层级 | 定义 | 特征 |
|------|------|------|
| **不知（Unaware）** | 不知道项目存在 | 完全未接触 |
| **抵制（Resistant）** | 知道但反对 | 可能阻碍项目 |
| **中立（Neutral）** | 知道但不支持也不反对 | 观望 |
| **支持（Supportive）** | 知道并支持 | 积极配合 |
| **领导（Leading）** | 积极推动项目 | 主动参与决策 |

### 差距分析

```
对每个关键干系人：
  当前层级（现在） → 期望层级（目标）
  差距 = 期望 - 当前
  差距 > 0 → 需要参与策略
  差距 = 0 → 维持策略
  差距 < 0 → 评估原因（是否过度参与）
```

## 参与策略

| 当前 → 期望 | 策略 | 工具 |
|-------------|------|------|
| 不知 → 支持 | 通知 + 教育 + 邀请 | 简报、启动会 |
| 抵制 → 中立 | 倾听顾虑 + 解决合理关切 | 一对一沟通 |
| 中立 → 支持 | 展示价值 + 邀请参与决策 | 工作坊、评审会 |
| 支持 → 领导 | 授权 + 赋予责任 + 认可 | 顾问角色、里程碑评审 |

## 参与计划模板

| 干系人 | 当前层级 | 期望层级 | 参与策略 | 关键信息 | 时间点 | 责任人 |
|--------|----------|----------|----------|----------|--------|--------|
| 项目发起人 | 支持 | 领导 | 月度治理评审 | 进度/风险/决策点 | 每月 | PM |
| 客户代表 | 中立 | 支持 | Sprint 评审参与 | 交付/反馈 | 每 Sprint | PO |
| 运维团队 | 不知 | 支持 | 早期介入培训 | 部署/运维需求 | 开发前 | PM |

## 执行与监控

### 参与效果评估

| 指标 | 评估方式 |
|------|----------|
| 参与度 | 会议出席率、反馈响应率 |
| 满意度 | 定期干系人满意度调查 |
| 期望对齐 | 期望管理是否有效（偏差减少） |
| 阻力变化 | 抵制干系人是否转向中立/支持 |

### 持续更新
- 干系人态度可能变化 → 定期重评（每阶段/Sprint）
- 新干系人出现 → 及时补充登记册
- 参与策略失效 → 调整策略和方法

## 常见误区

| 误区 | 纠正 |
|------|------|
| 参与 = 频繁开会 | 参与是质量而非数量，过度开会适得其反 |
| 只管理高权力干系人 | 低权力高影响（如意见领袖）也需关注 |
| 一次制定终身有效 | 参与计划需随项目推进动态调整 |
| 忽略抵制者 | 抵制者可能关键时刻否决项目 |

## 注意事项

- 参与计划要**聚焦关键干系人**（帕累托原则）
- 参与策略要**可执行**（明确谁、何时、做什么）
- 与 [communication-plan.md](./communication-plan.md) 配套使用
- 参与计划的执行情况纳入 [status-report.md](../../templates/status-report.md) 跟踪

## 适用场景

- ✅ 项目启动时评估干系人参与需求
- ✅ 关键干系人态度变化后的策略调整
- ✅ 高政治敏感度/多利益方项目
- ❌ 干系人简单且稳定的项目（维持常规沟通即可）
