# PMBOK 8th：方法裁剪指南

> 裁剪是选择最适合项目情境的管理方法、过程和工件，让项目管理从"照搬"走向"适配"。

## 概述

PMBOK 第 8 版的核心思想之一是**没有一刀切的管理方法**。裁剪不是"简化"的同义词，而是**有意识地选择**哪些过程、工具和工件适用于当前项目，并明确哪些不适用及原因。

## 裁剪的五步流程

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1. 选择初始方法 | 基于项目特征选择预测型/适应型/混合型 | 候选方法清单 |
| 2. 评估裁剪因素 | 逐项评估项目环境、团队、文化 | 裁剪因素清单 |
| 3. 选择过程与工件 | 确定需要的过程、深度、工具 | 过程取舍清单 |
| 4. 与干系人确认 | 与发起人和团队达成共识 | 裁剪决策记录 |
| 5. 持续审查 | 在生命周期中定期复查裁剪合理性 | 裁剪调整记录 |

## 裁剪因素

### 关键裁剪因素

| 因素 | 问题 | 影响 |
|------|------|------|
| 项目规模 | 预算/工期/团队多大 | 越大越需要正式过程 |
| 复杂度 | 技术/组织/依赖多复杂 | 越复杂越需要精细管理 |
| 风险等级 | 失败后果多严重 | 高风险需要更多监控过程 |
| 合规要求 | 是否有监管/合同约束 | 合规项目不可裁剪掉审计过程 |
| 干系人参与度 | 干系人是否持续参与 | 高参与适合适应型 |
| 团队经验 | 团队对该方法多熟悉 | 不熟的方法需要更多指导 |
| 文化 | 组织是否容忍不确定性 | 影响变更管理方式 |
| 交付频率 | 多久需要一次交付 | 高频交付倾向适应型 |

### 裁剪维度

| 维度 | 可裁剪内容 |
|------|-----------|
| 过程 | 增删/合并/调整过程 |
| 工件 | 选择工件形式（正式/非正式） |
| 工具 | 选择工具（看板/软件/表格） |
| 参与度 | 调整干系人参与深度 |
| 详细度 | 调整计划/文档的详细程度 |

## 常见裁剪模式

| 项目类型 | 推荐裁剪 |
|----------|----------|
| 大型合规项目 | 完整过程 + 正式工件 + 强制审计 |
| 中小型内部项目 | 精简过程 + 轻量工件 |
| 快速迭代产品 | 敏捷过程 + 用户故事 + 看板 |
| 紧急修复 | 最小过程 + 事后补文档 |

## 裁剪与绩效域的关系

裁剪决策影响所有 7 个绩效域：
- **规划**：详细程度取决于项目不确定性
- **交付**：验收标准的正式程度可裁剪
- **不确定性**：风险分析深度（定性 vs 定量）可裁剪

## 常见误区

| 误区 | 纠正 |
|------|------|
| 裁剪 = 省略 | 裁剪是有意选择，省略需记录理由 |
| 一次裁剪永久生效 | 裁剪需要定期审查和调整 |
| 团队单方决定 | 裁剪需要干系人共识 |
| 只减不增 | 有些项目需要额外过程（如安全审查） |

## 注意事项

- 裁剪决策应**记录在案**（谁裁了什么、为什么）
- 裁剪是渐进明细的——随着项目推进逐步细化
- 已发生的风险转为问题（Issue），进入问题日志
- 裁剪与 [processes.md](./processes.md) 的过程分组配套使用

## 适用场景

- ✅ 新项目启动时选择管理方法
- ✅ 项目特征变化时调整管理过程
- ✅ 大型/合规项目的过程取舍决策
- ❌ 已稳定运行的项目频繁改动（增加负担）
