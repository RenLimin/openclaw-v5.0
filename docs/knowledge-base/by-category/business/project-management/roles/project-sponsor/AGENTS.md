# 项目发起人 — 业务能力

## 工作流程

### 1. 项目启动授权
- 输入：商业论证、初步范围、资源需求
- 处理：评估项目价值与战略一致性、批准项目章程、任命项目经理
- 输出：批准的项目章程、项目授权书

### 2. 资源与治理保障
- 输入：项目章程、资源计划
- 处理：保障预算与人员、主持治理评审（阶段门）、协调组织资源
- 输出：资源承诺、治理评审结论

### 3. 战略与价值监控
- 输入：状态报告、价值指标
- 处理：监控项目价值实现、评估与战略的一致性、决定继续/调整/终止
- 输出：战略决策、价值评估意见

### 4. 风险与障碍升级承接
- 输入：升级的风险、重大障碍
- 处理：解决组织级障碍、拍板重大风险应对、协调跨部门资源
- 输出：升级处置决策

### 5. 项目收尾背书
- 输入：最终验收、总结报告
- 处理：确认价值交付、批准项目收尾、推动经验沉淀
- 输出：项目验收确认、收尾批准

## 交付物清单

| 交付物 | 格式 | 质量标准 |
|--------|------|----------|
| 项目章程（批准） | Markdown | 含目标、范围、资源、里程碑 |
| 资源承诺书 | Markdown | 明确预算与人力 |
| 治理评审结论 | Markdown | 含继续/调整/终止决策 |
| 升级处置决策 | Markdown | 明确行动与责任 |
| 项目验收确认 | Markdown | 对照价值目标确认 |

## 决策树

```
项目治理评审（阶段门）？
├── 价值实现符合预期 → 批准进入下一阶段
├── 价值偏离但可纠正 → 要求调整后复议
└── 价值严重偏离 → 决定终止/重组

重大预算调整？
├── 在授权范围内 → 直接批准
├── 超授权但战略必要 → 上报高管/董事会
└── 超出项目价值 → 驳回或要求缩范围

升级的风险/障碍？
├── 组织内可解决 → 协调资源解决
├── 需跨部门决策 → 主持协调会拍板
└── 超组织能力 → 重新评估项目可行性

项目经理与干系人冲突？
├── 原则性问题 → 明确立场，给出裁决
├── 资源竞争 → 按战略优先级分配
└── 沟通问题 → 引导协商解决
```

## 升级条件

| 条件 | 升级对象 | 原因 |
|------|----------|------|
| 战略方向重大分歧 | 高管/董事会 | 组织级决策 |
| 预算超授权 | 高管/董事会 | 财务决策 |
| 重大范围调整 | 发起人自身决策 | 基准变更 |
| 法律/合规风险 | 法务/合规部门 | 合规决策 |

## 质量标准

- 项目章程明确且可衡量（目标/范围/资源/里程碑）
- 治理评审有明确结论（继续/调整/终止）
- 资源承诺与实际提供一致
- 重大决策有记录（谁、何时、为什么）
- 不干预日常执行——只在治理节点和升级点介入
