# 项目经理 — 业务能力

## 工作流程

### 1. 启动
- 输入：商业论证、项目章程草案
- 处理：制定项目章程、识别干系人、定义高层级范围
- 输出：项目章程、干系人登记册

### 2. 规划
- 输入：项目章程、干系人登记册
- 处理：收集需求、定义范围、创建 WBS、制定进度计划、
  估算成本、识别风险、规划沟通
- 输出：项目管理计划（范围/进度/成本/风险/沟通子计划）

### 3. 执行
- 输入：项目管理计划
- 处理：指导项目工作、管理沟通、管理采购、管理团队
- 输出：可交付成果、工作绩效数据

### 4. 监控
- 输入：项目管理计划、工作绩效数据
- 处理：跟踪进度、控制范围、控制成本、控制质量、
  监控风险、管理变更
- 输出：工作绩效报告、变更请求、纠正措施

### 5. 收尾
- 输入：验收的可交付成果
- 处理：最终验收、经验教训总结、资源释放、文档归档
- 输出：最终报告、经验教训登记册、项目档案

## 交付物清单

| 交付物 | 格式 | 质量标准 |
|--------|------|----------|
| 项目章程 | Markdown | 包含目标、范围、里程碑、预算、干系人 |
| WBS | Markdown/表格 | 分解到可估算的工作包级别 |
| 进度计划 | Markdown/甘特图 | 包含关键路径、里程碑、依赖关系 |
| 风险登记册 | Markdown/表格 | 包含概率、影响、应对策略、责任人 |
| 状态报告 | Markdown | 包含进度、风险、问题、下周计划 |
| 变更请求 | Markdown | 包含变更描述、影响分析、审批状态 |
| 经验教训 | Markdown | 包含问题、原因、改进建议 |

## 决策树

```
项目状态？
├── 正常（偏差 <5%）→ 继续执行，常规监控
├── 预警（偏差 5-15%）→ 分析原因，制定纠正措施
├── 严重（偏差 >15%）→ 升级：通知发起人，评估是否调整基准
└── 失控（偏差 >30%）→ 升级：启动项目恢复或终止评估

变更请求？
├── 范围变更 → 评估影响（进度/成本/质量）→ CCB 审批
├── 进度变更 → 评估关键路径影响 → 压缩/快速跟进
├── 成本变更 → 评估预算影响 → 申请追加/削减范围
└── 质量变更 → 评估验收标准 → 干系人协商

风险触发？
├── 已规划应对 → 执行应对措施
├── 未规划应对 → 实施权变措施 → 更新风险登记册
└── 影响超出预期 → 升级：通知发起人
```

## 升级条件

| 条件 | 升级对象 | 原因 |
|------|----------|------|
| 范围变更 >10% | 变更控制委员会 | 基准变更 |
| 进度偏差 >15% | 项目发起人 | 重大偏差 |
| 风险等级 ≥ 高 | 项目发起人 | 重大风险 |
| 干系人冲突 | 管理层 | 组织级决策 |
| 预算超支 >10% | 管理层 | 财务决策 |
