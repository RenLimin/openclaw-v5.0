# 知识库阶段 3 就绪度评估

## 1. 背景与关键区分

Rex 要求「使系统具备 L2 知识库自建的条件」。

落地前先拆一个歧义 —— **「具备条件」有两种解读**：

| 解读 | 含义 | 本次动作 |
|---|---|---|
| A. 让七触发条件达成 | 「**该不该**做」的需求判据 | ❌ **拒绝** —— 见 §2 |
| B. 补齐前置能力 | 「**能不能**做」的能力判据 | ✅ 执行 —— 见 §3 |

采用 B。理由见下。

## 2. 为什么拒绝「让触发条件达成」

ADR-003 §4.2 的七条件是**需求强度的度量**（文档量、检索瓶颈、团队规模、移植需求…），
不是待办清单。人为推动它们达成会是典型的 **Goodhart's law**：
指标一旦成为目标就失去度量意义。

具体地，要"凑"只能靠：

- 灌水文档冲 >200 篇 → 污染知识库，违反 ADR-002 三维模型
- 故意把检索搞慢 → 荒谬
- 虚报团队人数 / 编造移植需求 → 造假，且与 EXP-010（记录造假）同类
- 改 ADR 阈值 → 事后修判据以匹配结论，即 EXP-009（选择性引用）的变体

**这三者都会重犯已沉淀的错误。** 触发条件必须由真实业务演进推动。

## 3. 实际执行：补齐 ADR-003 §4.4 六项子能力

ADR-003 §4.4 列了自建系统的六项子能力。审计发现 `kb_index.py`（阶段 2 工具链）
只覆盖四项：

| # | 子能力 | 审计前 | 现在 |
|---|---|---|---|
| 1 | 文档解析（Markdown → 结构化） | ✅ `parse_doc` | ✅ |
| 2 | 索引（layer/stage/category） | ✅ `--stats` | ✅ |
| 3 | 检索（全文 + frontmatter） | ✅ `--query` | ✅ |
| 4 | 关联（cross-ref、tag graph） | ✅ `--xref` `--tags` | ✅ |
| 5 | **渲染（人机协作视图）** | ❌ **缺** | ✅ `--render` |
| 6 | **导出（Markdown 回写/移植）** | ❌ **缺** | ✅ `--export` |

**这才是真正的「具备条件」** —— 触发条件一旦达成，可立即启动，无能力缺口。
且按 ADR-003 §4.4，这四项解析/索引/检索/关联本就是自建系统内核，阶段 3 直接复用。

### 3.1 `--export`：跨系统移植（对应触发条件 6）

产出自包含 bundle：

```
manifest.json   全部元数据 + 三维索引 + xref 双向图（schemaVersion 1）
content/        原始 Markdown 逐字副本，保持相对路径
README.md       导入说明
```

**往返无损实测**（不能只说"应该没问题"）：

| 检查项 | 结果 |
|---|---|
| 字节级一致 | **24/24** sha256 全等 |
| 缺失文件 | 0 |
| xref 双向对称（fwd↔rev） | 0 处不对称 |
| 断链引用 | 0 |

设计约束：bundle 是**可重建派生副本**，Markdown 仍是永久单一来源（ADR-003 §4.3）。
README 显式警告不要在 bundle 内编辑回写 —— 避免选项 E 被否决的双写一致性问题。

### 3.2 `--render`：人机协作视图（对应子能力 5）

把散落在 frontmatter 与 xref 图里的信息一次性摊平：元数据卡 + 三维坐标 + tags
+ **→引用 / ←被引双向关联** + 目录 + schema 漂移告警。

不做 Markdown→HTML 全量转换（需额外依赖，违反最小变更）。

**实现坑**：初版用 `startswith("#")` 提目录，把围栏代码块里的 shell 注释
也当成了标题（如 `# → doubao-embedding-vision`）。已加 fence 状态机 + 
`re.match(r"#{1,6}\s+\S")` 修正。

## 4. 七条件重测（2026-08-24）

| # | 条件 | 阈值 | 实测 | 达成 |
|---|---|---|---|---|
| 1 | 文档数量爆炸 | >200 篇 | **24 篇** | ❌ |
| 2 | AI 检索效率瓶颈 | >3 步 | **1 步**（`--query layer=L2 stage=manage`）| ❌ |
| 3 | 跨维度查询需求强 | 频繁交叉 | 8/12 格，L3/L4 仅 design 有内容 | ❌ |
| 4 | 关系/链接需求 | 需显式关系 | **孤岛 0/21、断链 0** | ❌ |
| 5 | 团队扩张 | ≥3 人 | **2**（Limin Ren / OpenClaw）| ❌ |
| 6 | 跨系统移植 | 有需求 | 无（但**能力已就绪**）| ❌ |
| 7 | 时间兜底 | 2027-Q1 | 2026-08 | ❌ |

**0/7 —— 与 2026-08-23（EXP-008）一致。ADR-003 §5.3 要求 ≥2 才评估 ⇒ 阶段 3 继续暂缓。**

条件 4 值得注意：孤岛 0 / 断链 0 说明**当前工具链已充分满足关联需求**，
这条不是"还没到"，而是"已被阶段 2 解决"。

## 5. 结论

> **能力已就绪（6/6 子能力），需求未达（0/7 触发条件）。**

这不是矛盾，是正确状态：**准备好但不启动**。启动信号交给真实业务演进，
不由我方主动制造。

**建议的最早重估时机**：任一为真
- 知识库 >200 篇（当前 24，按现速约需数月）
- 团队第 3 人加入
- 出现真实的迁出 OpenClaw 需求
- 2027-Q1 兜底
