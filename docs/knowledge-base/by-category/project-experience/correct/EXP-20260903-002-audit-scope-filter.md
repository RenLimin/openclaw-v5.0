# [EXP-20260903-002] 合同审核 scope 防误报：给审核规则加上"位置意识"

## 1. 背景

合同智能审核模块的核心机制是：将合同按条款标题拆分成段，然后对每个审核项（如"付款期限"、"违约责任"、"争议解决"）检查对应条款是否合规。

v1 实现采用**关键词全文匹配**：只要正文里出现审核项的关键词，就判定该条款命中审核规则。

## 2. 问题

**症状**：
- 审核报告中 P0 级风险有 **11 项**，但人工复核后发现大部分是误报
- 典型误报案例：
  - "付款节点清晰"这句话出现在**违约责任**段里，被"付款期限"审核项命中 → 误报
  - "争议解决方式为仲裁"出现在**其他约定**里，但关键词命中了 → 其实没问题
  - "期限"一词在很多条款都会出现（保密期限、服务期限、付款期限…）→ 大量误匹配

**用户体验**：
- 审核报告风险太多 → 用户不知道哪些是真问题
- "狼来了"效应 → 真正的风险反而被忽略
- P0 误报率 > 90% → 审核工具可信度严重受损

## 3. 根因

**根因**：`cat_kw`（分类关键词）太宽，缺少**位置约束**。

审核规则 v1 结构：
```json
{
  "audit_item": "付款期限",
  "keywords": ["付款", "期限", "支付"],
  "risk_condition": "未明确约定付款期限"
}
```

问题在于：
- "付款"、"期限"这些词在合同中**无处不在**
- 关键词只判断"有没有出现"，不判断"在什么位置出现"
- 全文搜索 → 只要上下文提过一次就命中，不管在哪个条款

本质：审核规则只有**内容意识**，没有**位置意识**。

## 4. 解决方案

### 方案：给每个审核标准增加 scope 字段

在审核规则中新增 `scope` 字段，指定该规则只在哪些条款标题内检查：

```json
{
  "audit_item": "付款期限",
  "scope": ["付款方式", "付款条款", "支付方式", "费用与支付"],
  "keywords": ["付款", "期限", "支付"],
  "risk_condition": "未明确约定付款期限"
}
```

**匹配逻辑**（伪代码）：
```python
def check_audit_item(contract_sections, audit_rule):
    for section in contract_sections:
        # 第一步：scope 过滤 — 只在指定条款标题内检查
        if not any(kw in section.title for kw in audit_rule.scope):
            continue
        # 第二步：关键词匹配 — 在 scope 限定的范围内做内容检查
        if matches_keywords(section.content, audit_rule.keywords):
            return evaluate_risk(section, audit_rule)
    return "未找到相关条款"  # 不在 scope 里 = 不检查，不是风险
```

**scope 关键词的设计原则**：
- 用**条款标题常用词**，不用正文内容词
- 可以有多个别名（"付款方式"、"支付条款" 都算）
- scope 宁可严不可宽 — 漏检比误报好（漏检是 conservative，误报会毁掉信任）

## 5. 效果

**实测数据**（2026-09-03，同一合同 3 份样本）：

| 指标 | 修复前 | 修复后 | 变化 |
|------|--------|--------|------|
| P0 级风险项 | 11 项 | 1 项 | ↓ 90.9% |
| P0 误报数 | 10 项 | 0 项 | 清零 |
| 真实风险漏检 | — | 0 项 | 无漏检 |
| 审核报告可读性 | 混乱 | 清晰 | 显著提升 |

**仅剩的 1 项 P0**：合同确实缺少"违约责任上限"约定 → **真实风险**，不是误报。

## 6. 教训与原则

**原则 1：审核规则要有"位置意识"，不是全文搜关键词**
- 合同是结构化文档（条款 → 子条款 → 内容）
- 审核规则必须尊重这个结构 — 在正确的位置检查正确的内容
- 全文关键词匹配是偷懒做法，在合同审核领域几乎一定会有高误报

**原则 2：误报比漏检更伤害产品信任**
- 漏检：用户觉得"工具不够全，还能补" → 可以接受
- 误报：用户觉得"工具不靠谱，说的都不对" → 直接弃用
- 所以 scope 宁可收窄，也不要放宽

**原则 3：审核项 = （位置 × 内容）的联合判定**
- 位置错了 → 内容再对也不算
- 这就像法律条文的"上下文解释"——脱离条款语境的关键词没有意义

**设计推广**：
- 不止合同审核，任何"在长文档中按规则找问题"的场景都适用
- 简历解析、财报审核、论文查重… 只要文档有结构，就要利用结构
- 关键词匹配是最后一步，前面必须有结构过滤
