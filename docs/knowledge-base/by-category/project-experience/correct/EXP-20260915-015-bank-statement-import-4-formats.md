# [EXP-20260915-015] 银行流水导入的 4 格式适配实战

## 1. 背景

手工记账是家庭理财的最大痛点。银行/支付平台都支持导出流水 CSV/Excel，但每家格式都不一样：
- 列名不同（"交易日期" vs "记账日期" vs "交易时间"）
- 金额格式不同（分正负号 / 收入支出分列 / 只有绝对值）
- 编码不同（UTF-8 / GBK / UTF-8 BOM）
- 表头位置不同（有的前面有好几行说明文字）
- 交易类型描述差异巨大

目标：一套导入框架，适配 4 种主流渠道（招行 / 工行 / 支付宝 / 微信），支持自动识别 + 智能分类。

## 2. 问题

1. 格式差异太大，每种都写一套解析逻辑维护成本高
2. 如何自动识别银行类型（用户不用手动选）
3. 如何对不同描述的交易做智能分类（餐饮 / 交通 / 购物...）
4. 如何去重（同一笔流水导入两次不重复记账）

## 3. 方案

### 3.1 模板驱动的解析架构

每种银行格式用一个 YAML 模板描述，解析器通用：

```yaml
# bank_templates/cmb.yaml (招商银行)
bank_code: cmb
bank_name: 招商银行
encoding: gbk
header_row: 6          # 前 6 行是表头说明，第 7 行才是列名
columns:
  date: "交易日期"
  amount: "金额"
  direction: "收支"
  counterparty: "交易对方"
  summary: "交易摘要"
  balance: "余额"
amount_sign:
  income: "收入"
  expense: "支出"
dedupe_key: "{date}_{amount}_{counterparty}_{summary}"
```

解析流程：
```
原始文件 → 编码检测 → 读取 (CSV/Excel) → 跳过表头 →
列名映射 → 金额规范化 → 去重检测 → 智能分类 → 入库
```

### 3.2 银行自动识别

三级识别策略（从快到慢）：

1. **文件名匹配**：`支付宝账单*.csv` → alipay；`微信支付账单*.csv` → wechat
2. **列名指纹匹配**：读前 20 行，提取列名集合，与模板列名集合取 Jaccard 相似度，>0.6 判匹配
3. **关键词匹配**：文件内容中搜索特征关键词（如"招商银行"、"微信支付"）

实测准确率：4 种格式 100% 正确识别。

### 3.3 智能分类引擎

三级分类器，优先级从高到低：

| 级别 | 方式 | 说明 | 置信度 |
|---|---|---|---|
| L1 | 精确规则 | 对方 = 美团 → 餐饮 | 高 |
| L2 | 关键字匹配 | 摘要含 "饿了么" → 餐饮 | 中 |
| L3 | 正则表达式 | 匹配 "滴滴.*出行" → 交通 | 中 |
| L4 | 默认规则 | 未匹配 → 未分类 | 低 |

规则同样用 YAML 配置，可扩展：

```yaml
rules:
  - id: food-001
    pattern: "美团|饿了么|麦当劳|肯德基"
    field: summary
    category: "餐饮美食"
    priority: 100
```

### 3.4 去重机制

去重键：`{日期}_{金额}_{对方}_{摘要}` 的 MD5 哈希

每次导入前：
1. 计算每条记录的 dedupe_key
2. 与数据库中已有交易比对
3. 标记为「新增 / 重复 / 错误」
4. 预览时让用户确认，只导入新增的

### 3.5 导入流程设计

```
上传文件 → 自动识别银行 → 预览结果
                              ↓
         显示统计（新增/重复/错误）+ 明细列表
                              ↓
         支持手动调整分类 → 确认导入 → 批量入库
```

## 4. 验证

- 4 种格式全部正确解析（招行 / 工行 / 支付宝 / 微信）
- 自动识别准确率 100%
- 智能分类覆盖率：高置信度 > 70%，中置信度 > 20%
- 重复导入零新增（去重机制有效）
- 支持 CSV 和 Excel（.xlsx/.xls）双格式

## 5. 教训

**为什么有效**：
1. **模板驱动**：新增银行格式只需要加一个 YAML 文件，不用改代码
2. **分层识别**：多级识别策略容错性好，某一级失败还有下一级
3. **预览确认**：让用户看到结果再确认导入，降低出错成本

**可推广条件**：
- 需要导入多种异构格式数据的系统
- 格式有规律但各不相同的场景
- 需要用户确认的批量数据导入

**踩过的坑**：
1. **编码坑**：支付宝 CSV 是 UTF-8 with BOM，招行是 GBK，微信是 UTF-8。必须先检测编码再读
2. **表头行坑**：各家前面的说明行数不一样，不能假设第一行就是列名
3. **金额格式坑**：有的用「收入/支出」两列，有的用正负号，有的只有绝对值加备注列。必须规范化
4. **数字格式坑**：金额里可能有千分位逗号、货币符号，要先清洗
5. **Excel 日期坑**：Excel 日期可能是序列号，也可能是字符串，需要判断
