# [ADR-202608-010] L2 知识库工具链组件

## 1. 状态
**accepted** — 2026-08-23 起生效

## 2. 背景

知识库自 2026-08-21 启动以来，采用 Markdown + frontmatter 形式承载（ADR-002、ADR-003）。
截至 2026-08-23，共有 20 篇文档、9 份 ADR、7 份 EXP 卡片。

一直存在却不可见的问题：
- **schema 漂移**：`layer`/`layers`、`kind`/`category`、`experience-card`/`experience` 混用
- **缺 stage 字段**：11/19 篇文档无 stage，三维查询静默漏掉它们
- **相对链接失效**：3 篇 ADR 引用了不存在的路径
- **无自动校验**：这些错误一直存在，但不需要工具无法发现

需要将知识库的**工具链层**（而非自建服务层）正式作为 L2 组件，纳入组件规范。

## 3. 考虑的选项

### 选项 A: 当作顺手脚本，不建组件（实际发生的情况）
- **优点**：零额外仪式
- **缺点**：
  - 绕过架构 §3.2 组件规范（已有 6 个组件都有 ADR + DESIGN.md + 实现）
  - 无组件契约，后续集成/演进无依据
  - 与架构文档矛盾的源头之一
- **评估**：❌ 已发生，需纠正

### 选项 B: 正式建为 L2 组件，补 ADR + DESIGN.md — **采用**
- **优点**：
  - 符合架构 §3.2 组件规范
  - DESIGN.md 明确契约边界（只读/可重建/不反向写）
  - 阶段 3 自建系统直接复用解析内核
- **缺点**：
  - 多写一份文档
- **评估**：✅ 采用

### 选项 C: 直接跳到阶段 3 自建系统
- **优点**：一步到位
- **缺点**：
  - 0/7 触发条件（见 EXP-20260823-008）
  - 内容缺口（L3/L4 develop/manage 全空）不是建系统能解决的
  - 自建系统前需要解析内核——正好是工具链
- **评估**：❌ 过早

## 4. 决策

**采用选项 B**：`scripts/kb_index.py` 正式作为 L2 知识库能力组件，补 ADR-010 + DESIGN.md。

### 4.1 组件边界

| 维度 | 值 |
|---|---|
| 是 | CLI 工具链（只读/可重建/幂等） |
| 不是 | 自建系统（服务形态：DB + Web 渲染） |
| 设计 | `components/knowledge-base/DESIGN.md` |
| 实现 | `scripts/kb_index.py` |
| 层级 | L2 基础设施层 |
| 验证 | pre-commit 第 3 段 |

### 4.2 与 ADR-003 的关系

ADR-003 定义了 3 阶段演进。本组件是**阶段 2 工具链**的交付物，不是阶段 3 自建系统。

工具链的自建系统解析内核会在阶段 3 直接复用。从现在起，知识库能力分为两个概念：

| 概念 | 状态 | 阶段 |
|---|---|---|
| 工具链层（CLI + Markdown 为源） | ✅ 已建成 (ADR-010) | 阶段 2 |
| 服务层（DB + Web 渲染） | ⏳ 暂缓（0/7 触发条件） | 阶段 3 |

### 4.3 组件规范检查

| 规范项 | 状态 |
|---|---|
| ADR | ✅ 本文件 |
| DESIGN.md | ✅ `components/knowledge-base/DESIGN.md` |
| 实现 | ✅ `scripts/kb_index.py` |
| 验证 | ✅ pre-commit 第 3 段实测通过 |
| 契约 | ✅ 只读/可重建/不反向写（除 INDEX.md 标记区） |
| 架构文档同步 | ✅ §3.2 组件表 + 四件套清单已更新 v0.7 |

## 5. 后果

### 5.1 正面
- 知识库工具链进入组件治理体系，有据可查
- 架构文档与实际对齐，不再自我矛盾
- 自建系统的解析内核已就绪

### 5.2 负面
- 无（三件套本就该有）

### 5.3 风险
| 风险 | 缓解 |
|---|---|
| 工具链与自建系统概念混淆 | 架构文档 §3.2 和 §6.3 均增加区分说明 |
| 工具链被当作"可以建自建系统了" | ADR-003 触发条件 0/7，EXP-008 明确暂缓 |
