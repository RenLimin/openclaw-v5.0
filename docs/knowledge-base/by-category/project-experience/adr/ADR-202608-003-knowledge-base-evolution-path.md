# [ADR-202608-003] 知识库承载形式演进路径决策

## 1. 状态
**accepted** — 2026-08-21 起生效

## 2. 背景

Rex 启动"综合开放平台"系统建设，明确：
- **核心目标**：人机协作阅读 + 跨系统移植
- **承载形式要求**：自建系统作为演进目标（不是外部 SaaS）
- **当前现实**：系统刚启动，L1 + L2 最小可用阶段，没有自建系统的工程能力

**已建立事实**（2026-08-21）：
- 知识库骨架已基于 **Markdown + frontmatter 元数据** 落地
- 三维模型（层级 × 阶段 × 类别）已被 ADR-002 接受
- 第一张经验卡片（EXP-20260821-001）已创建

**待决策问题**：
1. 知识库承载形式的**演进路径**是什么？
2. 何时从 Markdown 迁到自建系统？
3. 迁移时如何保证**不丢失历史知识**？
4. 自建系统应作为 **L2 基础设施** 还是 **L3 通用业务** 能力？

## 3. 考虑的选项

### 选项 A: 当前直接自建
- **思路**：跳过 Markdown 阶段，直接进入自建系统开发
- **优点**：
  - 一步到位
- **缺点**：
  - **过早投入**：当前 L2 还没最小可用，自建系统是 L2/L3 大工程
  - **没有验证内容**：自建系统的 schema 是从 ADR-002 三维模型推导的，但没经过实战检验
  - **价值密度低**：早期知识库内容少，复杂系统的 ROI 太低
- **评估**：❌ 过早

### 选项 B: 长期用 Markdown, 不自建
- **思路**：Markdown 永远够用，不需要自建
- **优点**：
  - 简单，git 友好
- **缺点**：
  - **缺乏结构化能力**：跨文档查询、关系分析、tag 聚合都靠文本搜索
  - **AI 检索效率低**：frontmatter 元数据虽存在但工具不丰富
  - **规模化困难**：超过 ~500 篇文档时检索会变慢
- **评估**：❌ 长期不可持续

### 选项 C: Markdown 先行, 阶段三自建（明确触发条件）— **采用**
- **思路**：分阶段演进，每个阶段有明确的**触发条件**
- **三阶段**：
  1. **阶段 1 (现在 - 2026-Q3)**: Markdown + frontmatter，沉淀内容、验证模型
  2. **阶段 2 (2026-Q4 - 2027-Q1)**: 增强 Markdown 工具链（索引、聚合、tag explorer），丰富内容
  3. **阶段 3 (2027-Q1+ 或触发条件达成)**: 自建系统，Markdown 作为导出格式保留
- **优点**：
  - ✅ **每个阶段 ROI 合理**：早期沉淀 > 工具投入
  - ✅ **触发条件明确**：不是"等到那天"，是"达到这些指标就启动"
  - ✅ **Markdown 永不过时**：作为导出格式永远保留
  - ✅ **风险可控**：自建系统失败不影响内容（Markdown 仍是单一来源）
- **缺点**：
  - 工具链需要多次切换（Markdown 工具 → 自建系统）
  - 阶段 3 的"自建"工作量是 L2/L3 大工程
- **缓解**：
  - 工具链切换时保留 Markdown 为导出格式
  - 阶段 3 启动前评估外部成熟方案（避免无谓自建）

### 选项 D: 引入外部知识库 SaaS (Notion/Obsidian/Affine 等)
- **思路**：用成熟外部工具
- **优点**：
  - 快速、功能完整
  - 不需要自己开发
- **缺点**：
  - **违反"自建系统作为演进目标"的核心目标**
  - 数据驻留问题（部分 SaaS 不友好）
  - 跨系统移植性差
  - 长期成本不可控
- **评估**：❌ 违反目标

### 选项 E: 用 Notion API + 本地 Markdown 镜像
- **思路**：外部工具 + 本地双写
- **优点**：
  - 兼顾外部工具体验 + 本地数据
- **缺点**：
  - 双写一致性复杂
  - 仍依赖外部
- **评估**：⏸️ 部分满足，但未到自建阶段

## 4. 决策

**采用选项 C：Markdown 先行 + 阶段三自建（明确触发条件）**。

### 4.1 阶段划分

| 阶段 | 时间 | 承载形式 | 目标 | 触发下一阶段 |
|---|---|---|---|---|
| **1. Markdown 验证期** | 2026-08 ~ 2026-Q3 | Markdown + frontmatter | 沉淀内容、验证三维模型 | 阶段 1 验收通过（≥ 1 个月，≥ 10 条知识）|
| **2. 工具链增强期** | 2026-Q4 ~ 2027-Q1 | Markdown + 索引工具 + 聚合器 | 提升检索效率、积累更多内容 | 阶段 2 验收通过 + 触发条件之一达成 |
| **3. 自建系统期** | 2027-Q1+（或触发条件）| 自建系统 + Markdown 导出 | 人机协作阅读、跨系统移植 | 持续运行 + 评估自建系统收益 |

### 4.2 阶段 3 启动的触发条件（满足任一即可启动评估）

| # | 条件 | 量化指标 |
|---|---|---|
| 1 | 文档数量爆炸 | 知识库 > 200 篇，Markdown 检索变慢 |
| 2 | AI agent 检索效率瓶颈 | agent 完成"找特定知识"任务 > 3 步 |
| 3 | 跨维度查询需求强 | 需要频繁的"层级 × 阶段 × 类别"交叉查询 |
| 4 | 关系/链接需求 | 知识条目之间需要显式关系（不只是文本）|
| 5 | 团队扩张 | 团队人数 ≥ 3，协作需要结构化 |
| 6 | 跨系统移植需求 | 需要把知识库迁出 OpenClaw 到另一系统 |
| 7 | 时间 | 2027-Q1（兜底时间，即使前 6 个未达成）|

### 4.3 迁移策略

**核心原则**：Markdown 是**永久单一来源**，自建系统是**可重建的索引/视图**。

```
Markdown 文件 (源, 永久)
  ↓ 索引/解析
自建系统 (索引, 可重建)
  ↓ 导出
Markdown (回到源, 无损)
```

**具体规则**：
1. **不直接编辑自建系统**：所有内容修改都在 Markdown 完成
2. **自建系统从 Markdown 重建**：全量或增量 reindex
3. **自建系统可有元数据派生**（如 cross-reference、tag cloud），但**不能反过来定义内容**
4. **导出格式 = Markdown**：跨系统迁移时直接复制 Markdown 目录
5. **自建系统的 schema 直接对应 3 维模型**（layer × stage × category），不引入新维度

### 4.4 自建系统的层级归属

**自建系统是 L2 基础设施层能力**，**不是 L3 业务层**。

理由：
- L2 基础设施 = 通用能力，跨业务可用
- L3 通用业务 = 按业务维度切分（user/order/...）
- 知识库不是"业务维度"，是"系统建设基础设施"
- 放在 L2 方便 L3/L4 都可使用（不只是某个业务模块）

**具体子能力**：
- 文档解析（Markdown → 结构化数据）
- 索引（按 layer / stage / category）
- 检索（全文 + frontmatter 元数据）
- 关联（cross-reference、tag graph）
- 渲染（人机协作视图）
- 导出（Markdown 回写）

## 5. 后果

### 5.1 正面
- **早期投入低**：Markdown 是最经济的承载形式
- **数据永久可读**：Markdown 不会过时，git 友好
- **跨系统可移植**：直接复制目录即可
- **风险可控**：自建系统失败不影响内容
- **演进路径清晰**：3 阶段 + 7 触发条件，避免"永久 Markdown 党"或"过早自建派"

### 5.2 负面
- **阶段 1 检索能力有限**：纯文本搜索，frontmatter 元数据靠 grep / IDE
- **阶段 2 工具链是临时方案**：用脚本/Python 增强，不会是大系统
- **阶段 3 自建系统是 L2 大工程**：需要单独排期，资源消耗
- **自建系统对 Rex 一人全职是挑战**：可能需要外部分工或招聘

### 5.3 风险
| 风险 | 缓解 |
|---|---|
| 阶段 2 工具链维护成本失控 | 控制复杂度（脚本而非系统），每个工具都有 README 解释价值 |
| 阶段 3 启动过早 | 7 个触发条件中至少 2 个才评估 |
| 阶段 3 启动过晚 | 时间兜底（2027-Q1）|
| Markdown 内容质量参差 | frontmatter 模板强制 + 定期审查 |
| 自建系统变成"另一个 Notion" | 明确自建系统是 L2 基础设施而非通用工具 |
| 团队扩张后 Markdown 不便协作 | 阶段 3 启动条件 #5（团队 ≥ 3）|

### 阶段 2: 工具链增强期
- [ ] **2026-Q4**: 评估"tag explorer" 工具（按 tag/标签聚合展示）
- [ ] **2026-Q4**: 评估"cross-reference"工具（自动发现文档间引用）

### 阶段 3: 自建系统期
- [ ] **触发时**: 评估外部方案（避免无谓自建）
- [ ] **触发时**: 架构设计（基于 3 维模型 schema）
- [ ] **触发时**: MVP 实现
- [ ] **触发时**: 从 Markdown 迁移内容（无损）
- [ ] **触发时**: 切换到自建系统（Markdown 仍保留为导出格式）

## 7. 验证标准

### 阶段 1 验收（1 个月后，2026-09-21）
- 知识库 ≥ 10 条
- 3 维模型使用无混乱
- 至少 3 个不同类别（业界/理论/经验）有内容
- 至少 1 个 ADR 触发升级

### 阶段 2 验收（6 个月后，2027-Q1）
- 知识库 ≥ 30 条
- 工具链（如 tag explorer）使用率 ≥ 50%
- 至少 2 个 trigger 条件接近达成

### 阶段 3 启动评估（2027-Q1 或触发时）
- 7 触发条件至少 2 个满足
- 自建系统 ROI 分析完成
- 外部方案评估完成
