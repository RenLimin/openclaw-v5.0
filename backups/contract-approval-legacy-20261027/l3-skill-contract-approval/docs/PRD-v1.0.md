## 1. 背景与目标

### 1.1 业务背景

销售合同审批是 Bangcle 交付业务的关键流程。此前痛点：

1. **纯人工审核**：合同逐条人工比对《民法典》合同编，耗时且易漏
2. **无审计追踪**：审批过程无结构化记录，事后无法回溯
3. **扫描件难处理**：纸质合同需人工录入后才能审核
4. **分级标准不统一**：不同金额的合同审批层级靠口头约定

### 1.2 产品目标

1. **起草→审批→签署→归档全流程数字化**，状态机强制流转
2. **风险自动扫描**：基于《民法典》合同编 22 条规则，输出结构化风险报告
3. **分级审批**：按金额四级分级（<10万/10-50万/50-200万/>200万）
4. **全程审计**：所有操作写审计日志，不可跳过
5. **扫描件 OCR 接入**：复用 L2 OCR-001，扫描合同直接进审核流水线

## 2. 功能清单

### 2.1 核心功能

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1 | 合同起草 | 创建合同元数据（甲乙方/金额/类型/日期），生成合同编号 | P0 |
| F2 | 审批状态机 | draft→review1→review2→review3→approved→signed→archived，驳回回 draft | P0 |
| F3 | 分级审批 | 按金额自动映射审批层级（4级）与角色 | P0 |
| F4 | 风险扫描 | 22 条《民法典》规则扫描合同文本，输出 P0-P2 分级风险报告 | P0 |
| F5 | 审计日志 | 全操作留痕（操作人/动作/状态变迁/时间/详情） | P0 |
| F6 | 合同生成 | 按 docx 模板生成正式合同文档，金额大小写自动校验 | P1 |
| F7 | 扫描件 OCR | 调用 L2 OCR-001 识别扫描合同 → 进入审核 | P1 |
| F8 | Excel 审批报告 | 审批分析报告（顶部摘要+颜色标注+P0-P2 风险分级+整改建议） | P1 |
| F9 | 逐条审核 | 43 项审核标准、17 类别逐条审计（v3.1 三件套） | P2 |

### 2.2 用户角色

| 角色 | 职责 | 对应审批层级 |
|---|---|---|
| 起草人 | 创建合同、提交审批 | — |
| 业务主管 | 一级审批 | review1 |
| 部门经理 | 二级审批（≥10万） | review2 |
| 总监/法务 | 三级审批（≥50万） | review3 |
| 签署人 | 签署已批准合同 | sign |
| 归档人 | 归档已签署合同 | archive |

### 2.3 验收标准

1. ✅ 状态机流转 100% 符合规则（非法流转被拒绝并报错）
2. ✅ 驳回后合同回到 draft，可重新提交
3. ✅ 22 条风险规则全部可触发、可输出结构化报告
4. ✅ 审计日志完整覆盖所有状态变迁
5. ✅ 金额大小写校验（不一致时生成失败）
6. ✅ L3 core 零副作用（无 DB/文件/网络），可独立单测
7. ✅ L4 持久化层全部测试通过（25/25 e2e + 58 pytest）

## 3. 非功能需求

| 项 | 要求 |
|---|---|
| 层级契约 | L3 core 不 import L4 / 不操作 DB / 不做网络请求 |
| 可移植性 | L3 纯逻辑可被任意 L4 实例复用（依赖注入 level_table） |
| 审计不可绕过 | 所有状态变迁必写审计日志（Hard Rule） |
| 风险扫描定位 | 辅助提醒，非法务专业判断（免责声明） |
| 数据安全 | 合同数据本地 SQLite，不上外网 |
