# Bangcle 项目复盘建议技能

> 目标：在**真实交付数据**之上，回答两件事——
> 1. 我们交付的产品/服务与**标准产品/服务**差在哪、怎么优化；
> 2. 按 **PMBOK** 复盘项目管理的可优化空间，并给出可执行、有责任方的建议。

## When to Use

- 用户要求项目复盘 / 经验教训 / lessons learned / retrospective
- 分析实际交付与标准产品/服务的差异、定制成本、产品化机会
- 识别重复 POC、长期未签约、需求后置、无验收等管理问题并给整改建议

## 前置

- 先跑 `bangcle-project-summary` 得到可信台账；复盘**不重新猜数据**。
- 标准基线来自 `product-kb`（产品/服务目录、白皮书、部署/运维文档）。

## Hard Rules

1. 每个结论必须挂证据（ONES 字段/工时/评论 或 Product KB 条目），无证据标【缺失】。
2. 建议必须落到 **责任方 + 动作**，不写空泛的"加强管理"。
3. 区分**产品问题**与**项目管理问题**，不混为一谈。
4. 对外副作用（推动制度/通知客户）仅建议，不自动执行。

## Workflow

### Step 1 — 客户级 Program 诊断
- 统计同客户 POC 次数、跨产品线数、是否签约、累计投入 vs 预期规模。
- 触发信号：同客户 12 个月内 ≥2 个同类 POC / 长期 0 签约 / 多份重复履约项。
- **完成判据**：给出"是否需要客户级项目集治理"的明确判断。
- 落地动作见 `references/program-playbook.md`。

### Step 2 — 产品/服务 vs 标准基线差异分析
- 从 Product KB 取对应标准产品与付费服务（如：本地部署、组件定制适配、定制化实施、数据运营高级服务、驻场外包）。
- 逐维度对比：版本命名、CPU/OS（信创/ARM）、中间件/数据库、容器/云、数据运营、授权模块。
- 判断每处差异性质：产品缺口 / 兼容性缺口 / 隐性成本（本应收费却在 POC 白送）/ 一致。
- **完成判据**：差异表每行含 实际情况 / 标准基线 / 性质 / 优化空间。

### Step 3 — PMBOK 管理复盘
- 按 `references/pmbok-checklist.md` 逐知识域核查（整合/范围/需求/进度/相关方/风险/资源/质量收尾/知识）。
- 每域写：问题（带证据）→ PMBOK 要求 → 改进建议（责任方）。
- **完成判据**：至少覆盖有证据的知识域；无证据不强凑。

### Step 4 — 输出复盘报告
- 结构：客户全景 → 交付与反馈 → 产品差异与优化 → PMBOK 复盘 → 三句话结论。
- 落盘 `analysis_output/<客户>项目复盘报告-vN.md`，证据用【已验证/推断/缺失】分级。
- **完成判据**：每条建议可执行、有责任方、可在下次立项/复盘中检查。

## 核心框架速记

- 六层分析模型：客户 → 项目集(Program) → 产品 → 工作项 → 交付物 → 团队反馈。
- 复盘双轴：**产品轴**（对标标准基线）× **管理轴**（对标 PMBOK）。
- 经验教训格式（业界最佳实践）：Issue（问题）/ Root cause（根因）/ Impact（影响）/ Recommendation（建议）/ Owner（责任方）。

- [ ] 每个结论有证据或标【缺失】
- [ ] 产品问题与管理问题分开
- [ ] 每条建议含责任方与可检查动作
- [ ] Program 触发信号有量化依据
