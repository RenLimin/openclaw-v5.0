# PMBOK 复盘核查清单（Bangcle 交付场景裁剪）

> 每域：问题（证据）→ PMBOK 要求 → 建议（责任方）。仅就有证据项展开。

| 知识域 | 高频问题信号（在 ONES/交付中怎么发现） | 整改方向 / 责任方 |
|---|---|---|
| 整合/范围 | 同客户多次重复 POC、多份重复履约义务、无客户级统筹 | 设客户级 Program + 统一 WBS；商务+PMO |
| 需求 | 已开始部署却仍处于"需求收集中"；需求文档晚于执行 | 立项门禁：需求基线+成功标准客户签字；售前 |
| 进度 | 只有计划日期、无实际完成时间，算不出 SPI | 强制填实际起止；PM |
| 成本 | 信创/云适配工时在 POC 无偿消耗 | 适配清单前置报价，计入签约成本；商务 |
| 相关方 | 评审会上才出现价格/立场分歧（如反对低价） | 立项即拉商务/产研/财务立场对齐；商务 |
| 风险 | ARM/信创/云中间件兼容风险临近实施才暴露 | 信创/云做成标准风险登记册与预案；PM/产研 |
| 资源 | owner 为"管理员"占位，真实执行人靠工时反推 | 任务必须指派真人，建 RAM 责任矩阵；PM |
| 质量/收尾 | 状态直接"已完成"，无测试/验收报告与客户签字 | 收尾门禁：测试报告+验收签字+交付物台账；PMO |
| 知识 | 文档散落附件、工程 Tag 缺失、无经验教训 | 建交付物/Tag 台账，复盘回写知识库；PMO |

## 经验教训记录格式

Issue / Root cause / Impact / Recommendation / Owner（来源：PMBOK 经验教训登记册 + IT 项目复盘业界实践）。
