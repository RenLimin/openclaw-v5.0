# 项目集复盘证据化作业手册（防幻觉）

> 来源：2026-11-16 山盟（山东省城商行联盟）项目集复盘实战沉淀。
> 配套：`program-playbook.md`（项目集治理）、`pmbok-checklist.md`（9 域核查）。
> 用途：把"客户现场抱怨"逐条转成 ONES/OA 可验证数据，再产出复盘与制度，避免凭印象写。

## 0. 铁律：三档证据，禁止混用

| 档位 | 写法 | 要求 |
|---|---|---|
| 已验证 | `【已验证 YYYY-MM-DD｜来源】` | 必须能指到系统字段/导出文件+取数日期 |
| 推断 | `【推断】…（据…推导）` | 必须就近写推导依据，不得裸推断 |
| 缺失 | `【缺失】` | 明说未取到，禁止用印象补齐 |

- 客户原声 = 问题线索，**不是结论**；结论必须回落到系统数据。
- 交付前过 `L2-infra/prompts/tools/check_answer_contract.py`（fail-closed），报告型必须含信封 F1–F5 + 溯源链 + 质量信号。

## 1. 取数清单（按序，全部要落盘原始文件）

1. **合同面**：OA 销售合同台账导出（cube customid=179）→ 合同数/金额/标的/服务期。
   - 权威口径：合同条款以 OA 合同正文为准，金额/编号以台账为准。
2. **项目面**：ONES GraphQL `tasks_by_project_nested.json`（按客户关键词全量项目）。
3. **义务面**：筛 `issueType=项目履约义务`，逐条取 `statusCategory/planStartDate/planEndDate/owner`。
4. **现场面**：客户沟通记录原文（问题清单 + 客户要求的优化方向）。

## 2. 必算的 6 个量化指标（本次实证）

| 指标 | 算法 | 山盟实测 | 说明 |
|---|---|---|---|
| POC 占比 | POC/提前实施项目数 ÷ 项目总数 | 31/43 = 72% | 触发 Program 治理（≥2 同类 POC/12 月） |
| 计划日期完整率 | 有 planEndDate 义务 ÷ 义务总数 | 73/388 = 19% | 直接决定"进度能否预警" |
| 在途无计划率 | 未完成且无 planEndDate ÷ 未完成 | 110/113 = 97% | 客户"时点无反馈"的数据实锤 |
| 占位 owner 率 | owner=管理员/占位 ÷ 未完成 | 63/113 = 56% | 责任虚化，单点风险 |
| 无合同归属率 | 无合同依据义务 ÷ 义务总数 | 120/388 = 31% | 投入与签约脱节 |
| 脏数据 | planEndDate=1970 等零值计数 | 3 条 | 字段录入质量，须清理 |

> 注意：`statusCategory=done` 的完成率会被历史结项义务抬高（山盟 71%），**不可当作在途健康度**，须与"在途无计划率"并列看。

## 3. 双轴复盘结构（照此产出）

- **产品轴**：实际情况 vs 标准基线 → 差异性质（质量/兼容性/专业度/流程）→ 优化建议。标准基线须调 product-kb 核实，未调取标【缺失】。
- **管理轴**：PMBOK 十域逐域 `Issue → Root cause → Impact → Recommendation → Owner`，每条挂证据档位。
- **改进项**：短期(0–4 周)/中期(1–3 月)/长期(3 月+)，每条带责任方+时限+验收点。

## 6. 常见坑（本次踩过）

- ONES GraphQL 不支持 `totalCount/nodes`（报 `Malformed.GraphQL`）。
- `planEndDate=1970` 是零值脏数据，不是真逾期，统计时必须排除或单列。
- 项目全表（19617 行）是全公司的，须按客户关键词过滤，别当本客户项目数。
- 沙箱工作区 ≠ 真实工作区（`/Users/bangcle/Bangcle Workspace`），交付物落真实工作区。
- 共享 git index 会被其他会话回退/污染：提交一律用隔离 index（`GIT_INDEX_FILE` + `read-tree` + `commit-tree` + `update-ref`），提交后 `git show --stat HEAD` 核对。
