## 1. 背景与问题

v1.0 的 `contract_parser._extract_party_info` 对地址/邮箱/开户行/账号采用
「全文首个匹配」赋值，且甲乙方共用同一套规则 → **同一值被复制给双方**。

真实样本回归（OA workflowid=757 单据 `886377`，合同原文）：

```
party_a = {'name': '海通恒信…', 'address': '全包装产品：中国上海市黄浦区中山南路599号…',
           'email': '向huijuan.lin@bangcle.com',
           'bank': '上海银行股份有限公司北京海淀支行', 'account': '03005302039'}
party_b = 同上（完全相同）
```

合同事实：地址在 2.3 条（乙方指定账户语境）、开户行/账号属**乙方**，
却同时出现在甲方字段；L4 侧只能「标注疑似串用」无法纠正（L4→L3 反向依赖禁止）。

## 2. 目标

1. 主体信息抽取**按方归属**：地址/电话/联系人等双列表格按列分配，单列字段按最近标签距离分配；
2. **缺失优于错误**：无法归属时留空，绝不跨方复制；
3. 不改变公开 API 签名与既有调用面（向后兼容）。

## 3. 功能清单（v1.1 变更）

| # | 变更 | 说明 |
|---|---|---|
| F1 | 双列表格行按列归属 | `需方/供方` 行定名称；同名字段两列（地址/邮编/电话/联系人）按列序分配 |
| F2 | 单列字段最近距离归属 | 与「本方别名（甲方/需方 或 乙方/供方）」最近提及距离；与他方并列时**不归属** |
| F3 | 值卫生过滤 | 地址值含「电子邮箱」等串行 OCR 脏值丢弃；邮箱剥离中文前缀 |
| F4 | 距离阈值 | 距本方 >8 行不采信（防止把正文中偶然出现的信息当主体） |

## 4. 验收标准

| AC | 标准 | 验证手段 |
|---|---|---|
| AC-9a | 双列表格样本甲乙方地址/电话互不相同且分属正确 | `tests/test_party_extraction.py` |
| AC-9b | 单列字段按最近标签归属 | 同上 |
| AC-9c | 只出现一个地址且贴近甲方时，乙方地址缺失而非复制 | 同上 |
| AC-9d | 真实样本 886377：甲乙方地址不同、银行仅属乙方、邮箱无前缀 | 同上 |
| AC-9e | `parse_contract(text)` 签名不变（AC-1 契约稳定） | 同上 |
| AC-9f | L3 全量测试通过（原 115 + 新增 7 = 122） | `pytest tests/` |

## 5. 非目标（明确不做）

- 不改 `Contract.party_a/party_b`（那是**字符串**字段，模型层冻结）；
- 不做印章/签名检测（属 L4/L2 OCR 职责，见 v1.0 §7）；
- 不引入 LLM/NER 模型，保持纯 stdlib + 正则（L3 零副作用约束）。
