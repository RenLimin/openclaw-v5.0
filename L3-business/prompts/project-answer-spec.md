## 1. 触发意图 → 固定输出维度（缺一即不合格）

### 1.1 项目汇总（project-summary）
| 必含维度 | 说明 |
|---|---|
| 客户实体清单 | 含多实体映射（见 P1 §5） |
| 项目清单 | 编号/类型(POC/提前实施/签约)/立项日期/状态 |
| 任务量统计 | 总数/完成/进行/未开始 + 完成率 |
| 履约义务结构 | 按业务线分组（产品线/服务类型） |
| 交付物清单 | 每个项目主要交付物 |
| 内部研发支撑 | 非客户项目但承载该客户定制研发的列明 |
| 落盘 | `analysis_output/` 台账 + 报告 |

### 1.2 进度与风险（progress-risk）
| 必含维度 | 说明 |
|---|---|
| 总体进度 | 完成率 + 分项目进度表 |
| 逾期清单 | 每项含：计划完成日/逾期天数/状态/事项（按逾期时长降序） |
| 无计划任务 | 未完成且无计划日期的项数 + 分布 |
| 当前版本/活跃交付 | 正在交付的版本任务集群状态 |
| 责任人负载 | 未完成任务按责任人分布（识别单点） |
| 缺陷 | 数量/状态/热点模块 |
| 风险定级矩阵 | 🔴🟡🟢 + 行动项 + 时限（见 P1 §6） |

### 1.3 履约义务（obligation-summary）
必含：按产线/状态罗列履约义务 → 下钻子工作项 → 授权/维保到期日期 → 对照历史交付。

### 1.4 复盘（retrospective）
必含：产品/服务 vs 标准基线差异 → PMBOK 管理复盘 → 改进项 + 责任方 + 时限。

### 1.5 客户画像（customer-profile）
必含：客户环境/客户要求/定制要求/安全等级/安全需求 五维度（已有，保持）。

## 2. 项目域风险定级矩阵（P1 §6 补充）

| 级 | 项目域具体判定 |
|---|---|
| 🔴 | 逾期 > 30 天 / 当前版本交付断档（到期未开始）/ 合同-项目映射空档 / 单点依赖（>50% 未完成项一人） |
| 🟡 | 逾期 < 30 天 / 无计划任务 > 10 / 状态失真（高讨论未开始）/ 外包依赖未到位 |
| 🟢 | 收尾残留 / 口径提示 |

## 2.5 维度合格判据（交付前自检 checklist，任一 NO 即重做）

| 维度类 | 合格判据（必须全部 YES） |
|---|---|
| 实体/项目清单 | ① 多实体已分别列示并映射 ② 每个项目编号/类型/状态字段非空 ③ 实体名来自实时系统非 memory |
| 任务量统计 | ④ 总数=完成+进行+未开始 可对账 ⑤ 完成率算法标注口径(done/总数) ⑥ 数字带【已验证 日期\|ONES】 |
| 逾期清单 | ⑦ 每项含计划完成日+逾期天数+当前状态 ⑧ 按逾期时长降序 ⑨ 逾期天数用当日日期实算非引用旧值 |
| 无计划任务 | ⑩ 仅统计「未完成 且 无计划日期」 ⑪ 给出项数+责任人分布 |
| 责任人负载 | ⑫ 未完成项按人聚合 ⑬ 单点(>50%)触发🔴并写明百分比 |
| 缺陷 | ⑭ 数量+状态(开/关)+热点模块；全部关闭也要显式说明 |
| 风险定级 | ⑮ 每条🔴🟡附行动项+时限+责任方 ⑯ 定级可回溯到上面某条判据 |
| 溯源/落盘 | ⑰ 落盘含数据源→查询→结论链(P1 §4.5) ⑱ 降级/过期数据有质量信号标注 |

## 3. 状态口径约定

- 状态分类统一用 ONES statusCategory：`done / in_progress / to_do`，完成率 = done / 总数。
- 「已完成」按 ONES 状态字段原文（已完成/测试通过/冒烟测试中等）展示，不自行归一，标注口径。
- 讨论数/附件数只作参考信号，**不当作进度依据**（茅台教训：#368925 讨论 50 条但未开始）。
