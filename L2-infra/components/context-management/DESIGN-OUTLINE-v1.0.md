## 1. 定位

context-management 属于 L2 基础设施层，为 L3/L4 提供基础服务。

## 2. 架构设计

### 2.1 整体架构
现有两层防护体系基础上，增加**第三层阶梯式自动恢复层**：
- 第一层：Auto-compaction（safeguard 模式）→ 达到 WARN 阈值自动触发
- 第二层：Mid-turn precheck → 上下文溢出后中止，进入恢复流程
- 第三层：阶梯式尝试 → 按 `/compact` → `/reset` → `/new` 顺序自动尝试，每次尝试后检查阈值，直到回到安全水位

### 2.2 模块划分

- 核心模块：提供主要服务能力
- 接口模块：对外暴露稳定契约
- 配置模块：管理组件配置

## 6. 新增功能设计

### 6.1 阶梯式恢复流程
触发条件：当自动压缩失效，收到提示 `⚠️ Context is too large and auto-compaction could not recover this turn`

恢复步骤：
```
1. 执行 `/compact` → 等待压缩完成 → 检查上下文水位
2. 如果仍超阈值 → 执行 `/reset` → 等待清理完成 → 检查上下文水位
3. 如果仍超阈值 → 执行 `/new` → 启动新会话，恢复工作进度
```

### 6.2 规范文档对齐
- AGENTS.md「上下文过大处理流程」与设计一致
- 设计文档更新后文档保持一致

### 6.3 验收标准
- 任一阶段成功压缩到安全水位即停止
- 新会话会自动重新加载必要上下文，token 回到安全水位
- 工作进度不丢失
