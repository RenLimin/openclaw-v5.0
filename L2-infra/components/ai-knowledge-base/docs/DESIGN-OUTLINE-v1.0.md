## 1. 设计原则

### 1.1 核心原则

1. **Agent 无关**：知识库是独立基础设施，不是 Agent 的一部分。所有功能通过标准协议对外暴露，不绑定任何 Agent 框架。
2. **可插拔架构**：核心组件（Embedding、向量存储、LLM、数据库、解析器）均通过统一接口抽象，可灵活替换。
3. **分层清晰**：严格的分层架构，层间只通过接口交互，便于独立演进和替换。
4. **数据驱动**：所有知识以结构化数据存储，不依赖任何特定的运行时环境。
5. **安全优先**：三层风险防护贯穿全链路，不是事后补丁。
6. **模板化构建**：知识库实例通过配置模板生成，支持快速复制和定制。

### 1.2 设计约束

- 单机起步：SQLite + 本地 Embedding，无需外部依赖即可运行
- 平滑升级：可从单机版无缝升级到集群版，数据迁移成本最低
- 向后兼容：已有知识库实例不受升级影响，支持在线迁移
- 最小依赖：核心运行时仅依赖 Python 标准库 + SQLite，可选组件按需加载

## 2. 整体架构

### 2.1 分层架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    接入层 (Interface Layer)                 │
│  REST API  │  MCP Server  │  CLI  │  Python SDK            │
├─────────────────────────────────────────────────────────────┤
│                  服务编排层 (Service Layer)                  │
│  知识库管理  │  检索服务  │  反馈服务  │  审核服务  │  模板服务 │
├─────────────────────────────────────────────────────────────┤
│                   检索增强层 (Retrieval Layer)              │
│  多路召回  │  融合排序  │  重排序  │  查询改写  │  上下文压缩 │
├─────────────────────────────────────────────────────────────┤
│                  知识组织层 (Knowledge Layer)                │
│  实体管理  │  文档管理  │  知识图谱  │  版本管理  │  权限控制 │
├─────────────────────────────────────────────────────────────┤
│                   文档接入层 (Ingestion Layer)              │
│  格式解析  │  智能切片  │  向量化  │  实体抽取  │  质量检测 │
├─────────────────────────────────────────────────────────────┤
│                   风险防护层 (Security Layer)               │
│  输入防护  │  检索防护  │  输出防护  │  审计日志  │  降级策略 │
├─────────────────────────────────────────────────────────────┤
│                    存储层 (Storage Layer)                    │
│  关系数据库  │  向量索引  │  FTS 全文索引  │  对象存储(可选) │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 模块职责

| 层级 | 模块 | 核心职责 |
|---|---|---|
| 接入层 | REST API / MCP Server / CLI / SDK | 对外暴露标准接口，协议转换 |
| 服务编排层 | 管理/检索/反馈/审核/模板服务 | 业务逻辑编排，事务协调 |
| 检索增强层 | 多路召回/融合/重排/改写/压缩 | 检索质量优化，RAG 增强 |
| 知识组织层 | 实体/文档/图谱/版本/权限 | 知识的结构化组织和治理 |
| 文档接入层 | 解析/切片/向量化/抽取/质检 | 原始文档 → 结构化知识 |
| 风险防护层 | 输入/检索/输出防护/审计/降级 | 全链路风险管控 |
| 存储层 | 关系库/向量库/FTS/对象存储 | 数据持久化和索引 |

## 4. 数据流

### 4.1 文档接入数据流

```
原始文档
    ↓
格式识别 → 解析器调度 → 文本提取
    ↓
质量检测 → PII 检测 → 脱敏处理
    ↓
智能切片 → 元数据提取 → 实体识别 → 关系抽取
    ↓
向量化 → 索引构建
    ↓
入库（实体 + 文档 + 切片 + 关系 + FTS索引 + 向量索引）
    ↓
版本记录 + 审计日志
```

### 4.2 查询应答数据流

```
用户问题
    ↓
查询改写（扩展/分解/纠错）
    ↓
多路召回（实体精确匹配 + FTS关键词 + 向量相似度 + 图谱扩展）
    ↓
融合排序（去重 + 综合打分 + 权限过滤 + 过期过滤）
    ↓
重排序（交叉编码器精排）→ 上下文压缩
    ↓
风险校验（注入检测 + 一致性校验 + 权限二次校验 + 脱敏）
    ↓
组装答案上下文 → 返回给 LLM 或调用方
    ↓
答案生成（可选，调用方负责）→ 来源归因
    ↓
审计日志 + 查询统计
```

### 4.3 反馈迭代数据流

```
用户反馈
    ↓
反馈入库（关联查询+来源+用户）
    ↓
反馈统计 → 低质量识别 → 审核队列
    ↓
管理员审核
    ├─ 确认问题 → 标记知识状态（过期/错误/待修正）
    ├─ 需要更新 → 触发知识更新流程
    └─ 误报 → 忽略 + 记录
    ↓
质量重评 → 检索权重调整
```

## 5. 部署架构

### 5.1 单机部署（开发/小型场景）

```
┌─────────────────────────────────┐
│        AI KB Service            │
│  ┌─────────┐  ┌──────────────┐ │
│  │  API    │  │  Ingestion   │ │
│  └─────────┘  └──────────────┘ │
│  ┌──────────────────────────┐  │
│  │  SQLite (数据+FTS+向量)   │  │
│  └──────────────────────────┘  │
│  ┌──────────────────────────┐  │
│  │  本地 Embedding 模型      │  │
│  └──────────────────────────┘  │
└─────────────────────────────────┘
```

**适用场景**：开发测试、小型团队、单领域知识库
**优势**：零外部依赖，一键启动，资源占用低

### 5.2 生产部署（中大型场景）

```
┌─────────────┐    ┌─────────────┐
│  Load       │    │  对象存储    │
│  Balancer   │    │  (原始文档)  │
└──────┬──────┘    └──────┬──────┘
       │                  │
┌──────▼──────────────────▼───────┐
│     API Service (无状态，可水平扩展) │
└──────┬──────────────────┬───────┘
       │                  │
┌──────▼──────┐    ┌──────▼──────┐
│  PostgreSQL │    │  向量数据库  │
│  (元数据)   │    │  (Milvus等) │
└─────────────┘    └─────────────┘
       │
┌──────▼──────┐
│  Embedding  │
│  Service    │
│  (可独立部署)│
└─────────────┘
```

**适用场景**：企业级、多领域、高并发
**优势**：水平扩展、高可用、性能独立

### 5.3 可插拔设计

核心组件的可插拔替换矩阵：

| 组件 | 轻量版（默认） | 标准版 | 企业版 |
|---|---|---|---|
| 关系数据库 | SQLite | PostgreSQL | PostgreSQL 集群 |
| 向量索引 | SQLite + NumPy | Qdrant | Milvus / Pinecone |
| Embedding | 本地 GGUF | OpenAI / 火山 | 私有化部署模型 |
| 文档存储 | 本地文件系统 | 本地 + 备份 | 对象存储（S3/MinIO） |
| 部署方式 | 单进程 | Docker | K8s + 集群 |

## 6. 知识库模板化设计

### 6.1 模板核心概念

```
Template（模板）                  Instance（实例）
┌─────────────────────┐          ┌─────────────────────┐
│ 实体类型定义         │          │  独立domain          │
│ 分类规则             │  创建    │  独立数据库          │
│ 检索配置             │ ───────→ │  独立配置            │
│ 权限模板             │          │  独立文档库          │
│ 导入规则             │          │  独立索引            │
└─────────────────────┘          └─────────────────────┘
```

### 6.2 模板示例：Bangcle 产品知识库

```yaml
template:
  id: bangcle-product-kb
  name: "Bangcle 产品知识库"
  domain: bangcle-product
  
  entity_types:
    - name: product
      display_name: "产品"
      fields: [名称, 产品线, SKU, 价格, 版本, 状态, 简介]
    - name: solution
      display_name: "解决方案"
      fields: [名称, 适用行业, 核心能力, 典型客户]
  
  categories:
    - path: "产品/移动安全"
      match: "移动安全/"
    - path: "产品/终端安全"
      match: "终端安全/"
    - path: "解决方案/金融"
      match: "解决方案/金融/"
  
  search:
    default_top_k: 5
    hybrid_search: true
    graph_enhance: true
    rerank: false
  
  permissions:
    default_clearance: internal
    public_entities: false
```

### 6.3 实例化流程

1. 选择模板 → 配置实例参数（名称、描述、存储路径等）
2. 创建独立 domain + 初始化数据库
3. 按模板配置预创建分类和实体类型
4. 导入文档（按模板分类规则自动归类）
5. 自动构建索引和知识图谱
6. 发布上线

## 7. 风险防护体系

### 7.1 三层防护架构

```
          ┌─────────────┐
  输入 ──→│  输入防护   │──→ 不合格：拒绝/标记/脱敏
          └──────┬──────┘
                 ↓ 合格
          ┌─────────────┐
          │  检索防护   │──→ 风险：过滤/降级
          └──────┬──────┘
                 ↓ 通过
          ┌─────────────┐
  输出 ←──│  输出防护   │──→ 风险：拒绝/脱敏/警告
          └─────────────┘
```

### 7.2 风险分级处置策略

| 风险等级 | 触发条件 | 处置策略 |
|---|---|---|
| 低风险 | 轻度格式问题、低置信度 | 标注警告后返回，记录日志 |
| 中风险 | 部分越权、内容矛盾、解析不完整 | 只返回来源片段，不生成答案，提示用户核实 |
| 高风险 | 注入攻击、敏感泄漏、明确越权 | 拒绝回答，记录审计日志，通知管理员 |
| 严重风险 | 大量异常查询、数据损坏迹象 | 触发熔断，暂停服务，告警通知 |

## 8. 技术选型

### 8.1 核心技术栈

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 语言 | Python 3.11+ | 生态丰富，AI 领域标准 |
| Web 框架 | FastAPI | 异步、高性能、自动文档 |
| 关系数据库 | SQLite → PostgreSQL | 单机起步，可平滑升级 |
| 向量存储 | NumPy (SQLite) → Qdrant → Milvus | 按规模选择，统一接口 |
| 全文检索 | SQLite FTS5 | 内置，零依赖 |
| 文档解析 | python-docx / openpyxl / python-pptx / pdfplumber / pytesseract | 各格式专用解析库 |
| OCR | Tesseract (本地) → PaddleOCR | 本地起步，可升级 |
| ASR | Whisper (本地) | 音视频转文字 |
| Embedding | 本地 GGUF → 火山 / OpenAI | 可插拔 |
| 部署 | 单进程 → Docker → K8s | 按需选择 |

### 8.2 选型原则

1. **默认轻量**：默认配置零外部依赖，降低入门门槛
2. **接口抽象**：所有可选组件通过统一接口封装，切换实现不影响上层
3. **生态优先**：优先选择成熟、社区活跃的开源项目
4. **可渐进式**：从小规模到大规模，平滑升级，不需要推倒重来

- 业务组件通过标准接口调用，不直接依赖内部实现

## 10. 演进路线

### Phase 1：核心服务化（MVP）

**目标**：可独立部署的知识库服务，支持常见格式文档导入和查询

主要交付：
- 服务化改造（FastAPI + MCP + CLI）
- 文档接入流水线（8种常见格式 + 智能切片）
- 混合检索引擎（关键词 + 向量 + 实体匹配）
- 三层风险防护基础版
- 知识库模板机制
- 核心文档（架构、API、使用、运维）

### Phase 2：生产增强

**目标**：生产级知识库，质量体系完善

主要交付：
- 知识图谱自动构建
- 重排序 + 查询改写 + 上下文压缩
- 完整审核工作流
- 反馈自动聚类与质量评分
- PostgreSQL + Qdrant 升级支持
- 性能优化 + 监控告警

### Phase 3：企业级智能化

**目标**：企业级部署，自动优化能力

主要交付：
- 知识自动更新（检测源文档变更自动同步）
- 答案一致性校验（反幻觉增强）
- 智能问答优化（基于反馈自动调优检索策略）
- 多知识库联邦检索
- 高可用集群部署
- 多租户支持
