# 产品专家Agent设计文档 — Bangcle产品专家 v1.0

> 基于AI知识库构建的产品专家Agent，面向销售/售前/客户提供产品信息支持
> 版本：v1.0 · 状态：Draft
> 最后更新：2026-10-18，Phase 1 + Phase 2 + Phase 3 核心功能开发完成 ✅

## 1. 需求分析

### 1.1 业务需求

梆梆安全需要一个产品专家Agent，能够：
1. 随时回答客户关于产品的问题
2. 基于官方产品知识库回答，保证信息准确
3. 支持售前方案推荐、产品对比、文档整理
4. 所有回答必须附带来源引用，保证可追溯
5. 支持用户反馈收集，用于持续优化知识库质量

### 1.2 用户场景

| 场景 | 说明 |
|---|---|
| **售前支持** | 销售/售前在给客户沟通时，随时查询产品信息、获取标准化话术 |
| **客户咨询** | 客户直接咨询产品细节，得到准确回答 |
| **内部培训** | 新员工学习产品知识，快速获取准确信息 |
| **知识库维护** | 产品专家收集用户反馈，自动提交审核，提醒知识库维护人员更新 |

### 1.3 约束条件

1. **信息准确第一**：必须基于官方知识库，禁止编造
2. **可追溯**：每个回答必须附带来源引用
3. **无幻觉**：如果知识库中没有信息，必须直接承认
4. **复用现有能力**：完全复用AI知识库已有的所有能力（检索/权限/质量/审计）
5. **标准化接口**：使用MCP协议暴露工具，兼容任何Agent框架

## 2. 架构设计

### 2.1 整体架构图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          用户（客户端/Agent框架）                          │
└───────────────────────────┬────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          AI知识库（MCP Server）                              │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐          │
│  │  kb_query  │  │ kb_stats   │  │ kb_feedback │  │ other tools │          │
│  └─────────────┘  └─────────────┘  └─────────────┘  └─────────────┘          │
└───────────────────────────┬────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Agent（问题处理+结果生成）                          │
│  1. 意图理解 → 2. 工具调用 → 3. 结果整理 → 4. 输出回答                      │
└───────────────────────────┬────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          用户得到回答 + 可选择提交反馈                          │
└─────────────────────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          AI知识库（更新审计日志+统计+反馈入库）                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 模块职责划分

| 模块 | 所属组件 | 职责 |
|---|---|---|
| **工具调用层** | AI知识库（MCP Server） | 提供标准化工具接口：查询知识库、获取统计、提交反馈 |
| **会话编排层** | Agent（外部框架，本设计只定义提示词和调用规则） | 理解用户意图、调用工具、整理结果、生成回答 |
| **知识层** | AI知识库 | 数据存储、检索、质量控制、权限、审计、反馈 |

### 2.3 设计原则

1. **Agent无关**：Agent框架可以是任意（Claude Code/OpenAI Agents SDK/Cline/自定义），只需要支持MCP工具调用即可
2. **数据主权**：所有知识数据存储在AI知识库，Agent不缓存知识数据，保证数据一致性
3. **上下文工程**：严格遵循2026最佳实践，检索结果压缩/排序/去重/截断，避免无效token
4. **可观测性**：所有查询和反馈都记录审计日志，指标可监控
5. **质量闭环**：用户反馈自动用于质量优化，形成闭环

## 3. 工具设计（MCP工具）

### 3.1 工具清单

Agent需要调用以下MCP工具，所有工具都由AI知识库MCP Server提供：

| 工具名 | 用途 | 输入参数 |
|---|---|---|
| `kb_query` | 查询知识库，获取带来源的结果 | `question: string, top_k: int = 5, format: string = "json"` |
| `kb_stats` | 获取知识库统计信息 | `domain_code: string` |
| `kb_add_feedback` | 提交用户反馈 | `query_text: string, feedback_type: string, entity_id: int = None` |
| `kb_list_entities` | 列出实体 | `domain_code: string, collection_id: int = None` |
| `kb_get_entity` | 获取实体详情 | `entity_id: int` |
| `kb_stats` | 获取实例统计 | `domain_code: string` |

## 4. Agent提示词设计

### 4.1 最终优化后的提示词

```markdown
# 角色：Bangcle梆梆安全产品专家

## 角色定位
你是梆梆安全官方认证的产品专家，你熟悉公司**所有产品、行业解决方案、技术参数、客户案例**，你为销售、售前、客户提供专业准确的产品信息支持。

## 依赖机制
你必须通过 MCP 工具 `kb_query` 查询 AI 知识库获取产品信息，**所有回答必须基于知识库检索结果**，**不得编造任何内容**。
如果知识库中没有相关信息，直接告诉用户「抱歉，当前知识库中未找到相关信息，请确认问题或补充信息」。

## 工作流程

### 第一步：查询知识库
调用工具 `kb_query`，参数：
- `question`: 完整用户问题
- `top_k`: `5`
- `format`: `json`

### 第二步：检查结果
- 如果没有找到结果：直接回复「抱歉，当前知识库中未找到相关信息，请确认问题或补充信息」
- 如果找到结果：进入下一步

### 第三步：整理回答
基于检索结果整理回答，要求：
1. **专业简洁**：语言专业，逻辑清晰，适合客户和售前沟通场景
2. **结构清晰**：分点说明，使用 markdown 标题/列表，重点突出，便于快速阅读
3. **合并互补**：如果多个来源有互补信息，合并整理
4. **冲突说明**：如果信息冲突，说明冲突情况，给出建议
5. **缺失说明**：如果问题部分信息缺失，说明哪些信息缺失

### 第四步：强制来源引用
回答末尾必须附上所有来源引用，格式如下：

---
**来源引用**：
{% for source in sources %}
1. **{{source.entity.name}}** — `{{source.doc_asset.file_name}}` [文档]  
> `{{source.chunk.text[:250]}}...`
{% endfor %}

## 约束规则（必须严格遵守）

1. 🚫 **禁止编造**：任何问题，找不到信息直接承认，绝不编造
2. ✅ **来源强制**：所有回答必须附带来源引用，即使只有一个来源
3. 🔒 **权限遵守**：只返回当前用户权限允许查看的内容
4. 🧩 **结构化输出**：使用 markdown 标题、列表分割内容，不要大段文字
5. 🧠 **幻觉检测**：自动检查回答内容，如果发现内容不在所有来源中，需要标注出来
6. 📊 **上下文管理**：只保留最近 5 轮对话历史，更早的对话自动截断避免上下文溢出

## 你可以主动提供的能力

如果用户问：
- 「推荐产品方案」：根据用户场景（行业/规模/痛点）推荐匹配的产品组合方案
- 「对比产品」：对比不同产品的差异和适用场景
- 「售前问答」：提供标准化问答话术，帮助销售应对客户提问
- 「产品文档整理」：整理现有文档为结构化产品介绍，方便发布

## 当前用户提问：
{{user_query}}
```

### 4.2 设计说明

1. 严格遵循**上下文工程**最佳实践：每次都调用工具查询，不缓存知识，保证数据一致性
2. 强制来源引用，满足可追溯要求，符合合规要求
3. 幻觉检测是内置能力，Agent检查后标注，进一步降低幻觉概率
4. 上下文截断避免溢出，保证稳定运行

## 5. 质量与可观测性

### 5.1 质量保证

| 质量环节 | 实现位置 | 说明 |
|---|---|---|
| 内容质量评分 | AI知识库 | 文档入库前进行质量评分，低质量内容需要人工审核 |
| PII脱敏 | AI知识库 | 自动检测并脱敏敏感信息 |
| 审核工作流 | AI知识库 | 新内容/变更必须审核才能发布 |
| 用户反馈收集 | Agent + AI知识库 | 用户反馈自动收集，用于聚类发现知识缺口 |
| 反馈聚类 | AI知识库 | 自动聚类相似问题，发现知识缺口通知维护人员 |
| 幻觉检测 | Agent + AI知识库 | Agent回答后再次检测是否超出检索内容 |

### 5.2 可观测性

复用AI知识库已有的Prometheus指标：
- 查询计数、成功计数、延迟分布
- 摄入文档计数、成功计数
- 文档/实体/块数量gaurce
- 缓存命中率
- 反馈计数按类型统计

所有查询和操作都记入审计日志，支持问题追踪。

## 6. 部署方式

### 6.1 前置条件

1. 已创建Bangcle产品知识库实例：
```bash
ai-kb instance create --code bangcle-products --name "Bangcle产品知识库" --template product-kb
```
2. 已导入产品文档
3. AI知识库MCP Server已启动，Agent配置了正确的端点

### 6.2 Agent配置示例（Claude Code）

在 Claude Code `settings.json` 中添加：
```json
{
  "mcpServers": {
    "bangcle-product-kb": {
      "url": "http://<aikb-host>:<port>/mcp",
      "apiKey": ""
    }
  }
}
```
然后在 Agent 设置中使用上面的提示词即可。

### 6.3 部署架构

和AI知识库部署架构一致，支持单机/生产两种模式：

| 组件 | 单机部署 | 生产部署 |
|---|---|---|
| AI知识库MCP Server | 和Agent同一主机 | 独立部署，可水平扩展 |
| Bangcle产品知识库 | SQLite | PostgreSQL + Qdrant |
| 文档存储 | 本地文件系统 | 对象存储（MinIO/S3） |
