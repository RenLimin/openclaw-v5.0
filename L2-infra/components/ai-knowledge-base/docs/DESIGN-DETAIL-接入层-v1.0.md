# AI 知识库 - 文档接入层详细设计 v1.0

> L2 Infrastructure Component · ai-knowledge-base
> 版本：v1.0 · 状态：Draft
> 最后更新：2026-10-18

---

## 1. 设计目标

1. **多格式支持**：覆盖主流文档格式，支持常见办公文档、网页、图片、音视频
2. **高保真提取**：尽可能完整保留原文内容和结构信息
3. **智能切片**：按语义/章节切分，避免知识断裂，保留上下文
4. **可扩展架构**：解析器可插拔，新增格式无需修改核心流程
5. **质量可控**：解析质量检测 + 降级策略 + 人工补录入口
6. **增量更新**：基于内容指纹的增量导入，只处理变更部分

### 2.1 接入流水线

```
┌─────────────────────────────────────────────────────────────────┐

│                                                                 │
│  ① 发现  →  ② 解析  →  ③ 质检  →  ④ 切片  →  ⑤ 抽取  →  ⑥ 入库  │
│                                                                 │
│  发现源：                                                        │
│    - 本地目录扫描                                                │
│    - 对象存储监听                                                │
│    - 单文件上传                                                  │
│    - URL 抓取                                                    │
│                                                                 │
│  解析器：                                                        │
│    - 文本类：MD / TXT / HTML / CSV                              │
│    - 办公类：Word / Excel / PPT / PDF                           │
│    - 图像类：图片 OCR / 扫描件 PDF                              │
│    - 音视频：Whisper ASR 转文字                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 文档发现 (Discovery)

### 3.1 支持的发现方式

| 方式 | 描述 | 适用场景 |
|---|---|---|
| 目录扫描 | 递归扫描本地目录，按规则匹配文件 | 批量导入、定时同步 |
| 文件上传 | API 上传单个文件 | 手动导入、UI集成 |
| 对象存储监听 | 监听 S3/MinIO 等对象存储的新文件 | 云原生部署 |
| URL 抓取 | 输入URL，抓取网页内容 | 网页知识库 |
| Git 仓库同步 | 同步 Git 仓库中的文档 | 技术文档知识库 |

### 3.2 目录扫描规则

- 支持文件名通配符过滤（`*.pdf`, `*.md` 等）
- 支持排除规则（忽略 `node_modules/`, `.git/` 等）
- 支持文件大小上限配置
- 支持递归深度配置
- 增量扫描：基于文件修改时间 + MD5，只处理变更文件

### 3.3 文档识别策略

1. **扩展名识别**：优先通过文件扩展名判断格式
2. **MIME 嗅探**：扩展名不明时，读取文件头检测真实格式
3. **内容探测**：读取前几KB内容，进一步确认格式
4. **解析器回退**：首选解析器失败时，尝试备用解析器

## 4. 文档解析器 (Parser)

### 4.1 解析器架构

```python
class BaseParser(ABC):
    """所有解析器的基类"""
    
    @abstractmethod
    def supports(self, file_path: str, mime_type: str) -> bool:
        """判断是否支持该文件"""
        pass
    
    @abstractmethod
    def parse(self, file_path: str) -> ParseResult:
        """解析文件，返回结构化结果"""
        pass
    
    @property
    @abstractmethod
    def priority(self) -> int:
        """优先级，数字越小优先级越高"""
        pass
```

### 4.2 解析结果结构

```python
@dataclass
class ParseResult:
    success: bool                    # 是否成功
    status: str                      # success / partial / failed
    error_message: str = ""          # 错误信息
    
    # 文本内容
    text: str = ""                   # 完整纯文本
    
    # 结构信息
    sections: List[Section] = None   # 章节结构
    tables: List[Table] = None       # 表格数据
    images: List[ImageRef] = None    # 图片引用
    
    # 元数据
    metadata: Dict = None            # 文档元数据（标题/作者/日期等）
    language: str = "zh"             # 文档语言
    word_count: int = 0              # 字数
    page_count: int = 0              # 页数（如有）
    
    # 质量指标
    quality_score: float = 0.0       # 解析质量分 (0-1)
    confidence: float = 0.0          # 置信度

@dataclass
class Section:
    title: str                       # 章节标题
    level: int                       # 层级（1=一级标题，2=二级...）
    content: str                     # 章节内容
    position: int                    # 在全文中的起始位置

@dataclass
class Table:
    headers: List[str]               # 表头
    rows: List[List[str]]            # 数据行
    caption: str = ""                # 表格标题
    position: int = 0                # 在文中的位置

@dataclass
class ImageRef:
    path: str                        # 图片路径
    caption: str = ""                # 图片说明
    ocr_text: str = ""               # OCR识别文字（如有）
    position: int = 0                # 在文中的位置
```

### 4.3 格式解析器清单

#### 文本类（高优先级）

| 格式 | 解析库 | 说明 |
|---|---|---|
| Markdown (.md) | markdown-it-py / mistune | 保留章节结构，代码块、表格正确处理 |
| 纯文本 (.txt) | 直接读取 | 按空行分段 |
| HTML (.html/.htm) | BeautifulSoup / readability | 提取正文，去除导航/广告等噪声 |
| CSV (.csv) | csv 标准库 | 按行解析，表头作为字段 |
| JSON / YAML | 标准库 | 结构化数据，键值对展平 |

#### 办公文档类

| 格式 | 解析库 | 说明 |
|---|---|---|
| Word (.docx) | python-docx | 提取段落、表格、标题层级；.doc 格式用 LibreOffice 转换 |
| Excel (.xlsx/.xls) | openpyxl / xlrd | 逐Sheet提取，每个Sheet一个section；保留表格结构 |
| PowerPoint (.pptx) | python-pptx | 提取每页标题+文本+备注，按页组织 |
| PDF (.pdf) | pdfplumber（优先）/ PyMuPDF | 提取文本+表格；扫描件走OCR分支 |

#### 图像类

| 格式 | 解析库 | 说明 |
|---|---|---|
| 图片（PNG/JPG等） | Pytesseract → PaddleOCR | OCR 识别文字；支持中英文混合 |
| 扫描件 PDF | pdf2image + OCR | 每页转图片再OCR |

#### 音视频类

| 格式 | 解析库 | 说明 |
|---|---|---|
| 音频（MP3/WAV等） | faster-whisper | ASR 转文字，按时间戳分段 |
| 视频（MP4/AVI等） | ffmpeg 提取音频 + Whisper | 先提取音频再转文字，可选抽帧OCR |

### 4.4 降级策略

| 场景 | 降级方案 |
|---|---|
| 首选解析器失败 | 尝试备用解析器（如 pdfplumber 失败 → PyMuPDF） |
| 部分页面解析失败 | 标记 `partial` 状态，记录失败页码，已解析部分仍入库 |
| 完全解析失败 | 保留原始文件，记录 `failed` 状态；可通过文件名和元数据检索 |
| OCR 识别率低 | 保留原图片 + OCR文本，标注低置信度，建议人工补录 |
| 格式不支持 | 保留文件原始信息，进入人工处理队列 |

## 5. 质量检测 (Quality Check)

### 5.1 检测项

| 检测项 | 描述 | 处置 |
|---|---|---|
| 内容完整性 | 字数是否合理、是否有大面积空白 | 过低则标记低质量 |
| 格式正确性 | 是否有乱码、编码错误 | 严重则标记解析失败 |
| PII 检测 | 手机号、身份证、邮箱、密钥、地址等 | 检测到则自动脱敏 |
| 敏感词检测 | 政治敏感、违法违规内容 | 标记并阻止入库 |
| 语言检测 | 识别文档语言 | 设置 language 字段 |
| 重复检测 | 与已有文档的内容指纹对比 | 完全重复则跳过，部分重复则标注 |
| 可读性评分 | 句子复杂度、专业术语密度等 | 作为质量分一部分 |

### 5.2 PII 检测与脱敏

**检测范围**：
- 手机号：`1[3-9]\d{9}`
- 身份证号：18位带校验
- 邮箱地址
- 银行卡号
- IP 地址
- API Key / Secret Key 模式（通用模式匹配）
- 姓名 + 地址组合（需 NER，可选）

**脱敏策略**：
```python
# 手机号：138****1234
# 身份证：110101********1234
# 邮箱：a***@example.com
# 银行卡：**** **** **** 1234
```

可配置：哪些类型需要脱敏，脱敏级别（掩码 / 完全删除 / 替换为占位符）。

### 5.3 质量评分

综合评分（0-100）：
- 内容完整性（40%）：字数、结构完整性
- 解析置信度（30%）：解析器置信度、OCR 识别率
- 格式规范性（20%）：标题层级、段落结构
- 语言质量（10%）：无乱码、语法通顺

## 6. 智能切片 (Chunker)

### 6.1 切片策略

| 策略 | 适用场景 | 原理 |
|---|---|---|
| 章节切片 | 结构化文档（Markdown/Word/HTML） | 按标题层级切分，每节一个chunk |
| 语义切片 | 非结构化文本 | 用语义相似度判断段落边界，语义相近的合并 |
| 固定大小切片 | 兜底策略 | 按token数/字符数切分，带重叠 |
| 表格切片 | Excel/CSV/表格数据 | 按行或按逻辑单元切分，保留表头 |
| 代码切片 | 代码文档 | 按函数/类切分 |

### 6.2 切片流程

```
输入：解析后的全文 + 章节结构
    ↓
优先按章节切分（保留标题层级）
    ↓
章节过长？→ 按段落/语义进一步切分
    ↓
检查chunk大小 → 超过max_tokens → 再切分
    ↓
过小的chunk？→ 与相邻chunk合并
    ↓
为每个chunk添加元数据（标题、章节路径、所属文档）
    ↓
输出：chunk列表
```

### 6.3 切片参数配置

| 参数 | 默认值 | 说明 |
|---|---|---|
| max_tokens | 512 | 每个chunk的最大token数 |
| min_tokens | 50 | 最小token数，小于则合并 |
| overlap_tokens | 64 | 相邻chunk重叠token数，保留上下文 |
| chunking_strategy | auto | auto / section / semantic / fixed |
| preserve_tables | true | 是否完整保留表格不切分 |
| preserve_code | true | 是否完整保留代码块不切分 |

### 6.4 切片元数据

每个chunk附带：
- `doc_id`：所属文档ID
- `chunk_index`：在文档中的序号
- `title`：章节标题（最近的上级标题）
- `section_path`：完整章节路径，如 "第2章/2.3 功能介绍/2.3.1 接口说明"
- `position_start/end`：在原文中的字符位置
- `page_number`：页码（如有）

## 7. 知识抽取 (Extractor)

### 7.1 元数据提取

自动从文档中提取：
- 标题：从文件名 + 文档开头最大字号/一级标题
- 作者：文档属性 / 文末署名
- 日期：文档属性 / 文中日期模式匹配
- 版本号：文件名中的版本号 / 文中的版本信息
- 分类：根据路径规则 / 关键词自动分类

### 7.2 实体抽取

从文档文本中识别业务实体：
- **基于规则**：正则匹配（产品型号、SKU、编号等）
- **基于词典**：已有实体库的模糊匹配（发现已有实体的引用）
- **基于LLM**（可选）：用大模型抽取实体，返回结构化结果

### 7.3 关系抽取

识别实体之间的关系：
- 包含关系（产品包含功能）
- 依赖关系（A依赖B）
- 引用关系（文档A引用文档B）
- 相似关系（同类产品）
- 替代关系（新版本替代旧版本）

## 8. 向量化与索引 (Vectorizer)

### 8.1 Embedding 引擎

可插拔设计，支持多种后端：

| 后端 | 适用场景 | 特点 |
|---|---|---|
| 本地 GGUF | 单机/离线 | 零依赖，速度快，效果一般 |
| OpenAI text-embedding-* | 云端 | 效果好，有成本 |
| 火山 embedding | 国内 | 合规，速度快 |
| 通义 / 文心 / 智谱 | 国内 | 各有特色 |

### 8.2 向量化流程

```
chunk 文本
    ↓
文本预处理（清洗/标准化）
    ↓
调用 embedding 模型 → 向量
    ↓
向量存入 chunk.embedding 字段
    ↓
FTS 索引更新
    ↓
向量索引更新（如使用独立向量库）
```

### 8.3 批量优化

- 批量向量化：攒批处理，减少API调用次数
- 失败重试：指数退避重试
- 缓存机制：相同文本直接返回缓存结果
- 限流控制：按API供应商的限流配置控制并发

## 9. 流水线编排

### 9.1 任务状态机

```
pending → discovering → parsing → quality_checking → chunking 
                                                              ↓
                              completed ← indexing ← extracting
                                                              ↓
                              failed ← (任何步骤失败超过重试次数)
```

### 9.2 任务管理

每个文档导入是一个独立任务，支持：
- 任务队列（优先队列，支持优先级）
- 并发控制（配置最大并发数）
- 重试机制（失败自动重试，指数退避）
- 断点续传（进程重启后，未完成任务继续执行）
- 进度查询（实时查询导入进度）

### 9.3 批量导入流程

```
批量导入请求
    ↓
扫描文件 → 生成任务列表 → 去重（MD5对比）
    ↓
任务入队 → 工作池消费
    ↓
每个任务独立走流水线
    ↓
任务完成/失败 → 更新状态 → 记录审计日志
    ↓
全部完成 → 生成导入报告（成功/失败/跳过统计）
```

## 10. 增量更新机制

### 10.1 变更检测

| 检测方式 | 原理 | 精度 |
|---|---|---|
| MD5 对比 | 文件内容MD5是否变化 | 精确（文件级） |
| 内容指纹 | 分片哈希，检测局部变化 | 精确（内容级） |
| 修改时间 | 文件 mtime | 快速但不精确 |
| Git diff | 版本控制对比 | 精确（行级） |

### 10.2 更新策略

- 检测到变更 → 创建新版本 → 重新走完整流水线
- 旧版本保留（可配置保留数量）
- 新版本发布前，旧版本继续生效
- 原子切换：新版本索引构建完成后，原子切换到新版本

## 11. 错误处理与可观测性

### 11.1 错误分级

| 级别 | 示例 | 处理方式 |
|---|---|---|
| 警告 | 部分页面解析失败、低置信度 | 继续处理，标记警告 |
| 错误 | 单个文档解析失败 | 跳过该文档，记录错误 |
| 严重 | 数据库连接失败、Embedding服务不可用 | 暂停导入，告警通知 |

### 11.2 可观测性

- **Metrics**：导入速度、成功率、各阶段耗时、错误率
- **Logs**：每个任务的详细日志，可追溯
- **Tracing**：每个文档经过的全链路追踪
- **进度报告**：批量导入的实时进度和预估完成时间
