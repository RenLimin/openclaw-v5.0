# logs

## 设计目标

为 L2 基础设施层提供统一的日志管理与聚合能力，解决分布式组件日志分散、查询困难、轮转缺失的问题。

## 架构决策

- **目录先行**：先建立 `observability/` 子目录结构，后续实现时无需调整目录
- **预留可观测性接口**：日志作为可观测性的子集，与 metrics/tracing 共享 `observability/` 命名空间
- **聚合器先行**：核心日志聚合能力已实现（`src/aggregator.py`），查询 DSL 与轮转策略为演进方向

## 模块划分

```
logs/
├── src/
│   ├── aggregator.py           # 日志聚合器（多源采集、级别过滤、时间窗口聚合）
│   └── __init__.py
└── observability/              # 预留给可观测性日志
```

已实现：`LogAggregator` 日志聚合器（216 行，多源采集/级别过滤/时间窗口聚合）。
演进方向（未实现）：`LogQuery` 日志查询 DSL、`RotationPolicy` 日志轮转策略。

## 关键接口/数据结构

- `LogAggregator`：日志聚合器，支持多源采集（已实现）
- `LogQuery`：日志查询 DSL（待实现）
- `RotationPolicy`：日志轮转策略（待实现）

## 依赖关系

- **依赖**：暂无（Python 标准库）
- **被依赖**：待 L2/L3 组件接入本组件记录日志

## 演进方向

1. **短期**：完成日志查询接口、轮转策略、级别过滤
2. **中期**：接入结构化日志（JSON）
3. **长期**：远程聚合、告警联动
