# logs

## 设计目标

为 L2 基础设施层提供统一的日志管理与聚合能力，解决分布式组件日志分散、查询困难、轮转缺失的问题。当前为骨架阶段，预留目录结构供后续实现。

## 架构决策

- **目录先行**：先建立 `observability/` 子目录结构，后续实现时无需调整目录
- **预留可观测性接口**：日志作为可观测性的子集，与 metrics/tracing 共享 `observability/` 命名空间
- **延迟实现**：当前无实际日志产出组件，待 L2 组件数量增长后再投入实现

## 模块划分

```
logs/
└── observability/            # 预留给可观测性日志
```

当前仅 README.md 描述定位与规划，无实际代码模块。

## 关键接口/数据结构

（待设计，预留方向）
- `LogAggregator`：日志聚合器，支持多源采集
- `LogQuery`：日志查询 DSL

## 依赖关系

- **依赖**：暂无
- **被依赖**：暂无（待实现后，L2/L3 组件将依赖本组件记录日志）

## 演进方向

1. **短期**：实现基础日志采集与本地文件存储
2. **中期**：增加日志查询接口、轮转策略、级别过滤
3. **长期**：接入结构化日志（JSON）、远程聚合、告警联动
