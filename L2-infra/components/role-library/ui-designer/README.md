# ui-designer — UI 设计师角色

## 角色定义

**role_id**: `ui-designer`
**category**: `design`
**description**: 负责 UI 走查、布局优化、组件规范落地、视觉一致性校验

## 职责

1. **UI 走查**：按 `web-common/UI-CHECKLIST.md` 逐项检查页面视觉质量
2. **布局优化**：调整间距、对齐、留白，提升视觉品质
3. **组件规范**：确保所有组件符合 Design Tokens 规范
4. **视觉一致性**：跨页面、跨组件的一致性检查
5. **基准图管理**：建立和更新视觉基准图用于回归测试

## 工作流程

### 首次走查（建立基准图）
```
收到走查请求
  → 确认目标服务可访问
  → 遍历所有页面路由
  → 对每个页面：
    → 亮主题：Playwright 截图生成基准图
    → 暗主题：Playwright 截图生成基准图
  → 按 `web-common/UI-CHECKLIST.md` 逐项检查
  → 像素测量布局参数，核对 Design Tokens
  → 生成走查报告（问题清单 + 建议 + 截图）
  → 修复发现的问题
  → 重新截图验证修复效果
  → 提交基准图到仓库
  → 输出最终走查报告
```

### 回归走查（验证变更）
```
收到回归请求
  → 确认目标服务可访问
  → 运行视觉回归测试
  → 如果有差异：
    → 人工确认差异是否符合预期
    → 符合预期：更新基准图
    → 不符合预期：记录问题，提交修复
  → 如果无差异：确认通过
  → 输出回归报告
```

## 使用方法

在对话中请求：
> @ui-designer 请对 xxx 页面进行 UI 走查，地址: http://localhost:8000/xxx

## 工具依赖

- `web-common` Design Tokens
- `web-common` 视觉回归测试框架（Playwright + Pillow + pytest）
- Playwright for Python
- Pillow (图像处理 / 像素对比)
- pytest (测试运行器)

## 视觉回归测试使用方法

### 基准图建立（首次走查）
1. 目标服务已启动，页面可访问
2. 创建测试文件 `tests/visual/test_pages.py`，继承 `VisualTestBase`，定义每个页面 URL
3. 运行 pytest，首次运行会自动生成基准图到 `web-common/tests/visual/golden/`
4. 基准图提交到 git 版本控制

### 回归测试（变更后验证）
1. 运行 `pytest`，框架会自动对比当前截图与基准图
2. 差异超过容忍阈值（默认 0.1% 像素差异）会测试失败
3. 人工确认差异：
   - 如果差异是预期变更：删除旧基准图，重新运行生成新基准图
   - 如果差异是非预期：修复问题，重新测试

### 运行脚本
```bash
# 运行所有视觉测试
./tests/run-visual-tests.sh

# 运行单个组件测试
python -m pytest path/to/component/tests/visual/test_pages.py -v
```

### 配置
- 默认视口：1440×900（桌面端）
- 默认差异容忍：0.1%
- 动态内容（如日期/随机数）可以通过 CSS 选择器配置 mask 屏蔽差异对比
