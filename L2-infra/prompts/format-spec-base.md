# P1 通用输出格式契约（format-spec-base）

> ADR-035 · P1 层 · 与 `answer-spec-base.md`（内容契约）并列的**格式契约**
> 版本：1.0 (2026-10-30) · 适用：所有结构化分析/汇总/审查报告（项目/合同/产品三域及跨域）
> 关系：内容契约管"必须讲什么"，格式契约管"按什么固定骨架讲"。两者都过同一 checker。

## 1. 为什么需要格式契约

内容契约（answer-spec）规定维度，但不规定章节顺序与命名 → 同一类报告跨任务结构漂移、人工难以快速定位、无法用确定性校验保证一致性。格式契约提供**统一信封 + 域内固定内页**，使任何一次产出"看一眼就知道去哪找结论/风险/溯源/质量信号"。

## 2. 报告判定（report vs receipt）

- **报告型（report）**：含 H1 标题 + ≥2 个 `##` 章节的结构化产出 → **必须套本信封**，checker 强校验。
- **操作回执（receipt）**：无 H1 的短确认（"已合并 12 页""OCR 完成 1204 字"）→ 豁免格式信封，仅受内容契约相关条款约束。
- 判定由 checker 自动完成，无需作者声明；拿不准时按报告型处理（更严）。

## 3. 统一信封（所有报告型产出的固定骨架，顺序不可调）

```markdown
# <报告标题>

> 生成：<YYYY-MM-DD HH:MM TZ> · 数据基准：<YYYY-MM-DD HH:MM TZ> · 契约版本：P1/P2 v<x.y> · 归属：<L2/L3/L4 + 域>
> <可选：一句话修订/降级说明行>

## 0. 溯源链
<数据源 → 查询 → 结论 的 minimal trace；代码块或箭头链；P1 内容契约 §4.5>

## 1. <结论/总览（先给答案）>

## 2..N. <域内固定章节，见各 P2 §4 模板>

## N. 风险分析（或合并进域章节，但 RAG 表必备，见内容契约）

## 末. 质量信号
- 实时/导出/历史 数据源分级；降级项 ⚠️ 标注；口径修正记录；【缺失】项。
```

### 3.1 信封必填件（checker 硬校验）

| # | 要素 | 机器判据 |
|---|---|---|
| F1 | H1 标题 | 首个非空行以 `# ` 开头 |
| F2 | 元信息块 | 标题下存在 `>` 引用块，且含「生成」+「契约版本」+「归属」三关键字 |
| F3 | 数据基准时间 | 元信息块含「数据基准」或正文有【已验证 日期\|来源】（与内容契约时间戳二选一即可） |
| F4 | 溯源链章节 | 存在 `## 0. 溯源链`（或溯源链关键字，沿用内容契约 TRACE） |
| F5 | 质量信号章节 | 存在含「质量信号」的章节标题 |

## 4. 固定命名约定

- 章节编号从 `## 0. 溯源链` 起；结论/总览固定靠前（§1）。
- 风险统一用 RAG：🔴/🟡/🟢；风险表列固定为 `编号 | 风险 | 级别 | 证据 | 行动项 | 时限/责任`。
- 证据标注沿用内容契约三档：`【已验证 日期|来源】` / `【推断】` / `【缺失】`。
- 表格优先于长段落（USER 偏好）；可折叠细节用 `<details>`。

## 5. 域内固定内页

各域报告**正文章节的固定标题与表格列**由对应 P2 的「§4 输出格式模板」规定：
- 项目域 → `L3-business/prompts/project-answer-spec.md §4`
- 合同域 → `L3-business/prompts/contract-answer-spec.md §4`
- 产品域 → `L4-proprietary/prompts/product-answer-spec.md §4`

域内章节模板属指令规范（技能遵守），不做逐标题硬正则，避免脆弱误拦；通用信封（F1–F5）做硬校验。
