# Web UI 设计开发能力建设 - 详细设计

## 1. 设计原则层

### 1.1 核心设计原则

| 原则 | 内容 | 使用场景 |
|---|---|---|
| **内容分层** | 主页面精简，突出入口和重点，详细内容放到二级/详情 | 列表页、dashboard、首页 |
| **视觉层次** | 元素按重要性排序，大小、颜色、间距突出重点 | 所有页面 |
| **一致性** | 统一颜色、字体、按钮、间距规范，同一操作同一视觉 | 全项目 |
| **简化任务** | 拆分复杂任务为多步，减少每一步认知负担，提前校验输入 | 表单、流程类操作 |

### 1.2 UX/UI 通用原则

| 原则 | 内容 |
|---|---|
| **以人为本** | 设计围绕用户目标和行为，而非技术。简单比复杂更好，用户能用才是对的 |
| **设计系统优先** | 复用已有组件，统一规范，提升开发效率和一致性。已有组件不重复造轮子 |
| **动效合理使用** | 时长 150-400ms，入场 ease-out，出场 ease-in，同屏避免多动画同时 |
| **微交互** | 合理使用：滚动、悬浮、点击反馈、开关切换，提升参与感，避免过度 |
| **简约主义** | 去掉不必要装饰，突出功能本身，参考苹果 HIG |

## 2. 组件规范层

### 通用交互组件规范

#### 按钮
- **设计原则**：明确功能，视觉区分主次
- **类型：**
  - 主按钮：主色背景，白色文字，用于核心操作
  - 次按钮：边框+文字，浅色背景，用于次要操作
  - 危险按钮：红色背景/边框，用于危险操作（删除/驳回）
  - 文字按钮：仅文字，无背景边框，用于弱操作
- **交互状态：** 默认 → 悬浮 → 点击 → 禁用
- **禁用：** 降低透明度 + 禁止点击

#### 输入框
- **设计原则：** 清晰标签，提示占位，反馈及时
- **标签：** 必须有清晰标签，浮动标签或固定标签
- **占位：** 给出示例，而非重复标签
- **校验：** 输入后即时校验，错误给出清晰提示
- **状态：** 默认 → 聚焦 → 错误 → 禁用

#### 选择器
- **设计原则：** 选项清晰，支持搜索（大量选项）
- **单选/下拉：** 选中项高亮，支持搜索过滤（>10 选项）
- **多选：** 已选在顶部展示，支持快速移除
- **日期选择：** 使用标准日历组件，范围选择支持拖拽

#### 表格
- **设计原则：** 列对齐合理，支持排序、翻页/加载更多
- **对齐：** 文本左对齐，数字右对齐，表头和内容对齐一致
- **空状态：** 空数据给出友好提示，不空白
- **加载：** 滚动加载或分页，给出加载提示

#### 弹窗（Modal）
- **设计原则：** 模态遮罩，聚焦操作，关闭入口清晰
- **结构：** 标题栏 + 内容区 + 操作按钮区
- **关闭方式：** 遮罩点击关闭、ESC 关闭、右上角关闭按钮
- **操作按钮：** 主操作（确认/生成）右对齐，次操作（取消）左对齐

#### Toast / 通知
- **设计原则：** 轻量提示，自动消失，不打断操作
- **类型：** 成功（绿色）、错误（红色）、警告（黄色）、信息（灰色）
- **位置：** 顶部居中或右上角
- **消失：** 成功/信息 2-3 秒自动消失，错误/警告不自动消失，需要用户关闭

#### 导航 / 侧边栏
- **设计原则：** 清晰层级，当前选中高亮
- 激活项：背景/文字颜色高亮，明确当前位置
- 分组：同类项分组，用分割线或间距区分

#### 卡片
- **设计原则：** 包裹一组相关内容，信息块独立
- **间距：** 内边距合适，内容和边框留白
- **可点击：** 悬浮有反馈，表明可点击

#### 标签页（Tabs）
- **设计原则：** 同层级内容分组切换，当前激活高亮
- 切换：点击切换，不刷新页面
- 响应式：超出可滚动

## 3. 布局规范层

### 布局类型

| 布局 | 使用场景 |
|---|---|
| **侧边栏 + 主内容** | 后台管理类页面，导航固定，主内容滚动 |
| **顶部导航 + 内容** | 内容为主的页面，导航在顶部 |
| **网格卡片** | 列表/ Dashboard，信息块展示 |
| **流式布局** | 博客/文档，内容宽度自适应 |

### 响应式设计
- 断点：手机 (<768px)、平板 (768px-1024px)、桌面 (>1024px)
- 移动端：侧边栏可收起，网格一列，字体适配
- 原则：移动优先，渐进增强

### 栅格系统
- 12 列栅格，支持不同断点响应
-  gutter（间距）统一：16px / 24px

## 4. 视觉规范层

### 色彩系统

| 类型 | 使用场景 |
|---|---|
| **主色** | 主按钮、选中高亮、链接、品牌标识 |
| **辅色** | 辅助元素、信息图表、强调 |
| **中性色** | 文本、背景、边框、分割线 |
| **功能色** | 成功（绿色）、错误（红色）、警告（黄色）、信息（灰色） |

- 对比度：文本和背景对比度 ≥ 4.5:1，确保可访问性
- 暗黑模式：预留支持，切换不破坏布局

### 字体系统

- **字号层级：**
  - 大标题：24-28px
  - 小标题：18-20px
  - 正文：14-16px
  - 辅助文字：12-13px
- **行高：**
  - 标题：1.2-1.4
  - 正文：1.5-1.6
  - 小文字：1.4
- **字重：**
  - 标题：600-700
  - 正文：400
  - 强调：500-600

### 图标规范
- 使用 IconFont 或 SVG，保证清晰度
- 尺寸：16px（内联）、20-24px（按钮/导航）、32px+（大图标）
- 颜色：继承文字颜色，功能图标用对应功能色

## 5. 交互规范层

### 通用交互行为
| 状态 | 交互反馈 |
|---|---|
| 默认 | 正常显示 |
| 悬浮 | 背景加深/变色，提示可交互 |
| 聚焦 | 边框高亮，焦点可见（键盘导航） |
| 点击 | 轻微反馈（变暗/压动效果） |
| 禁用 | 透明度降低到 0.5，禁止点击 |
| 加载 | 显示 spinner，禁止重复点击 |

### 反馈规范
- **即时反馈：** 用户操作后立即给出反馈（哪怕还在加载）
- **成功：** Toast 提示，操作完成后更新 UI
- **错误：** 错误位置给出清晰提示，Toast 同时提醒
- **加载：** 长操作显示进度条/Spinner，不冻结页面

### 动画规范
- **时长：** 150-400ms，短了卡顿，长了拖沓
- **曲线：** 元素入场用 ease-out（快进慢出），元素出场用 ease-in（慢进快出）
- **使用场景：**
  - 模态弹出/收起：300ms
  - hover 反馈：150ms
  - 页面切换：300-400ms
  - 进度：即时更新，不用动画

## 6. 工程实践层

### 分层架构
- L2-infra：通用组件沉淀，所有项目复用
- L3-business：通用业务组件
- L4-proprietary：项目特定组件和页面
- 职责清晰，不越层实现，组件下沉

### 开发流程
1. **设计阶段：** 根据需求确定页面结构，复用已有组件
2. **开发阶段：** 对齐现有规范，优先复用 L2 已有组件
3. **验证阶段：** 语法检查 → 浏览器 JS 错误检查 → E2E 自动化测试

### 验证规范
- **语法检查：** 修改后必须用 node 检查 JS 语法，确保零错误
- **零 JS 错误：** 页面加载后必须零 JS 错误，所有功能正常
- **E2E 自动化：** 完整流程必须通过浏览器自动化测试，覆盖核心路径
- **零原生弹窗：** 禁止使用原生 `alert` / `confirm` / `prompt`，全部使用组件库

### 开发原则
- **不碰后端：** UI 重构不修改后端 API，只改前端
- **单一来源：** 同一个状态只保留一个入口修改，避免不一致
- **一致性：** 和已有项目代码风格对齐，不混合多种风格
