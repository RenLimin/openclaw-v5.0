# Web UI 设计开发系统级能力沉淀

## 能力描述
系统级沉淀通用现代Web UI设计开发最佳实践，为后续所有项目提供设计开发规范和参考。

## 设计开发最佳实践

### 核心设计原则

1. **内容分层**
   - 主页面内容精简，吸引用户兴趣，详细内容放到二级页面/详情展开
   - 使用卡片网格布局，用户自主选择浏览，提升交互性

2. **视觉层次**
   - 元素按重要性排序，引导用户视线流向
   - 突出核心操作，弱化次要信息，降低认知负担

3. **一致性**
   - 使用设计系统，统一颜色、字体、按钮布局规范
   - 一致性减少用户学习成本，提升品牌认知，降低交互错误

4. **简化任务**
   - 拆分复杂任务为多步，减少每一步认知负担
   - 提前做输入校验，减少用户错误，提供清晰错误提示

### UX/UI 通用原则

1. **以人为本**
   - 设计围绕用户目标和行为，而非技术堆砌
   - 简单比复杂更好，技术正确+用户能用才是正确

2. **设计系统优先**
   - 使用设计系统保证一致性和开发效率
   - 已有组件优先复用，不重新发明轮子
   - 推荐：Figma 协作，统一组件规范

3. **动效合理使用**
   - 动画时长保持 150ms - 400ms（短了卡，长了慢）
   - 动画曲线：入场用 ease-out，出场用 ease-in
   - 同一页面避免多个同时动画，会干扰用户
   - 必须在中端设备测试性能，不要只在高端机上测试

4. **微交互**
   - 合理使用微交互（滚动、悬浮、点击反馈、开关切换）
   - 提升用户参与感，让操作更直观
   - 避免过度动画，喧宾夺主

5. **简约主义**
   - 参考苹果人机交互指南，走简约路线
   - 去掉不必要的装饰，突出功能本身
   - 视觉干净，使用舒适

### 工程实践

1. **分层架构**
   - 通用组件沉淀到L2层，项目复用
   - 项目特定组件放到对应项目层
   - 不越层实现，保持职责清晰

2. **前后分离原则**
   - UI 重构不修改后端 API，只改前端
   - 现有业务逻辑不碰，只优化交互体验

3. **单一来源原则**
   - 同一个状态/参数，只保留一个入口修改
   - 避免多个入口修改同一状态，减少不一致bug

4. **代码规范**
   - 和已有项目代码风格对齐，不混合多种风格
   - 修改后必须做语法检查 + E2E 验证，确保零错误

5. **测试验证**
   - 必须通过浏览器自动化模拟人工测试，全流程跑通
   - 必须检查 JS 错误，确保零错误交付
