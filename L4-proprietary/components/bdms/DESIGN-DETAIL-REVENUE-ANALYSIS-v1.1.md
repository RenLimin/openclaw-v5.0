### 2.5 归因引擎行为

1. 遍历触发行 → 应用 §2.2/§2.3 两条硬规则（AT=合同终止 → 客户原因-终止；BF=3：交付异常 → 状态异常项目 + 原因项目异常）
2. 命中 → 自动填写；未命中 → **留空**
3. 汇总「待人工校验清单」：触发行中 BK/BL 为空者，附上下文（合同/履约/AK/AI/AT/BF/BU/BQ/AR/AS）供人工判断
4. 校验：BK 非空 ⇔ BL 非空（成对填写）；违反入校验报告

## 3. Q2 预算填报/预算趋势分桶引擎

### 3.1 总体原则

```
1. 所有记录都应有值（不允许空桶）
2. 列「预算填报 BQ」优先按上一个月度报告赋值
3. 上期为空 → 按 7 桶预定义规则自动判定
4. 规则无法判定 → 留空 + 系统提示人工校验
```

### 3.2 预算填报（BQ）分桶规则（上期为空时）

| 桶 | 自动判定规则 |
|---|---|
| **已归档但未下单** | OA 合同台账「合同下单（y/n）」为空或「否」 **且** ONES 履约义务工作项按「销售合同编号」**无法匹配** |
| **已下单但无法交付** | OA 合同台账「合同下单（y/n）」=「是」 **且** ONES 履约义务工作项按「销售合同编号」**无法匹配** |
| **已交付但无法确收** | ONES 履约义务工作项按「销售合同编号」**可以匹配** **且** `BF 履约项统计状态（周报）` = "3：交付异常" |
| **本年度正常可确收** | `计划开始时间` / `计划结束时间` / `计划完成时间` 任一在本年度 |
| **未来可确收** | `计划开始时间` / `计划完成时间` 在本年度（不含）之后 |
| **之前年度已确收** | `计划结束时间` / `计划完成时间` 在本年度（不含）之前 |
| **合同消失** | `AT 消失备注` = "合同终止" |

### 3.3 预算趋势（BU）分桶规则（上期为空时）

| 桶 | 自动判定规则 |
|---|---|
| **已归档但未下单** | 同 §3.2「已归档但未下单」 |
| **已下单但无法交付** | 同 §3.2「已下单但无法交付」 |
| **已交付但无法确收** | 同 §3.2「已交付但无法确收」 |
| **本年度正常可确收** | `预算-预估交付完成日期（周报）BX` 在本年度 |
| **未来可确收** | `预算-预估交付完成日期（周报）BX` 在本年度（不含）之后 |
| **之前年度已确收** | （Rex 未给规则 → 留空） |
| **合同消失** | `AT 消失备注` = "合同终止" |

### 3.4 分桶优先级（重叠时）

```
合同消失 > 已归档但未下单 > 已下单但无法交付 > 已交付但无法确收 > 未来可确收 > 之前年度已确收 > 本年度正常可确收
```

### 3.5 数据源依赖

| 信号 | 来源 | 现成能力 |
|---|---|---|
| OA 合同下单（y/n） | OA 合同台账（销售） | ✅ `bdms.modules.integration.connectors.oa_connector.OaConnector`（`_map_status` 归一化） |
| ONES 履约义务按销售合同编号匹配 | ONES 履约义务工作项 | ✅ `bdms.modules.integration.connectors.ones_connector.OnesConnector`（`normalize` 输出 `销售合同编号/BI履约ID`） |
| BF 履约项统计状态（周报） | 202606 预算执行表 BF 列（VLOOKUP 自「签约」） | ✅ 报表内嵌 |
| 预算-预估交付完成日期 BX | 202606 预算执行表 BX 列 | ✅ 报表内嵌 |

> **fail-closed 原则**：任一信号源缺失 → 该行分桶留空 + 提示人工校验；**禁止**用其他列推断。

## 4. Q3 跨期继承与外部报表依赖

### 4.1 继承逻辑（Rex 确认：是）

```
BU(预算趋势) = 按「履约 ID」继承上期差异表对应桶 + 本期人工改判
```

- 202606 实证：8058/8062 行逐行继承上期 202605，4 行人工改判（例：XSZS2605180322 上期「本年度正常可确收」→ 本期「已下单但无法交付」）
- **继承优先级高于重算**：上期有值 → 继承；上期无值 → §3 分桶引擎
- 人工改判覆盖后，本期值成为下一期继承源

### 4.2 外部报表依赖（Rex 确认：必需 + fail-closed）

| 依赖 | 用途 | 缺失时 |
|---|---|---|
| 《交付月报-YYYYMMDD》 | BF/BG/BW/BX 的 VLOOKUP 源（[2]签约） | **报错，不伪造** |
| 《上期差异表》 | BU 继承源（[3]预算执行表!J:BU） | **报错，不伪造** |
| 《销售合同信息查询台账》 | BO 下单标志源（[1]梆梆_销售合同台账） | **报错，不伪造** |

> 与 PRD v1.1 红线一致：Part B 无数据必须显式 `not_configured`，禁止伪造。


## 7. Q6/Q7 月度台账时序快照

### 7.1 连续性（Q6，Rex 确认）

```
系统应保持连续：每次生成报告后，自动在系统中补充快照信息
（人工统计报告也是这个制作逻辑）
```

**实现**：
- `generate` 完成后自动 upsert 当期快照到台账表
- 快照 = 当期计算出的 月度汇总记录 + 履约汇总记录
- 缺月不静默：若上一统计期非连续（非上月），写警告日志 + Web 提示

### 7.2 跨期重述（Q7，Rex 确认）

```
1. 历史合同金额每期重算（重述）→ 对应每月报表汇总表 row2~17
2. 台账按快照保存、不覆盖历史（持续保留）
3. 重述触发条件 = 按当前人工报表方式即可（每期生成即重算当前期）
```

**202606 实证**（row15 vs row3）：合同期间 202601 的新签额，统计期 202605 = 648.140122 → 统计期 202606 = 648.049622；D/E 两期未变。

**实现**：
- 台账表 `(统计期间, 合同期间)` 唯一，每期 upsert
- 历史统计期的行**不回写**（快照不可变）
- 重述只影响**当期**写入的行

### 7.3 台账快照权威口径（Rex 2026-11-12 明确，Q-20261112-01/02）

```
1. 「月度汇总记录」= 各期人工月报的历史快照，以对应月份人工月报数据为准
2. 每月财报数据一旦确定即不再变更；台账行不从当期明细重算、不回写
3. 历史快照中的部分明细，截至当月可能已发生变更——快照值与当期明细对不上属正常，非 bug
4. 当月明细由 Rex 在本轮任务完成后统一提供并录入，系统不依据残缺明细推断
```

**对系统的硬约束**：

- 台账（`月度汇总记录` / `履约汇总记录`）历史行**直接从对应期人工月报 sheet 原样导入**落库，
  **禁止**用当期预算执行表/底稿明细重算后覆盖。
- 仅**当期**（无历史月报的最新统计期）由 `generate` 计算并写入快照。
- 前期 P0 侦察中「按 U 列 >0 重算实际值」与黄金快照出现的差异
  （如 202601 递延实际差 18.58 万、202602 新签实际差 38.28 万）**不是缺陷**，
  根因是误用了「明细重算」口径；正确口径是直接继承冻结快照。
- 「汇总」表 row2–17 仍按当期口径重述（§7.2 第 1 条），与台账冻结快照是两条独立链路，
  二者不要求逐格相等；差异由各自校验列解释，不静默。
- 底稿列结构同样以 202606 人工月报实测为准（45 列 A–AS），202609 为 52 列，两套并存。
