# BDMS v2.1 — 产品需求文档（PRD）

> 版本：v2.1 PRD（2026-09-22）
> 层级：L4 专有业务层
> 基座：OpenClaw（L1）+ L3 DMS 通用管理框架
> 状态：待 Rex 审核

---

## 1. 业务目标

### 1.1 背景

Bangcle 交付管理系统（BDMS）是面向 Bangcle 交付中心的核心管理系统。当前 v1.0 已实现基础的交付月报和确收分析功能，但存在功能不完整、架构不清晰、缺乏全流程覆盖等问题。

### 1.2 目标

建设一个**具备业界最佳实践水准的 Bangcle 交付管理系统**，覆盖项目管理全流程（16 阶段 / 62 节点），以**合同审核管理、交付全流程管理、项目利润管理**为核心，支持一键部署、内外网访问控制、人类用户友好。

### 1.3 核心能力

| 能力 | 描述 |
|---|---|
| **全流程覆盖** | 覆盖 Bangcle 项目管理 16 阶段：立项→实施→交付→确收→验收→售后→结项→成本，**风险横向覆盖全流程** |
| **数据自动化** | 通过浏览器自动化从 OA、ONES、工时门户等系统获取数据 + 本机导入（Excel/CSV/手工录入），减少人工录入 |
| **报表编制** | 交付月报（15 Sheet）+ 确收分析（10 Sheet），按手工报表解析后的原始数据、公式计算数据、统计汇总数据实现自动生成 |
| **项目利润** | 收入 - 成本 = 利润，实时计算项目级利润率 |
| **安全访问** | 支持本机/内网/外网访问，Token 鉴权 + 内外网开关 |
| **一键部署** | 单命令安装，自动初始化 DB、配置、管理员账户 |

### 3.2 核心模块详细需求

---

#### 模块 1：合同审核管理（contract-management）

**业务目标**：实现合同全生命周期管理（起草→审批→签署→归档），集成风险扫描和 OCR 导入，确保合同合规。

| # | 功能 | 描述 | 验收标准 |
|---|---|---|---|
| F-CM-01 | 合同起草 | 基于 Bangcle 官方模板（11 份）生成 docx | 模板选择→变量填充→生成 docx |
| F-CM-02 | 分级审批 | 按金额/风险分级：部门经理→法务→高管 | 审批流转 + 驳回 + 修改重提 |
| F-CM-03 | 风险扫描 | 基于民法典 13 项风险点自动扫描 | 高风险标红 + 整改建议 |
| F-CM-04 | 合同签署 | 电子签章 + 纸质签署记录 | 签署状态跟踪 |
| F-CM-05 | 合同归档 | 对接 OA 归档流程 | 归档后只读 |
| F-CM-06 | OCR 导入 | 扫描件/图片→结构化数据 | 识别率 ≥ 95%，纠错规则完整 |
| F-CM-07 | 合同查询 | 按编号/客户/时间/状态检索 | 全文搜索 + 多维筛选 |

**数据源**：
- OA 合同流程（浏览器自动化）
- 知识库（kb_item）落盘：Bangcle 官方合同模板 + 民法典风险规则库

#### 模块 2：项目管理（project-management）

**业务目标**：覆盖项目全生命周期（立项→实施→交付→确收→验收→售后→结项），对接 ONES/OA，实现状态自动流转。风险横向覆盖全流程。

| # | 功能 | 描述 | 验收标准 |
|---|---|---|---|
| F-PM-01 | 项目立项 | ONES 同步 + 合同关联 + 履约项维护 | 自动创建 + 手动补录 |
| F-PM-02 | 实施管理 | 产品/安服/定制/外包四类实施 | 子任务创建 + 排期 + 执行记录 |
| F-PM-03 | 交付管理 | 交付邮件→客户确认→确收交接 | 状态自动流转 + 超时告警 |
| F-PM-04 | 验收管理 | 验收文件→客户确认→验收归档 | 验收条款自动校验 |
| F-PM-05 | 售后管理 | 维保→工单→关闭 | SLA 跟踪 + 超时告警 |
| F-PM-06 | 项目结项 | 全部履约完成后归档 | 结项检查清单 |
| F-PM-07 | 风险处置 | 异常报备→处置方案→关闭 | 风险等级 + 处置跟踪 |
| F-PM-08 | 进度监控 | 按项目/阶段/时间维度监控 | 甘特图 + 里程碑 |

**数据源**：
- ONES 项目管理（浏览器自动化导出）
- OA 立项/结项流程
- 工时门户（成本数据）

#### 模块 7：数据集成（integration）

**业务目标**：通过浏览器自动化从 OA、ONES、工时门户等系统获取数据 + 本机导入，减少人工录入。频率可配置，默认为人工触发（如生成新的交付月报、确收分析报告时）。

| # | 数据源 | 集成方式 | 频率 |
|---|---|---|---|

### 5.2 数据流

```

核心数据层（SQLite 宽表 + 知识库）
    ↓ 聚合计算
报表引擎（delivery_report / revenue）
    ↓ 落盘 + 缓存
Excel 导出 / 驾驶舱展示
```

## 6. 建设流程（强制）

> **所有功能开发必须严格按以下顺序执行，不可跳步：**

```
1. 明确需求      — PRD（本文档）
2. 设计大纲文档  — DESIGN-OUTLINE 级别
3. 详细设计文档  — DESIGN-DETAIL 级别
4. 测试方案      — 验收标准 + 测试用例 + 黄金基准
5. 开发建设计划  — IMPLEMENTATION-PLAN
6. 开发建设      — 按 Phase 逐步实现
7. E2E 自测      — 自动化测试全部通过
8. E2E 人工测试  — Rex 人工审核
```

**红线**：
- ❌ 禁止跳过任何阶段
- ❌ 禁止先开发再补文档
- ❌ 禁止自测不通过就提交人工测试
- ✅ 每份文档必须经 Rex 明确"通过"后才能进入下一阶段
