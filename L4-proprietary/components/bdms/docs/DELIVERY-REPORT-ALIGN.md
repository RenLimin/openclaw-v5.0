## 2. 根因：一个上游列污染了整片公式区

最初 5 个 sheet 的巨量差异里，相当一部分是**同一个根因**：

`签约!c56 履约项统计状态（即，财报-交付/确收状态）` 在库里的值口径与手工不同
（库里 `1：正常交付`=8004，手工=3950）。而 c56 是下游

```
c56 ──┬─→ c57..c65（9 个状态桶）
      ├─→ c67（项目验收状态）
      ├─→ c54 / c66（校验列）
      └─→ 异常项目 c38（VLOOKUP 取签约 c67）
```

的**共同上游**。上游错一格，下游全片错。**必须先修源头。**

### c56 手工公式原文（实测 `openpyxl(data_only=False)`）

```excel
=_xlfn.IFS(
   AND(OR(状态∈{实施未开始,义务已拆分,实施进行中,实施已完成,交付邮件交接中}),
       OR(预算-预估交付完成日期>=$A$1, LEN(预算-预估交付完成日期)=0),
       履约项异常/变更类型<>"履约项交付异常"),                 "1：正常交付",
   AND(OR(状态∈同上), 预算-预估交付完成日期<$A$1,
       履约项异常/变更类型<>"履约项交付异常"),                 "2：应交未交",
   AND(OR(状态∈同上), 履约项异常/变更类型="履约项交付异常"),    "3：交付异常",
   AND(OR(状态∈{交付邮件已归档,验收文件交接中}),
       OR(预算-预估验收完成日期>=$A$1, LEN(预算-预估验收完成日期)=0),
       履约项异常/变更类型<>"履约项验收异常"),                 "4：正常验收",
   AND(OR(状态∈同上), 预算-预估验收完成日期<$A$1,
       履约项异常/变更类型<>"履约项验收异常"),                 "5：应验未验",
   AND(OR(状态∈同上), 履约项异常/变更类型="履约项验收异常"),    "6：验收异常",
   AND(项目状态<>"已归档", OR(状态="验收文件已归档"),
       OR(基线-预估结项日期>=$A$1, LEN(基线-预估结项日期)=0)),  "7：正常服务",
   AND(项目状态<>"已归档", OR(状态="验收文件已归档"),
       基线-预估结项日期<$A$1),                               "8：应结未结",
   AND(项目状态="已归档"),                                     "9：已结项")
```

`$A$1` = 报表月末日期（202606 → `2026-06-30`）。

**验证：c56 逐格 15680/15680 零差异。**

> ⚠️ IFS 是**短路**求值：第 1 支命中就不再往下走。所以「项目状态=已归档」
> 的项目，若 `状态` 仍落在实施组，结果会是 `1：正常交付` 而不是 `9：已结项`。
> 实现里必须严格按此顺序。

## 3. 逐列修复依据

### 3.1 `签约` / `POC&提前实施`

| 列 | 手工公式原文 | 依据与坑 |
|---|---|---|
| c41 项目编号 | `=IF(ISERROR(FIND("】",G3)),G3,MID(G3,2,FIND("】",G3)-2))` | 从 `所属项目` 提取 `SSXM-…`；**每行都有值**。实测 0 差异 |
| c42 统计项目编号 | `=IF(COUNTIF(AO$2:AO2,AO3)>0,"",AO3)` | 去重列，**仅项目首行**有值（2619 个非空 = 项目数） |
| c43 统计合同编号 | `=IF(COUNTIF(M$2:M2,统计合同编号)>0,"",…)` | 去重列，仅首次出现的合同编号保留 |
| c45-c52 实施阶段桶 | `=IF(LEN(AP3)>0,COUNTIFS($AO:$AO,AP3,$AB:$AB,$AS$2),0)` | `AO`=c41项目编号（**每行都有**）、`AP`=c42统计项目编号（去重）、`AB`=c28`状态`。⇒ 首行返回「本项目内 `状态`==阶段标签的行数」，其余行 0 |
| c53 履约项合计 | `=IF(LEN(AP3)>0,COUNTIFS($AO:$AO,AP3),0)` | ⇒ 首行返回项目行数（如 r3=16），其余行 0 |
| c54 校验 | `=c53-SUM(AS3:AZ3)` | 因 c45-c52 修对后自然全 0 |
| c57-c65 状态桶 | `=IF(LEN(AP3)>0,COUNTIFS($AO:$AO,AP3,$BD:$BD,$BE$2),0)` | `BD`=c56。⇒ 首行返回「本项目内 c56==桶标签的行数」 |
| c66 统计校验 | `=SUM(BE3:BM3)-BA3` | 修对后全 0 |
| c67 项目验收状态 | 见 §3.2 | 逐行 IFS |
| r1 汇总行 | `=SUBTOTAL(9,BA3:BA84825)` 等 | 纯列求和，列对即对 |

**🔑 最大的坑：`AO` 到底是不是去重列。**
用 `openpyxl` 读 `签约!c41`（AO）时，`data_only=True` 在**共享公式**
（`<f t="shared" ref="AO4:AO67" si="11"/>`）上会返回 `None`，看起来像"去重列"。
但直接读 XML 可见 **AO 每行都有值**，去重的是 **`AP`（c42）**。
把 AO/AP 认反会推出"`COUNTIFS(AO,AP)` 恒等于 1"的错误结论，
导致 c53 全部写成 1、桶列全部写成 0/1。

**验证：c41/c54/c57-c66 全 0 差异；c42/c53/c63 各 1 格（见 §6）。**

### 3.2 c67 项目验收状态（逐行 ArrayFormula）

```excel
IF(LEN(AP3)>0,
   _xlfn.IFS(
     BM3=BA3,                                "已结项",
     BJ3>0,                                  "异常验收",
     SUM(BK3:BM3)=BA3,                       "全部验收",
     AND(SUM(BK3:BM3)>0,SUM(BK3:BM3)<BA3),   "部分验收",
     BI3>0,                                  "应验未验",
     SUM(BE3:BH3)>0,                         "正常验收"),
   "")
```

列位：`BA`=c53 履约项合计、`BE..BM`=c57..c65、`BH`=c60(4正常验收)、
`BI`=c61(5应验未验)、`BJ`=c62(6验收异常)、`BK..BM`=c63..c65。

- **是行级公式，不是项目级聚合。** 首行有值、非首行空（实测非空 2619 = 项目数）。
  ⚠️ 手工空格在 openpyxl 里读出的是 **`None`**，不是 `""`。
- 实测样本核对：`BM=BA`→已结项（r214: 1=1）、`BJ>0`→异常验收（r6728: 6>0）、
  `SUM(BK:BM)=BA`→全部验收（r41: 3=3）。

**验证：c67 逐格 15679/15680 零差异（1 格例外见 §6）。**

## 7. 关键教训

1. **上溯到源头**：一片列全错时，先找它们的共同上游，别逐列打补丁。
   本轮 15 万+ 差异其实是 1 个 c56 引起的。
2. **共享公式会骗过 openpyxl**：`data_only=True` 对 `<f t="shared"/>`
   的从属单元格返回 `None`，看起来像"空/去重列"。判定"去重"必须读 XML。
3. **别用中文近义词名做列匹配**：「项目经理」（人名）vs「项目经理所属部门」
   （部门名）只差 4 个字，取错就整列错 260 格。
4. **`data_type` 要核对内容**：`legend` 是确收类别，`project_manager` 才是
   项目经理→区域。表名像不代表内容对。
5. **没数据的列不能编**：宁可留差异并写进报告，也不要在导出器里造值。
