# PRD — BDMS 人工数据校准与填写功能 v1.0

> 状态：**待 Rex 审核** | 作者：Jerry 🦞 | 日期：2026-10-28
> 关联：`DESIGN-DETAIL-DELIVERY-REPORT-v2.1.md` · 交付月报模块
> 文档铁律：本 PRD 通过后才进入 OUTLINE，不提前开发。

---

## 1. 背景与问题

BDMS 交付月报生成后，自动校验产生大量待处理问题（如 202610 月 25,056 条）。当前审核界面：

- **能看**：「问题清单」Tab 列出问题明细；「数据浏览」Tab 查看行数据（只读）。
- **能标记**：单条/批量「确认 / 驳回」，只改 `dr_import_validation.status`。
- **不能改**：无法在校准界面修正错误值、补填空值。

数据层面 `dr_import_validation` 已预留 `corrected_value` 字段，但现有接口**不写入**；
另存在 `DeliveryReportValidator.apply_manual_fixes()`，它**直接覆盖** `dr_sheet_row.data`
原始 JSON —— 破坏原始数据、无留痕、不可审计，**本功能明确不采用该路径**。

**业务目标**：在审核界面提供人工数据校准与填写，确保报告数据合规，且全过程
**原始数据不动、校准可溯、可重新校验、导出可审计**。

## 2. 目标与非目标

### 2.1 目标（v1.0）

1. 在「问题清单」和「数据浏览」中对**指定单元格**输入校准值（含补填空值）。
2. 校准采用**覆盖层（overlay）**：原始 `dr_sheet_row.data` 永不修改。
3. 每次校准**强制留痕**：原值 → 校准值、操作人、时间、校准原因。
4. 校准保存后**自动触发重新校验**，以校准后值重跑规则，问题状态自动流转。
5. 校准可**撤销 / 修改**，撤销后恢复以原值参与校验。
6. 导出 Excel：报表主体采用**校准后值**，并额外附一张**校准台账** Sheet。
7. 「数据浏览」Sheet 下拉从 5 个补齐到 **15 个**。

### 2.2 非目标（v1.0 不做）

- 不做批量单元格粘贴 / Excel 反向导入校准（列为后续 v1.1）。
- 不做多级审批流（校准即生效，仅留痕；审批仍走月报级 approve/reject）。
- 不改动 revenue / project / contract 等其他模块，仅交付月报域。
- 不做校准值的历史版本多版本树（保留最新校准值 + 一条撤销前快照即可）。

## 4. 功能清单

### F1 校准录入（问题清单内）— P0
- 问题行提供「校准」操作 → 弹出校准对话框：
  - 只读：月份 / Sheet / 行号 / 列名 / 规则说明 / **原始值**；
  - 输入：**校准值**（与列数据类型一致的输入控件，日期列用日期控件）；
  - 必填：**校准原因**（下拉常用项 + 自定义文本）；
  - 操作人自动取当前登录身份（本地默认 `gateway-owner`）。
- 空值问题同样可补填（原始值显示为空）。

### F2 校准覆盖层存储 — P0
- 新增校准存储（数据模型在 DESIGN-DETAIL 确定，倾向独立表 `dr_calibration`），
  以 `(month, sheet, row_index, column_name)` 为唯一定位。
- **不写入** `dr_sheet_row.data`；`dr_import_validation.corrected_value` 同步回填用于问题视图。
- 同一单元格重复校准：更新校准值并保留一条「上一校准值」快照。

### F3 校准后自动重新校验 — P0
- 校准提交成功后，后端以「**应用校准层后的有效数据集**」重跑该校准涉及的规则；
- 受影响问题自动流转：
  - 已满足规则 → 状态转 `confirmed`（已修正），记录 `resolved_at/operator`；
  - 仍不满足 → 保持 `pending`，并刷新 `message/original_value`；
- 重算 `dr_review_status` 的 `total_errors / pending_fixes`。
- >10s 的批量重校验走**异步 job + 前端轮询**（遵守进度条铁律）。

### F4 校准留痕与审计视图 — P0
- 单元格/行提供「校准记录」入口，展示：原值、校准值、操作人、时间、原因、状态。
- 提供月度「校准总览」：已校准条数、待处理问题数、按 Sheet/严重度分布。

### F5 撤销 / 修改校准 — P0
- 「撤销校准」：删除/失效该覆盖层条目（保留审计快照），恢复原值，触发重校验。
- 「修改校准」：写入新校准值，旧值入快照，触发重校验。

### F6 数据浏览可校准 + Sheet 补齐 — P1
- Sheet 下拉补齐到当月实际 **15 个 Sheet**（由后端动态返回，不再硬编码 5 个）。
- 只读表格的单元格在「编辑模式」下可发起校准，复用同一校准对话框与覆盖层。

### F7 导出 Excel（校准后值 + 校准台账）— P0
- 各 Sheet 导出时，已校准单元格输出**校准后值**。
- 新增「**校准台账**」Sheet，列：月份 / Sheet / 行号 / 列名 / 原始值 / 校准值 /
  操作人 / 校准时间 / 校准原因 / 状态。
- 已校准单元格可在原 Sheet 加视觉标记（如批注/底色），样式在 DETAILED 定。

### F8 现有能力保留 — P1
- 月报级「审核通过 / 驳回」「重新校验」「对比手工报表」「批量确认/驳回」保持可用。

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 原始数据 `dr_sheet_row.data` 在任何校准操作下**只读不变**。 |
| BR-02 | 校准原因**必填**；无原因不能保存。 |
| BR-03 | 校准值必须通过该列**数据类型校验**（日期/数值/文本/枚举），不合规不能保存。 |
| BR-04 | 枚举列的校准值必须在允许枚举集合内（集合来源沿用主数据 legend 配置）。 |
| BR-05 | 同一单元格同时只有一条**生效**校准；重复提交走「修改」并留旧值快照。 |
| BR-06 | 月报一旦 `approved`，默认锁定校准；如需再校准需先驳回（审计一致性）。 |
| BR-07 | 所有读取报表/导出的路径统一经「校准解析层」，保证口径一致、单路径。 |

## 6. 验收标准

### 6.1 功能验收（P0 必须全过）

| AC | 验收点 | 判定 |
|---|---|---|
| AC-01 | 对一条 pending 问题输入校准值+原因保存，成功并有 toast | 校准记录可查 |
| AC-02 | 保存后读 `dr_sheet_row.data`，对应原值**未改变** | 原始值字节一致 |
| AC-03 | 校准后自动重校验：被修复问题状态变 `confirmed`，KPI/pending 数下降 | 数值正确更新 |
| AC-04 | 对空值补填后，对应非空类问题消失 | 问题转 confirmed |
| AC-05 | 校准记录展示原值/新值/人/时间/原因，字段完整 | 5 项齐全 |
| AC-06 | 撤销校准后恢复原值并重校验，问题重新出现（若仍违规） | 状态回滚正确 |
| AC-07 | 修改校准后旧值进入快照、新值生效并重校验 | 快照可查 |
| AC-08 | 导出 Excel：校准单元格为新值；含「校准台账」Sheet 且行数=已校准数 | 同口径核对 |
| AC-09 | 数据浏览 Sheet 下拉显示当月全部 Sheet（15 个或实际数） | 动态返回 |
| AC-10 | 类型/枚举非法的校准值被拒绝且不落库 | 保存失败 |

### 6.2 非功能 / 质量验收

- **E2E 用真实 HTTP + 模拟人工操作**，禁用 TestClient 测网络/写路径（遵守测试铁律）。
- 覆盖真实路径：问题校准 / 补填 / 撤销 / 修改 / 导出，均实跑。
- 批量重校验若 >10s，必须有分步进度条 + 当前步骤说明，无空白等待。
- **幂等性**：同一校准提交/同一重校验连跑 3 次结果稳定、不产生重复记录。
- 调用点扫描：报表读取与导出的所有入口都经过统一校准解析层，无绕过口径。
- 权限：未授权/非本人会话不能提交校准（本地单人模式默认 `gateway-owner`）。

### 6.3 合规验收

- 任意一条最终数据都能回答：「原值是什么、谁在何时为何改成什么」。
- 校准台账可独立导出，满足人工合规抽检。

## 7. 依赖与风险

| 项 | 说明 | 处置 |
|---|---|---|
| 校准层定位 | 新建独立校准表 vs 复用 `corrected_value` 字段 | DETAILED 定契约；倾向独立表 + 回填字段 |
| 既有 `apply_manual_fixes` | 破坏性覆盖，存在误用风险 | 标注废弃，全调用点扫描，改走覆盖层 |
| 重校验性能 | 25k 问题全量重跑耗时 | 按受影响范围增量重跑；大批量走异步 job |
| 口径一致性 | 多读取路径若不一致会导致导出与界面不符 | 强制统一「校准解析层」单入口 |
| 月报锁定 | approved 后再改破坏审计 | BR-06 锁定，需先驳回 |
