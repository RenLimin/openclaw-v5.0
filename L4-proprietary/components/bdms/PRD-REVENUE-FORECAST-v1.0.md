## 0. Rex 两点核心强调（2026-11-08）

1. **Part A —— 基于已提供的财务报告**：本模块只是"实时/动态确认收入预算预测"的**一部分**，其原始输入为**已提供的财务报告（上一个财务账期的数据）**，报告内**自带交付预计完成时间**，此部分**不依赖 ONES**。
2. **Part B —— 通过 ONES 动态数据生成**：另一部分（由 ONES 动态数据生成的预估）**当前只保留位置（接口/数据插槽），不在 v1.0 实现，后续补充**。

> 因此 v1.0 交付 **Part A 完整能力 + Part B 架构占位**，二者输出在同一预估界面汇聚。

---

## 1. 业务目标

把当前**手工、按月、静态**的"计划确收 vs 实际确收"对比，升级为**实时/动态**的本年度确认收入预算预测。整体由两条生成路径组成：

| 路径 | 数据来源 | v1.0 | 刷新性质 |
|---|---|---|---|
| **Part A** | 已提供财务报告（**上一账期**），报告内自带交付预计完成时间 | **完整建设** | 随每期财报上传更新 |
| **Part B** | ONES 动态交付数据（BI 履约 ID 实时匹配） | **仅预留位置**，后续补充 | 未来实时/定时动态刷新 |

**最终目标**：业务/财务随时回答"今年预计能确认多少收入、缺口多少、风险在哪"，并能逐步用 ONES 实时数据增强/校正财报静态口径。

- **账期说明**：该报告反映上一财务账期（截至 202609）数据；系统须支持后续每期新报告上传，并记录账期。

### 2.2 关键 Sheet

|---|---|---|
| `计划确收底稿` | 38,052 | **Part A 主数据源**：履约 ID + **自带交付预计完成时间(col3)** + 金额/已确收/计划确收 |

### 2.3 Part A 判定依据：col3「交付预计完成时间」

报告自带该字段，**无需 ONES**。实测其为**混合字段**（日期 + 状态文本）：

| col3 值 | 数量 | 对 2026 预估的处理 |
|---|---|---|
| 日期落在 **2026 年内** | 3,440 | 计入 2026（按日期归月） |
| 日期在 **2027 及以后** | 2,895 | 不计（跨年），入跨年清单 |
| `无需填写，100%确收` | 26,068 | 已在确收流程的存量合同；按金额/已确收口径处理 |
| `无需填写，已提交资料` / `已提交资料` | 3,767 | 已提交待确收；纳入 2026 待确收考量 |
| `调整` / `2026年调整` | 1,453 | 按调整后口径（DETAIL 细化） |
| `异常项目` | 169 | **排除**，入风险清单 |
| `合同终止` / `2026年终止` | 69 | **排除**（终止） |
| `未立项` / `未预计` / `金额为0` | 181 | 不计，入风险/零额清单 |

> ⚠️ **口径风险（实测）**：仅按"交付日期=2026"只得约 **0.87 亿**，而报告 col42 的 2026 计划确收约 **2.23 亿**。差额来自"已提交资料 / 100%确收"等**已进入确收流程**的存量项。Part A 规则必须同时覆盖"未来日期到期"与"流程中待确收"两类，否则系统性低估。具体映射在 DETAIL 固化。

### 2.4 金额字段（计划确收底稿，0-based 列序）

| 列 | 字段 |
|---|---|
| col39 | 单项履约义务金额（实测合计 ≈16.7 亿，含大量历史存量） |
| col41 | 截止 20251231 已确收（合计 ≈0.36 亿） |
| col42 | 2026 年及以后计划确收（合计 ≈2.23 亿） |

`预算执行表` 另提供：分类（递延/新签）、收入确认方法（时点法/时段法）、单项金额、已确收，作为口径交叉校验基准（已核：单项 ≈5.46 亿、已确收 ≈0.71 亿）。

### 2.5 Part A 处理逻辑（粗规则）

```
对每期上传财报：
1. 解析 计划确收底稿（履约ID / col3交付预计完成时间 / 金额 / 已确收 / 计划确收）
2. 将 col3 混合值映射为：{2026到期, 跨年, 流程中待确收, 异常排除, 终止排除, 未立项/零额}
3. 结合金额列，计算 2026 预计可确收：
   - 未来到期：按交付日期判定+归月
   - 流程中：已提交/100%确收项按剩余待确收额纳入
   - 异常/终止：排除并入风险清单
4. 输出：总额(新签/递延)、按月分布、计划vs预估差异、明细、风险/排除清单
```

## 6. 验收标准

1. 以一份财报为输入，输出的 Part A 预计可确收总额可逐项下钻、可复算；
2. 同一报告连解析 3 次结果稳定（幂等）；
3. Part A 预估与财报 col42 静态计划数可同口径对照，差异可解释（col3 状态映射、异常排除所致）；
4. 异常/终止/未立项/跨年/缺值项 100% 进入对应清单，不被静默丢弃；
5. 财报解析失败/格式不符时明确报错并保留上次结果，不产出误导数字；长耗时解析有进度条；
6. **Part B 占位可见且行为明确**：界面与接口清晰标注"未配置/待接入"，不伪装成有数据；
7. 不新增第三方依赖（标准库 + 既有 openpyxl 等）；
8. 不破坏现有后端基线（当前 367 passed / 16 skipped），新增测试数 ≥ 新增判定分支数。

## 7. 风险与约束

- **口径是最大风险**：col3 混合枚举的金额映射直接决定数字；必须覆盖"流程中待确收"，以财报计划数校准（见 §2.3）；
- **账期依赖**：Part A 严格依赖按期提供的财报，缺失则只能沿用上版；
- **Part B 字段漂移**：ONES 自定义字段 key 未来可能被调整 → 接入时映射可配置 + 启动校验；
- **只读红线**：不向 ONES/OA 写入；Part A 仅处理已提供的报告文件；
- **凭据安全**：Part B 接入时凭据只从 secrets 读取，不进日志/响应/文档。
