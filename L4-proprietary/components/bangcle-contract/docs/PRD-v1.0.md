## 1. 背景与目标

### 1.1 业务背景

Bangcle 销售合同审批当前痛点（承接 SCA-001 + 新增）：

1. **审批流未接 OA**：合同审批仍在 OA 人工流转，无法自动获取合同文本、无法自动回写审批状态
2. **缺少知识库参照**：合同标的（产品/SKU）与本地产品/服务知识库未联动，报价/折扣红线靠人工核对
3. **审批责任不清**：人工审核无结构化记录，事后无法回溯
4. **模板不统一**：合同文档格式靠人工维护，金额大小写易错

### 1.2 目标

构建 **Bangcle 合同管理专家**，打通「OA 合同审批流程 ↔ 本地合同智能审批 ↔ 本地产品/服务知识库参照分析」闭环：

- **OA 集成**：从 OA 获取合同文本（审批附件）、推送风险报告与审批状态、同步审批意见、归档回写
- **智能审批**：复用 L3 状态机 + 风险扫描，按金额自动分级流转
- **知识库参照**：复用 product-kb ContractMatcher，合同标的自动匹配 SKU + 折扣红线预警
- **文档与归档**：模板生成 docx + Excel 风险报告 + 归档

### 1.3 成功标准

1. OA 合同附件可自动获取 → OCR/解析 → 风险扫描 → 知识库比对 → 生成报告
2. OA 审批节点状态与本地状态机同步（双向）
3. 合同标的匹配准确率 ≥ 95%（复用 product-kb 验收口径），折扣红线预警
4. 全程审计日志，审批责任可追溯
5. 支持 CLI 全流程操作（本期无 Web UI）

## 3. 端到端流程（目标态）

```
OA 发起合同审批
  → [B-F2] 获取合同附件
  → [B-F3] OCR/直读 → 文本
  → [B-F4] L3 风险扫描 → 风险报告
  → [B-F5] product-kb 知识库比对 → 标的一致性报告
  → [B-F6] 状态机编排：分级审批（OA 节点同步）
  → [B-F8] 生成正式 docx
  → [B-F9] Excel 报告归档
  → OA 状态回写（驳回 → 回 draft）
```

## 4. 验收标准

1. ✅ 模拟 OA：本地目录放入合同 PDF → 一条命令跑通「获取→OCR→扫描→比对→审批→归档」
2. ✅ 钉钉 OA：凭证配置后，可拉取审批实例附件、回写审批结果（凭据走安全存储，不落 markdown）
3. ✅ 知识库比对：产品名/型号/单价 → SKU 匹配 + 折扣红线预警（复用 product-kb 验收 ≥95%）
4. ✅ 状态机：OA 节点变更回调 → 本地状态推进；本地 approve/reject → OA 回写
5. ✅ 审计日志：全操作可查，append-only
6. ✅ L3 契约：L4 只依赖 L3 公开 API，不越界
7. ✅ 回归：L3 单测 + L4 e2e 全绿

### 10.2 MVP 核心（最小可用闭环）

Rex 明确：**核心是合同条款全文扫描、解析，并依据 Bangcle 产品管理专家建议，对比产品/服务是否满足合同要求以及风险点**。

MVP 只保 4 步分析闭环（不做完整审批编排/文档生成）：

```
1. 合同文本获取（上传/OA附件） → PDF/docx/扫描件
2. 全文扫描 + 解析（L2 OCR + L3 条款解析）→ 结构化条款 + 全文文本
3. 双轨风险扫描（L3 22条规则 + 语义判断）→ 法律风险点
4. 产品知识库参照（product-kb ContractMatcher + 产品管理专家建议）
   → 合同要求的产品/服务 vs 实际产品库：是否满足 + 偏差 + 风险点
   → 输出《合同智能审查报告》（风险点 + 满足度结论 + 建议）
```

**MVP 必做**：步骤 1-4 + 报告产出（Markdown/Excel）
**MVP 不做**：OA 双向审批回写、docx 合同生成、Web UI、状态机多级流转（保留接口，后续迭代）

### 10.3 验收标准（MVP 口径）

1. ✅ 上传/获取一份真实销售合同（含扫描件）→ 跑通步骤 1-4
2. ✅ 全文条款可解析，风险点结构化输出（含法条依据 + 原文位置）
3. ✅ 合同产品/服务清单 ↔ product-kb 自动匹配，给出"满足/部分满足/不满足"结论 + 风险点
4. ✅ 输出审查报告，含免责声明
5. ✅ 合同原文不发公网模型（数据隐私红线）

**浏览器自动化兜底路径（Rex 拍板 2026-10-27）**：
- 若泛微 OA API 无法调用或无法全功能调用（账号权限等原因），**采用浏览器自动化方式实现** OA 合同文本获取与审批状态读取
- 直接复用 BDMS 已验证资产：`BrowserAdapter`（connect_over_cdp 复用登录态 Chrome）→ `navigate(OA 合同详情页)` → 提取附件/字段 → 落盘
- 该路径在 BDMS 开发建设过程中已实现并验证（ONES/OA/工时门户数据采集），无需重新造轮子
