# DESIGN-OUTLINE-v1.0.md — BDMS 交付月报系统设计大纲

## 1. 概述

为交付月报提供模块化、可测试、多入口的自动化生成与管理能力，解决手工汇总效率低、质量不稳定的问题。

## 2. 模块划分

| 模块 | 职责 |
|------|------|
| **采集层（collectors）** | 从 OA、ONES 导出文件读取原始数据，清洗标准化，输出统一结构 DataFrame |
| **引擎层（engines）** | 7 个纯计算引擎：合同、工时、状态、异常、交接、评分、映射，每个引擎单职责，纯函数无副作用，可独立测试 |
| **服务层（services）** | 异步任务管理、报告生成流程编排、元数据 DB 操作、概要提取 |
| **入口层（cli + web）** | CLI 命令行入口和 FastAPI Web UI 入口，封装服务层能力对外暴露 |
| **存储层（db + generators）** | SQLite 元数据存储，Excel 报告文件生成 |

## 3. 核心依赖

- **L3 DMS 框架**：提供基础架构和规范
- Python 依赖：pandas（数据处理）、openpyxl（Excel 读写）、FastAPI（Web）、uvicorn（Web 服务器）、pytest（测试）
- L2 组件：依赖 `web-common` 组件提供 Web 静态资源和模板宏

## 4. 关键决策点

1. **双版本策略**：v1 保留兼容，v2 重构架构，渐进式迁移，避免一次性切换风险
2. **引擎纯函数设计**：引擎层无副作用，输入 → 输出，最大化可测试性
3. **异步任务设计**：月报生成可能耗时较长，异步执行避免 Web 阻塞
4. **多入口设计**：同时提供 CLI/Web/Python API，满足不同使用场景
5. **元数据 SQLite 存储**：轻量无需额外数据库服务，满足当前单实例部署需求
