# OFC-001 Office 合同审批模块 PRD v1.0

## 1. 项目背景

企业销售合同审批流程普遍存在以下痛点：
- 流程不规范：审批流转靠人工沟通，容易遗漏、延误
- 风险不透明：合同条款风险需要法务逐字检查，效率低且容易漏检
- 记录不完整：审批过程和意见没有完整留痕，难以追溯
- 复用度低：通用合同审批能力缺乏持久化和业务编排，无法直接落地企业场景

本模块基于通用 L3 合同审批能力，面向企业 Office 销售场景提供完整的全流程管理能力，解决上述痛点。

## 2. 目标用户

- 企业销售团队：起草合同、提交审批
- 法务团队：风险审查、合规审核
- 财务团队：金额条款审核
- 管理层：合同审批
- 运维/管理员：系统配置

## 3. 功能清单

1. **合同起草**：录入合同基本信息，自动生成合同编号，支持查询和列表展示。
2. **分级审批**：按合同金额自动判定审批层级（1~4级），每级对应不同角色和SLA。
3. **风险扫描**：复用 L3 风险扫描能力，基于《民法典》13 类条款自动扫描，输出风险等级和整改建议。
4. **合同生成**：基于模板生成标准 docx 格式合同文档，支持下载查看。
5. **签署归档**：签署后归档，完整状态流转，支持历史版本查看。
6. **审计日志**：所有操作留痕，不可篡改，支持操作追溯和审批记录查询。
7. **Web API**：提供 RESTful API，支持前端对接和二次开发。
8. **CLI 入口**：提供完整命令行操作，适合批量处理和开发调试。

## 4. 验收标准

1. 所有 58 个单元测试/集成测试全部通过。
2. 覆盖 4 个金额级别的审批流程，状态机流转正确，任一环节驳回正确回退到 draft 状态。
3. 风险扫描功能正常调用 L3 能力，风险分级准确，整改建议完整。
4. 合同文档生成正确，金额转换中文大写无误，占位符替换正确。
5. 审计日志完整记录所有操作，包括操作人、角色、时间、意见。
6. CLI 和 Web API 入口都能正常工作，参数校验正确，错误提示清晰。
7. SQLite 持久化工作正常，数据不丢失，支持分页查询。

## 5. 约束条件

1. 技术约束：
   - Python 3.10+ 依赖，依赖 python-docx 库
   - 依赖 L3 contract-approval 通用能力（风险扫描规则、审核标准）
   - 仅支持 SQLite，暂不支持其他数据库
   - 当前仅支持销售合同类型，其他类型合同需要后续扩展

2. 业务约束：
   - 审批层级和金额阈值可在配置中修改，但不支持动态多级自定义（最多 4 级）
   - 电子签名能力未集成，签署仅状态标记
   - 不支持多人并行审批，串行审批
   - 无用户权限系统，依赖外部身份认证
