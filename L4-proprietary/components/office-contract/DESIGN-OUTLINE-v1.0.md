# OFC-001 Office 合同审批模块 DESIGN-OUTLINE v1.0

## 1. 概述

为企业 Office 销售合同提供基于状态机驱动、分级审批、持久化存储的全生命周期管理能力，复用 L3 通用能力，落地 L4 业务编排。

## 2. 模块划分

1. **CLI 模块**：提供 `contractctl` 命令行入口，处理参数解析，调用核心服务完成操作，支持开发调试和批量处理。
2. **业务服务模块**：核心业务编排层，实现状态机流转、分级审批逻辑，协调风险扫描、文档生成、持久化操作，暴露业务接口供 CLI 和 Web API 调用。
3. **配置模块**：维护 Office 场景配置，包括甲方企业信息、审批角色定义、SLA 规则、金额阈值等配置。
4. **持久化模块**：基于 SQLite 实现合同数据、审批记录、审计日志的读写操作，支持分页和筛选查询。
5. **Web API 模块**：提供 RESTful API，对接前端界面，支持分页查询、参数校验、错误处理。

## 3. 核心依赖

1. **L3 层**：`skills/contract-approval`，提供风险扫描、条款解析、状态机核心逻辑、金额工具等纯逻辑能力。
2. **L2 基础设施层**：依赖 SQLite 持久化、python-docx 文档生成。
3. **第三方库**：FastAPI（Web API）、pytest（测试框架）、python-docx（文档生成）。

## 4. 关键决策点

1. **分层决策**：L4 负责编排和持久化，L3 负责纯逻辑，分离关注点，提高复用性和可测试性。
2. **状态机设计**：7 个状态，固定流转路径，任一环节驳回回退到草稿，简单可控。
3. **分级审批**：按金额预定义 1~4 级，满足大多数企业需求，配置可修改阈值和角色。
4. **审计日志**：所有操作强制留痕，不可修改，确保合规性和可追溯性。
5. **双入口设计**：同时提供 CLI 和 Web API，兼顾开发调试和前端对接。
6. **数据存储**：使用 SQLite，轻量无需额外服务，适合中小规模企业使用。
