## 1. 背景与目标

### 1.1 业务背景

Bangcle 在售产品/服务已有 **386 SKU**，涵盖 6 大产品线，共有 **1158 份本地文档**（白皮书、销售一指禅、功能清单、PPT、技术文档等）。

当前痛点：
1. 合同报价/审批时，找不到对应产品的标准价格、折扣红线、注意事项，容易漏项/报错
2. 销售/售前答疑时，翻遍多个目录/文档也找不到产品功能/版本的正确信息
3. 产品对比时，需要手动整理不同产品的功能/价格差异，效率低下
4. 文档分散在不同目录，版本混乱，找不到最新版

### 1.2 业务目标

| 目标 | 验收标准 |
|---|---|
| 合同标的自动比对 | 输入合同标的列表 → 自动匹配标准 SKU，输出价格/折扣比对表，准确率 ≥ 95% |
| 产品知识问答 | 自然语言提问 → 输出对应产品的答案 + 来源文档，召回率 ≥ 90% |
| 多维度产品检索 | 支持产品线 / 产品名称 / 类别 / 版本 / 价格区间筛选，结果秒出 |
| 多产品对比 | 选 N 个产品 → 自动生成功能/价格对比矩阵 |
| 版本管理 | 支持同产品多版本并存，自动标记最新版 |

## 3. 用户故事

### Story 1: 合同报价审批

**角色**：销售 / 销售助理

> 作为销售，我拿到客户需求后，需要快速报价，我希望：
> 1. 粘贴客户需要的产品列表 → 系统自动匹配标准 SKU
> 2. 快速看到哪些产品不在标准库，哪些价格偏离标准，哪些低于折扣红线
> 3. 拿到标准描述，可以直接复制到合同里
> 4. 找到对应产品的销售一指禅和白皮书，快速参考卖点

**验收标准**：
- 粘贴 20 行产品列表，10 秒内出结果
- 匹配准确率 ≥ 95%
- 结果包含：匹配度/标准名称/标准单价/合同单价/偏差率/折扣红线预警/注意事项

### Story 2: 产品知识答疑

**角色**：售前 / 销售 / 技术支持

> 作为售前，客户问我「你们鸿蒙Next SDK加固支持什么版本？有什么限制？」，我希望：
> 1. 直接搜索问题就能找到对应产品和文档片段
> 2. 看到来源文档，可以点进去看完整内容
> 3. 如果有多个版本，自动给出最新版信息

**验收标准**：
- 问题响应时间 ≤ 3 秒
- 前 3 个结果召回率 ≥ 90%
- 每个结果附产品卡片 + 文档路径 + 文档片段

### Story 3: 方案选型对比

**角色**：售前 / 解决方案架构师

> 作为解决方案架构师，我需要给客户选一个合适的加固方案，有 3 个候选产品，我希望：
> 1. 一键生成功能对比矩阵
> 2. 价格区间一目了然
> 3. 快速导出给客户做方案附件

**验收标准**：
- 支持 2-10 个产品对比
- 自动对齐功能点，差异高亮
- 支持 Excel 导出

## 5. 验收标准

### 5.1 功能验收

| 功能点 | 验收标准 |
|---|---|
| 价格表导入 | 386 SKU 全量导入成功，无丢失字段，类型正确 |
| 文档扫描 | 1158 个文档全量扫描，元数据抽取正确，90%+ 能关联到对应产品 |
| 全文抽取 | 95% 以上文档能正确抽取文本，乱码率 < 5% |
| 合同比对 | 随机 10 份合同，准确率 ≥ 95%，运行时间 ≤ 30 秒 |
| 问答检索 | 随机 20 个问题，前 3 结果召回率 ≥ 90%，运行时间 ≤ 5 秒 |

### 5.2 非功能验收

| 维度 | 要求 |
|---|---|
| 依赖 | 仅依赖现有 L2 组件，不新增重型外部依赖（如 Elasticsearch / Neo4j） |
| 存储 | SQLite 单文件，总大小不超过原始文档大小的 50% |
| 部署 | 纯 Python，无需额外编译/安装系统依赖 |
| 可维护性 | 代码注释覆盖率 ≥ 30%，核心逻辑有单元测试 |
