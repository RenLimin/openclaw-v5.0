### 1.2 黄金基准（Golden Master）

- **客户**：中国建设银行股份有限公司
- **基准位置**：`golden/ccb-2026/`
- **基准内容**：
  - 六类产物 IR JSON（schema 校验通过 + 数字自洽）
  - md / docx 样例
  - trace 样例（字段→原始文件路径）
  - completeness 证据样例
- **生成方式**：首次 E2E 跑通后，人工复核确认，冻结为 v1.0 基准
- **回归策略**：后续任何代码变更，跑通 E2E 后产物与 golden diff，核心字段（金额、条款数、项目数）必须一致

### 1.3 测试铁律（承 AGENTS.md）

- Web/安全功能验收必须用真实 HTTP；禁止用 FastAPI TestClient 测试网络安全/Cookie/访问控制
- 所有 E2E 自测务必使用真实的模拟人工操作的方式进行
- E2E 测试必须覆盖真实用户操作路径
- 后端 API 应同时兼容多种输入格式

## 4. E2E 自测（自动化，真实浏览器）

### 4.1 E2E-01 建行标准流程

- **目的**：验证从真实 OA/ONES 取数到六类产物生成的全链路
- **步骤**：
  1. 以真实账号登录 OA + ONES（Playwright 持久化 session）
  2. 触发流水线：customer="中国建设银行股份有限公司", period="2026-01-01~2026-11-01", audience="internal"
  3. 等待 N3 齐套闸 → 自动 approve（测试环境配置）
  4. 等待 N6 签发闸 → 自动 approve（测试环境配置）
  5. 产物生成完毕
- **预期**：
  - ✅ 六个节点全部 pass，无 BLOCK
  - ✅ completeness 证据齐全（ONES 分页触顶、OA 文件清单）
  - ✅ 六类产物 schema 100% 通过
  - ✅ 数字一致性校验通过（金额、账龄、分摊）
  - ✅ 血缘追溯可到原始文件（至少抽 5 个关键字段验证）
  - ✅ 产物与 golden master 核心字段一致（diff 通过）

### 4.2 E2E-02 换客户一致性验证

- **目的**：验证换客户后输出结构一致、口径一致
- **步骤**：
  1. 换客户（如「山东省城市商业银行合作联盟有限公司」）
  2. 触发同样流水线
- **预期**：
  - ✅ 六类产物结构一致（同一 JSON Schema）
  - ✅ 项目编号规则一致（`PROJ-YYYY-<客户>-<序号>`）
  - ✅ 字段命名一致，无额外专有字段
  - ✅ 血缘机制相同

### 4.3 E2E-03 数据来源验证（铁律专项）

- **目的**：验证所有事实数据均直接来自 OA/ONES，无可疑来源
- **步骤**：
  1. 取 E2E-01 产物
  2. 遍历所有事实类字段，检查 `sourceUri`
  3. 验证 sourceUri 格式（`ones://...` / `oa://...`）
  4. 抽检 10% 字段，打开原始文件核对
- **预期**：
  - ✅ 100% 事实字段有 sourceUri
  - ✅ 抽检 10% 字段，值与原始文件一致
  - ✅ 无手工录入字段、无「经验值」字段
  - ✅ 无历史产物倒推字段
