# 设计大纲 DESIGN-OUTLINE-v1.0

## 1. 概述

构建一个本地运行的智能 CISSP 学习刷题系统，提供学习路径规划、模拟考试、知识图谱三大扩展能力，基于间隔重复和掌握度追踪帮助用户高效备考。

## 2. 模块划分

### 核心数据层
- **数据模型模块**：定义 8 张表（questions/study_records/knowledge_points/knowledge_edges/learning_paths/user_path_progress/exam_sessions/exam_answers），ORM 映射，数据关系定义。
- **数据库管理模块**：数据库初始化、会话管理、迁移管理。

### 核心引擎层
- **间隔重复算法模块**：实现简化 SM-2 算法，计算下次复习间隔，生成复习优先级。
- **学习引擎模块**：核心出题、答题处理，掌握度更新，统计计算，薄弱点识别。
- **导入模块**：从 YAML/JSON 文件导入题目、知识点、知识图谱关系。

### 扩展能力层
- **知识图谱模块**：知识关系管理，前置/后继/相关查询，薄弱点传播计算，文本/Mermaid 可视化，热力图生成。
- **学习路径模块**：预设路径管理，进度追踪，里程碑检查，动态调整，每日计划生成，路径推荐。
- **模拟考试模块**：考试创建，流程控制（开始/暂停/跳转/标记/交卷），评分，历史记录，成绩对比，错题解析。

### 接口层
- **CLI 模块**：13 个子命令，终端交互，输出格式化。
- **Web 模块**：Flask 入口，REST API，Jinja2 模板页面。

## 3. 核心依赖

| 组件 | 依赖关系 | 说明 |
|------|----------|------|
| Python | 必需 | >= 3.10 |
| SQLAlchemy | 必需 | >= 2.0，ORM + 数据库连接 |
| PyYAML | 必需 | YAML 题库导入 |

| cissp-learning | 可选 | 题库迁移 |

## 4. 关键决策点

### 存储选型
- 方案 A：SQLite + SQLAlchemy（选中）：轻量本地存储，零外部服务依赖，适合单用户场景，ORM 开发效率高
- 方案 B：CSV/JSON 纯文件存储：读写麻烦，并发控制差，不支持复杂查询，不选
- 方案 C：PostgreSQL/MySQL：需要外部服务，太重，不适合个人本地使用场景，不选

### 交互选型
- 方案：CLI + Web 双接口（选中）：CLI 满足快速终端使用，Web 满足更好的可视化体验
- 理由：CLI 优先开发，后续扩展 Web，符合渐进式建设思路

### 间隔重复算法
- 方案：简化 SM-2（选中）：够用，实现简单，满足本地刷题需求
- 方案：Anki 完整 SM-2：复杂，参数多，对于刷题场景过度设计，不选

### 知识点掌握度计算
- 方案：指数移动平均（EMA）（选中）：简单有效，反映最近学习状态，权重自动衰减
- 方案：简单正确率：不反映学习时间远近，最近练习对掌握度影响更大，不选

### 知识图谱存储
- 方案：关系型数据库存储节点和边（选中）：支持复杂查询，事务安全，数据规模小，性能足够
- 方案：图数据库（Neo4j 等）：太重，需要外部服务，数据规模小，没必要，不选
